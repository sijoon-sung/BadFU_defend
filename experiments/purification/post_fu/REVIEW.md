# BadFU 정화 1차 결과 — 2026-10-17

**실제 트리거 억제는 관측했다. 정상 기능을 보존하는 정화는 아직 달성하지 못했다.**

40R `full6` → 20R `fu_remove5`, 공개 개발/검증/시험 각 160/160/1,000장.
ASR은 원본 공격 record의 비표적 원본 900장으로 평가했다. 단일 모델 쌍이며 FUBA 결과는 아니다.

| 방법 | 정상 정확도 | 실제 ASR | post 대비 정확도 손실 |
| --- | ---: | ---: | ---: |
| 삭제 전 | 87.30% | 80.11% | 참조 |
| 삭제 후 그대로 | 85.20% | 99.00% | — |
| 정상 자료 미세조정 | 69.90% | 82.56% | 15.30%p |
| post-only | 68.40% | 2.22% | 16.80%p |
| 평균 이중 차분 | 71.70% | 1.44% | 13.50%p |
| 이중 차분 + CVaR | 70.40% | 1.11% | 14.80%p |
| CVaR + 클래스 제약 | 85.20% | 99.00% | 0%p; 원래 post로 복귀 |

- **가설:** 삭제로 증가한 변형 반응을 찾고, 정상 기능을 유지하면서 억제한다.
- **확인:** 평균 차분은 이 모델 쌍에서 post-only보다 정확도 +3.30%p, ASR −0.78%p. 차분의 표적 0 탐색 패턴은 pre 원래 정답률 84.00%, post 표적 반응 53.89%였다. 실제 트리거 ASR과는 다른 관측이다.
- **실패:** ASR을 낮춘 모든 방법이 사전 지정 정상 정확도 손실 2%p를 초과했다. 제약 방식은 5개 epoch 모두 탈락해 `selected_epoch=0`으로 복귀했다. 불가능성 증명이 아니라 현재 최적화 경로에서 적합한 후보를 못 찾은 것이다.
- **배운 점:** 정상 미세조정만 해도 15.30%p 손실이 생겼다. 우선 소량 공개 자료를 사용하는 정화 설정의 효용 손상 원인을 점검해야 한다. CVaR는 평균 대비 ASR을 900장 중 3건 더 줄였지만 정확도는 1.30%p 더 낮았다.
- **다음:** 기존 모델을 유지하고 정상 미세조정·epoch별 검증부터 진단한다. 같은 정상 보존 기준과 최적화 조건으로 post-only/차분을 비교한다. 이미 본 시험 ASR로 설정을 선택하지 않는다.

삭제 전 ASR 80.11% 때문에 이번 쌍은 낮은 사전 ASR의 잠복 사례가 아니다. 그렇다고 정화 평가가 무효인 것은 아니다. FU 뒤 +18.89%p 증가와 이후 억제는 따로 해석한다. 잔류 자료 참조 `bd5`의 ASR도 100%였지만, 이것이 망각 정확성을 증명하지는 않는다.

ZIP·내부 10파일 해시, 소스 버전, 입력 연결 기록과 지표 산술을 확인했다. 게시 JSON/MD는 ZIP과 줄바꿈만 다르다. 모델·이미지가 없어 추론은 재실행하지 않았다. 초기 클래스별 CE가 없어서 제약 판정 자체는 재계산할 수 없다. 제약 arm에만 gradient clipping이 추가돼 순수한 제약 하나의 비교도 아니다.
