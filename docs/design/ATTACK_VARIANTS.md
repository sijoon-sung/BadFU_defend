# 적응형 공격과 가족 안의 변형 공격 (설계 메모, 2026-10-11)

전제: 가족 = "학습 중 심어 두고 제거로 깨어나는 백도어" (BadFU, FUBA, clean-unlearning 2506.12522, clean-label 2607.27936, Zhang 2023 단계 요청).
방어 = 투여량 조절 FU (`DOSE_FU.md`) + 쌍→집합 (`PAIR_ROLES.md`). 공격자는 방어를 안다고 가정한다.

## A. 방어 부품별 공격면 (적응형)
각 줄: 부품이 기대는 가정 → 그 가정을 깨는 공격 → 대응 → 검증 비용 (★ = 저장된 갱신만으로 학습 없이 시뮬레이션 가능)

| # | 부품 | 가정 | 적응형 공격 | 대응 | 검증 |
|---|---|---|---|---|---|
| a | 같은 양 비교 | 요청 한 건의 효과가 크다 | **요청 쪼개기**: 기여를 n 조각으로 나눠 시간차 요청. 조각마다 z < τ | 누적 장부 (`--ledger`) | ★ 코드 있음 (`--split n`). FUBA 5 조각은 조각마다 z 7~14 로 아직 잡힘. 20~50 조각까지 가면? 공격자 비용 = 요청 횟수 |
| b | 같은 양 비교 | 억제가 한 클라에 모여 있다 | **위장자 분산**: 억제를 m 명이 나눠 들고 각자 조금씩 요청. 개인 z < τ, 합은 활성화 | 클라이언트별 장부 → **전체 예산**: 창 W 안의 모든 요청을 합쳐 "하나도 안 들어줬다면" 모델과 비교 | ★ U_4 를 m 개 가상 클라로 쪼개 재배치하면 학습 없이 됨. `pair_roles` 의 C 는 각자 z_single > τ 일 때만 잡음 |
| c | 같은 양 비교 | 모집단의 흩어짐이 정상을 대표 | **모집단 오염**: 빼면 크게 흔들리지만 해롭지 않은 미끼 클라(큰 노름, 극단 non-IID)를 심어 std 를 부풀림 → 진짜 z 가 τ 아래로 | 상한 c 로 비건강 멤버 제외(이미), 절사 std, "정상 핵" 군집 기준. MAD 는 공격자 과반에서 깨짐(확인됨) | ★ 정상 U_j 에 α 를 곱해 미끼로 만들면 됨 |
| d | 같은 양 비교 | 탐침에 활성화가 보인다 | **탐침 사각**: 깨끗한 입력엔 안 보이고 트리거에만 보이게 (BadFU 패치, 입력 특정 트리거) | 탐침 확장: 격자 패치, 클래스 조건 탐색 (`release_map` 의 grid/class) | 코드 있음. BadFU 에서 아직 실패. 이 가족의 **가장 큰 약점** |
| e | 같은 양 비교 | 모집단이 충분히 크다 | **시점 공격**: 참여자가 적은 라운드, 또는 대량 이탈 직후에 요청 | 최소 모집단 크기 미달이면 요청 보류 | 저렴 (m 을 줄여 보면 됨) |
| f | 상한 c | 요청자도 건강하게 빠진다 | **붕괴 방패**: 자기 제거가 어떤 δ 에서도 무너지게 만들어 서버가 포기하게 함 (삭제권 DoS) | 그 요청자만 KD/재학습 연산자로 대체 | 낮은 우선순위 (공격자의 목적인 활성화도 같이 실패) |
| g | 수정 | 모집단 중앙값은 깨끗하다 | **기준 오염**: 운반자들이 "누구를 빼도 탐침에서 타깃 쪽으로 살짝 기울게" 만들어, 수정이 백도어 쪽으로 당기게 함 | 중앙값(과반 미만이면 안전), 기준 vs θ_T 거리 점검 | ★ 저장 갱신에 타깃 방향 성분을 더해 시뮬레이션 |
| h | 수정 | 재우면 끝 | **재잠복 악용**: 수정은 백도어를 지우지 않고 재운다. 창 W 가 지난 뒤 다시 요청, 또는 공동 위장자가 요청 | 영구 기록, 그리고 `pair_roles` 로 운반자까지 **지움** | 설계로 답함. 실험은 창 W 만 바꾸면 됨 |
| i | 쌍→집합 | 운반자 몇 명이 크게 든다 | **운반자 분산**: 백도어를 많은 클라가 아주 조금씩 들어 Δ_j 가 margin 아래 (로컬에서도 운반자 0 을 놓침) | margin 을 z 기준 정지로 바꾸고, 집단 제거 검사(상위 r 명 동시 제거) | ★ U_0..3 을 더 많은 가상 운반자로 쪼개면 됨 |
| j | 제거 연산자 | 요청 = 클라 기여 전체 | **자기 완결형(BadFU 원형)**: 한 클라가 백도어+위장을 다 들고, 위장 **샘플만** 삭제 요청(샘플 단위 FU). 제거 벡터가 U_k 가 아님 | 샘플 단위 FU 에서 "같은 양" 정의: 남들도 같은 비율의 샘플을 뺀 모델과 비교 | BadFU 코드가 이 꼴. FUBA 는 클라 단위라 불가. **가족 정의에 꼭 넣어야 할 축** |

## B. 가족 안의 변형 공격 (방어와 무관하게 존재할 수 있는 것)
1. **다중 위장자** 동시 요청 / 순차 요청. FUBA `--clients_ratial 2` (위장자 4, 8). 동시는 `pair_roles --joint`, 순차는 장부.
2. **분산 신호형** (clean-unlearning 2506.12522 의 FL 판): 운반자도 위장자도 특정 한 명이 아니라, 약한 성분을 여러 클라에 흩고 정상처럼 보이는 기여 몇 개를 빼면 합이 드러남. = b + i 의 결합. 이 가족의 "끝판"이라 방어의 한계를 보여 주는 데 쓰임.
3. **FU 방법 적응형**: FUBA 는 빼기에 맞춰 줄다리기를 하므로 KD-FU/FedEraser 에서는 활성화가 씻겨 나감(44/30 % vs 9~14 %). 공격자가 배포된 연산자(KD)를 목적함수에 넣으면 KD 에서도 깨어나는 변형이 가능. 우리 `--op kd` 가 의미를 갖는 지점.
4. **지연 활성**: 위장을 빼도 당장은 안 깨어나고, 이후 몇 라운드의 정상 학습이 마무리하게 설계. 배포 직후 검사만 하면 놓침 → VeriFi 식으로 몇 라운드 뒤까지 창을 두고 재검사.
5. **다중 타깃·동적 트리거**: 활성화가 "한 클래스로 몰림(mass)"으로 안 잡히게 여러 타깃에 분산. `--stat changed` 가 더 맞음. 통계 선택의 근거가 됨.
6. **정상 이탈 악용**: 정상 클라의 이탈로 깨어나게 설계. 우리 데이터(BadFU/FUBA 표 V + 정상 이탈 검증)에서는 안 깨어남. 부정 결과로 보고.

## C. 우선순위 (논문의 '적응형 공격' 절)
돌리지 않고도 정할 수 있는 순서. 기준: 방어의 핵심 가정을 건드리는가, 학습 없이 시뮬레이션되는가.
1. **b 위장자 분산 + a 쪼개기** — 같은 양 비교의 핵심 가정. 둘 다 저장 갱신만으로 됨(★). 전체 예산 장부가 답이면 "누적 비교"가 설계의 중심 부품으로 격상.
2. **c 모집단 오염** — 통계의 강건성. ★. 절사 std 가 답.
3. **i 운반자 분산** — 쌍→집합의 한계. ★.
4. **j 자기 완결형(샘플 단위)** — 가족 정의의 축. BadFU 코드로만 가능. 실험 비용 큼.
5. **d 탐침 사각** — 가장 큰 약점. 해결 못 하면 "범위"로 명시.
6. g, h, e, f — 설계로 답하고 실험은 선택.

## D. 공격 시뮬레이터 (제안, 미구현)
저장 궤적에서 학습 없이 변형을 만드는 작은 모듈 `attack_sim.py`:
- `split_client(k, m)`: U_k 를 m 개 가상 클라로 쪼갬 (b, i)
- `scale_client(j, α)`: 미끼 (c)
- `add_direction(j, v, β)`: 기준 오염 (g)
- `schedule(requests)`: 시간차 요청 목록 (a, h)
출력은 dose_fu/pair_roles 가 읽는 같은 (U, K) 형식. 이러면 적응형 절 전체가 재학습 없이 몇 분 안에 돈다.
