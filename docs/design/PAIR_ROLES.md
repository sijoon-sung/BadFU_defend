# 쌍 검사의 일반화: 운반자 집합과 공동 위장자 (pair_roles.py)

작성 2026-10-11. 코드 `FUBA/pair_roles.py`, run_all.sh 단계 `pair`.

## 0. 한 줄
BadFU/FUBA 는 "심은 자(운반자)"와 "억누른 자(위장자)"의 **쌍**으로 움직인다. 쌍 하나를 가정하면 운반자가 여럿이거나 위장자가 여럿일 때 깨지므로, 쌍을 **집합**으로 넓힌다. 표시된 요청에 대해 "누구를 더 빼면 활성화가 줄어드나"로 운반자 집합 A 를, "누가 혼자 빠져도 이상한가"로 공동 위장자 C 를 찾는다. 둘 다 빼 보기만 쓴다(라벨·트리거·학습 없음).

## 1. 탐지와의 관계
탐지는 `dose_fu.py` 의 같은 양 비교가 맡는다(쌍 구조를 가정하지 않으므로 교수님이 지적한 범용성 문제가 없다). 이 모듈은 **표시된 뒤**에 돌아가는 후속 단계다: 책임 추적(누가 심었나)과 **진짜 제거**(운반자 기여를 지우면 백도어가 '재워지는' 게 아니라 '지워진다').

## 2. 절차 (요청 집합 S, 보통 S={k})
1. θ_S = θ_T − Σ_{s∈S} U_s. 기준 ref = 남들을 각각 다 뺀 모델들의 중앙값 앙상블. 활성화 a(θ) = stat(θ vs ref).
2. **지도**: 모든 j ∉ S 에 대해 Δ_j = a(θ_S) − a(θ_S − U_j). Δ_j > 0 이면 j 를 빼서 활성화가 줄었다 = j 의 기여에 백도어가 있다.
3. **탐욕 선택**: Δ 최대인 j 를 A 에 넣고 θ ← θ − U_j. a 가 모집단 띠 안(z ≤ τ)이거나, margin(기본 20 %) 만큼 더 안 줄거나, |A| 상한이면 멈춤. `--exhaust` 면 띠 안에 들어와도 margin 이 되는 한 계속.
4. **공동 위장자**: C = { j : 자기 혼자 빠졌을 때의 z_j > τ }. 모집단 단일 제거 통계를 그대로 재사용하므로 추가 비용 0.
   (Δ_j < 0 은 쓰지 않는다. "한 명 더 빼서 생긴 일반 열화"와 섞여 정상 클라이언트도 음수가 된다 — 2026-10-11 확인.)
5. 평가: θ_S(요청만), θ_S − U_A(운반자까지), 선택적으로 수정.

여러 위장자가 **같이** 요청하면 `--requesters a b --joint` (S 를 한 번에 뺀다). **따로** 요청하면 dose_fu 의 누적 장부가 다루고, 먼저 처리된 위장자는 여기서 C 로 잡힌다.

## 3. 로컬 1 시드 확인 (loc_fuba, K=8, 운반자 0–3, 위장자 4)
| 요청 S | z0 | 지도 Δ (운반자 / 정상) | A (정밀/재현) | C | ASR: 요청만 → +운반자 |
|---|---|---|---|---|---|
| {4} 위장자 | 11.2 | +0.07~+0.12 / −0.28~−0.33 | {1,3,2} (1.0 / 0.75) | ∅ | 62.9 → 8.8 (ACC 75.0 → 77.1) |
| {7} 정상 | 0.5 | +0.02~+0.04 / −0.07~−0.11 | ∅ | {4} (z 12.8) | 21.7 → 21.7 |
| {4,5} 동시 | 27.7 | +0.09~+0.17 / −0.24~−0.27 | {1,3,2} (1.0 / 0.75) | {7} (z 3.6, 오탐) | 89.8 → 24.3 |

- 운반자 집합은 정밀 1.0. 운반자 0 은 Δ 가 작아(0.066) margin 에 걸려 빠졌다(재현 0.75). ASR 은 8.8 로 떨어져 **지움**이 실제로 된다.
- 정상 요청에서는 집합이 비고, 진짜 위장자 4 가 C 로 잡힌다(혼자 빠져도 z 12.8).
- 동시 요청에서 정상 7 이 C 로 오탐(z 3.6, 문턱 3 근처). 모집단이 6 명뿐이라 z 가 흔들린다. 시드로 확인할 것.
- 운반자 제거 뒤 수정(--repair)은 ASR 을 오히려 올렸다(8.8 → 16.0): 수정 기준(모집단)에 남은 운반자 0 이 들어 있기 때문. 운반자 제거 뒤에는 수정을 하지 않거나, 기준에서 A 를 빼야 한다. 기본은 끔.

## 4. 여러 위장자 궤적
FUBA 코드에 `--clients_ratial r` 을 노출했다(main.py/config.py). r=2 면 K=16, 백도어 측 0–9 중 위장자는 4 와 8, 운반자 {0,1,2,3,5,6,7,9}, 정상 10–15. `NB_CLIENTS=8 EXTRA_ARGS="--clients_ratial 2" bash run_real_fuba.sh <name> <seed>` 로 만든다. 그 궤적에서 pair_roles 를 `--defenders 4 8 --attackers 0 1 2 3 5 6 7 9` 로 돌리면 위장자가 둘일 때의 A, C 가 나온다. (옵션만 노출했고 16 명 궤적 생성은 아직 확인하지 못했다. 세션이 중단되어 검사 실행이 끊김.)

## 5. 비용
지도 1 회 = (K−|S|) 모델 + 탐침 통과. 탐욕 한 걸음마다 다시 (K−|S|−|A|). 최악 O(K²) 모델이지만 학습은 없다. 로컬 K=8: 요청 하나에 2–3 초.

## 6. 범위 밖
- 운반자 기여를 통째로 빼면 그들의 정상 기여도 사라져 ACC 가 준다(8 명 중 3 명 제거: 75 → 77, 원래 94.8). "기여 중 백도어 방향만" 빼는 것은 별도 문제.
- 탐침에 트리거가 안 보이는 공격(BadFU 패치)은 a(θ) 자체가 신호가 없어 지도도 비어 있다(dose_fu 와 같은 한계).
