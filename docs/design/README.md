# 한 장 정리 (2026-10-11)

## 연구 질문
연합 언러닝(FU)에서, 삭제 요청으로 **깨어나는** 백도어(BadFU, FUBA)를 서버가 어떻게 안전하게 처리하는가.

## 제안 (기법 하나)
**투여량 조절 FU.** 요청자를 뺀다 → 남들을 같은 양만큼 뺐을 때와 비교해 이상한지 본다 → 이상하면 남들 입력에서의 행동만 되돌린다.
- 정상 요청이면 기본 FU 와 **완전히 같은 결과** (손대지 않음).
- 라벨·트리거·학습 없음. 비용은 "몇 명과 비교하느냐"로 정해짐.
- 모델이 약하면 자동으로 여러 단계로 나눠 뺀다(무너진 모델은 내보내지 않음). 멀쩡하면 한 단계.
- 뒤따르는 부품: **쌍→집합** (누가 심었나 찾아서 지우기).

## 지금까지 확인된 것
| | 결과 |
|---|---|
| FUBA IID (3 시드) | 위장자 요청 ASR 49 → 6, 정상 요청은 기본 FU 와 동일(오탐 0). 한 단계로 끝남 |
| FUBA owner non-IID (3 시드) | 위장자 요청 ASR 53 → 10. **그러나 클래스 소유자(정상 7)가 3 시드 중 2 번 오탐**되어 수정이 그의 망각을 되돌림 (49 → 70). 범용성 문제의 실체 |
| BadFU (CIFAR ResNet) | 깨끗한 탐침으로는 안 보임. 빼기 자체가 모델을 무너뜨림 → 멈춤 처리됨 |
| 기준선 (3 시드) | MASA: 운반자 AUROC 0.97~1.0, 위장자 0.0~0.1 → 학습 중엔 위장자가 안 보인다. SubID 식: IID 에선 위장자 1 위(3 중 2 표시), owner 에선 소유자가 더 이상해 2 위 — 갱신 기하는 non-IID 에 약함 |
| 적응형 (1 시드 검사) | 쪼개기·기준 오염은 버팀. **위장자 분산·미끼·운반자 분산은 뚫림** |

## 약점 (고칠 것)
0. **non-IID 소유자 오탐** (3 시드 결과): 한 클래스를 혼자 가진 정상 클라를 빼면 그 클래스 입력에서 행동이 크게 바뀌어 위장자처럼 보임 → 통계를 "한 클래스로 몰림"에서 "다른 클래스로 *빨려 들어감*" 과 구분하거나, 탐침을 남들 분포로 가중
1. 위장자 여러 명이 나눠 요청하면 놓침 → "n 명 제거" 띠로 전체 예산 비교
2. 미끼 클라가 표준편차를 부풀리면 놓침 → 절사 표준편차
3. 운반자가 여럿이면 탐욕 선택이 못 찾음 → 집단 제거 검사
4. 탐침에 트리거가 안 보이면(BadFU 패치) 신호 없음 → 범위로 명시하거나 탐침 확장
