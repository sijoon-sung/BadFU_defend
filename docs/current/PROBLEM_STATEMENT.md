# 탐지와 정화의 문제 정의

2026-10-17. 이 문서와 [결과표](../../RESULTS.md)가 현재 판단의 기준이다.
과거 설계 문서의 목표·예상 성능을 완료 결과로 승계하지 않는다.

## 공통 현상: 삭제가 맞게 수행돼도 모델은 위험할 수 있다

전체 자료 $D=D_R\cup D_F$, 학습 알고리즘 $A$, 삭제 요청 $r$에 대해
$\theta_-=A(D)$, $\theta_+=U(\theta_-,H,r)$로 표기한다.
FU는 삭제 대상 $D_F$의 영향을 지워 잔류 자료의 재학습 $A(D_R)$에 가까워지는 것을 목표로 한다.
그러나 $D_R$에 독성 기여가 남고 $D_F$가 그 발현을 억제했다면, 삭제 뒤 백도어가 드러날 수 있다.
**삭제 정확성, 정상 효용, 백도어 안전성은 같은 조건이 아니다.**

우리가 다루는 것은 FL 학습과 FU 삭제를 함께 이용하는 잠복 백도어다.
모든 FU 성능 저하, 모든 공격 의도, 모든 악성 클라이언트를 식별하는 범용 문제로 넓히지 않는다.
BadFU와 FUBA는 이 공통 현상을 갖지만 삭제 단위·실제 실행은 별도로 확인한다.
현재 BadFU 자동 실행은 공개 코드의 별도 client 5 삭제이며 논문의 내부 위장 샘플 삭제와 동일하지 않다.

## 1. 탐지: 어떤 삭제 요청에 활성화 위험이 있는가

**연구 질문:** 개별 업데이트나 요청은 정상처럼 보이더라도, 그 요청이 과거 기여 관계를
제거함으로써 생기는 잠복 백도어 위험을 정상 Non-IID 변화와 구분할 수 있는가?

| 항목 | 정의 |
| --- | --- |
| 기본 입력 | 서버가 저장한 학습 이력 $H$, 실제 삭제 요청 $r$, 삭제 전 모델, 명시된 공개 probe 자료 |
| 출력 | 요청 위험 점수·순위, 근거가 된 입력/출력 좌표, 관측 부족 시 보류 |
| 사전 탐지 | 실제 FU 후 모델을 쓰지 않은 결과만 해당 |
| 사후 위험 관측 | 실제 $\theta_+$를 사용한 차분 검사. 사전 탐지와 별도로 보고 |
| 알 수 없는 정보 | 공격자의 의도·진짜 트리거·공모 역할. 평가용 정답을 탐색에 넣지 않음 |
| 성공 기준 | 독립 정상 실제-FU 대조에서 오탐률을 제한하면서 위험 요청을 검출하고, 같은 정보의 단순 기준선보다 개선 |
| 함께 보고할 지표 | TPR/FPR, 보류율, 모델/seed 단위 변동, 탐지 시점의 실제 공격 반응 |

정상 Non-IID도 지속적인 상쇄, 큰 삭제 변화, 일부 클래스의 성능 손실을 만든다.
이 특징만으로 악성 의도를 결정할 수 없다. 따라서 모든 환경에서 완전 분리한다는 주장을 하지 않는다.
개발 궤적의 요청자 1위, 공격 한 번의 큰 점수, 같은 모델의 여러 이미지 묶음은 독립 탐지 성공률이 아니다.
실제 FU 대신 누적 업데이트를 뺀 모델이 붕괴하면 해당 점수를 실제-FU 탐지 성능으로 쓰지 않는다.

**현재 결론:** 특정 입력 조건의 위험 신호는 관측했다. 이력/시계열 점수의 추가 이득과
독립 정상 오탐률은 입증하지 못했고, 정상 설명 집합은 현재 설정에서 실패했다.
[탐지 작업과 기록](DETECTION.md).

## 2. 정화: 삭제 후 위험을 줄이되 무엇을 보존할 것인가

**연구 질문:** 실제 삭제를 마친 모델에서 활성화된 취약 변형을 찾아,
삭제 후 정상 기능을 가능한 범위에서 유지하며 백도어 반응을 줄일 수 있는가?
삭제 자체를 되돌리거나 삭제 전 모델 전체를 복원하는 것은 목적이 아니다.

| 항목 | 정의 |
| --- | --- |
| 입력 | 같은 요청의 실제 pre/post 모델, 공개 정상 이미지·라벨·전처리 |
| 출력 | 교정 모델, 정상 기능 손상과 실제 공격 반응, 제약을 만족하지 못한 경우 명시적 실패/원래 post 반환 |
| 핵심 비교 | 같은 공개 자료·탐색·정화 절차에서 pre/post 정보가 post-only보다 유리한가 |
| 현재 연산 | 변형의 전후 마진 차분 탐색 → 공개 정답으로 교정 → post 기준 클래스별 손실 검사 |
| 성공 기준 | 실제 트리거 ASR 감소와 정상/클래스별 효용의 개선된 절충, 별도의 삭제 효과 검증 |
| 필요한 대조 | 무정화 post, 정상 미세조정, post-only, 전후 차분, CVaR 추가, 제약 추가; 이후 공식 방어 |

연구 목표는 다음처럼 표현할 수 있다.

$$\min_\theta R_{\rm backdoor}(\theta)
\quad\mathrm{s.t.}\quad
L_c(\theta)\le L_c(\theta_+)+\epsilon_c,\quad
\text{삭제 효과에 관한 별도 검증 조건}.$$

실제 공격 위험 $R_{\rm backdoor}$는 학습 중 알 수 없어 공개 입력의 탐색 변형 손실을 대리 목적으로 쓴다.
현재 구현은 공개 개발·검증 자료의 클래스 CE 조건만 검사한다. 모집단 효용이나 인증된 망각 제약을
이미 구현한 것은 아니다. pre 모델을 사용하면 삭제 자료 정보가 다시 영향을 줄 수 있어 후처리 보장도 자동 승계되지 않는다.

**현재 결론:** 여섯 비교군 구현과 축소 연결 검사만 완료했다. 본 성능·기존 방어 대비 개선·망각은 미측정이다.
[구현 수식·가정·한계](PURIFICATION_COMPARE.md).

## 두 브랜치에서 섞지 않을 것

- `detection`: 요청 위험을 관측·판별하는 방법과 탐지 지표를 관리한다.
- `purification`: 실제 FU 후 교정과 ASR–효용–망각 평가를 관리한다.
- 실제 post를 쓰는 위험 관측은 탐지 분석에 포함할 수 있지만 사전 탐지 결과로 보고하지 않는다.
- 같은 관측 신호를 정화에 사용할 수 있어도, 탐지 성공과 정화 성공은 각각 검증한다.
- 공유 기록기·원본 공격 코드·평가 도구는 양쪽에 남긴다. 브랜치 구분은 연구 목적과 실행 안내의 구분이다.
- CVaR, QP, CBF, 두 모델 비교 자체는 신규성이 아니다. 조건에 맞는 연산과 검증된 추가 이득이 필요하다.
