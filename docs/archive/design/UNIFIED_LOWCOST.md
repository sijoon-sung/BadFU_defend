# 두 공격을 한 번에, 가장 싸게 잡는 신호는 무엇인가 (2026-10-12)

설계 메모. 코드 변경 없음. 로컬 확인 두 번(BadFU 궤적 `BadFU_src/BadFU-main/logs/traj_full`, 6 명, 위장자 5, 공격자 0, 1 시드, 각 1 분 안쪽)만 돌렸다. 확인 스크립트는 스크래치(`chk1_shape.py`, `c2.py`)에 있고 저장소에 넣지 않았다.

## 0. 결론 먼저 (쉬운 말)

1. 지우려는 사진을 서버가 보지 않고는 BadFU 쪽(위장자)은 잡을 수 없다. 이번 확인으로 그 이유가 더 분명해졌다.
2. 위장자의 기여는 가중치 모양으로는 보통 사람과 구별되지 않는다 (확인 1).
3. 위장자의 기여를 빼도 공개 사진에서는 "클래스 0 을 많이 가진 보통 사람"을 뺀 것과 똑같이 보인다 (확인 2). 트리거 사진에서만 다르다.
4. 사진 대신 "중간층 특징"을 받아도 안 된다. 트리거를 알아보는 부분이 앞쪽 층에 있어서, 뒤쪽 층만 바꿔 봐서는 신호가 사라진다 (확인 2).
5. 그래도 비용은 크게 줄일 수 있다. 모델을 여러 개 만들어 돌리는 대신, **지우려는 사진에서 손실의 기울기를 한 번만 구하고, 저장된 기여 벡터들과 내적**하면 된다. 1 시드에서 위장자가 또렷하게 튀었다 (확인 2 마지막 표).
6. 그 기울기 신호는 "손실이 모든 클래스에서 고르게 오르는가(위장자)" 와 "자기 클래스에서만 오르는가(클래스 소유자)" 로 모양이 달라서, non-IID 소유자 오탐 문제에도 손잡이가 된다.
7. 추천: **2 단 구조**. 1 단은 기울기 내적으로 거르기(몇 초). 1 단에 걸린 요청만 2 단에서 지금의 투여량 절차(건강 확인 + 수정)를 돌린다. 안 걸리면 기본 FU 그대로.
8. 서버가 받는 것은 지우려는 사진의 **입력만**(라벨 없음), 그것도 무작위 일부. 학습 때 해시로 봉인해 바꿔치기를 막는 것은 그대로.
9. 아직 확인 안 된 것: FUBA 에서 기울기 신호가 서는지, 라벨 없이(모델의 예측을 라벨로) 해도 되는지, 시드 여러 개. 이 메모는 설계 결정용이지 결과 보고가 아니다.

## 1. 문제 정리

| | FUBA (억제자) | BadFU (위장자) |
|---|---|---|
| 요청자 데이터 | 적대적으로 학습된 억제 기여 | 트리거 붙은 사진 + **정답 라벨** (보통 학습) |
| 빼면 어디서 달라지나 | 공개 입력에서도 달라짐 | **트리거 붙은 입력에서만** |
| 지금 잡히나 | 공개 탐침으로 z 11~14 | 잊을 집합을 탐침에 더해야 z 8.4 |
| 현행 비용 (한 단계) | 기여 빼기 K 번 + 모델 (K+1) 개에 약 500~1000 장 통과 | 같음 |

질문: 서버가 **지우려는 사진을 보지 않고**, 또는 **덜 보고**, 둘 다 잡는 더 싼 방법이 있는가.

## 2. 로컬 확인 두 번 (BadFU, 1 시드)

### 확인 1 — 가중치 모양만으로 위장자가 보이는가 (`latent_risk.py` 식, ResNet-18 15 라운드)

라운드별 기여의 노름·최대 특이값 비율·유효 랭크·질량 집중도·라운드 간 일관성을 전체/fc/conv1 에서 재고, 요청자(5)가 나머지 5 명에서 얼마나 튀는지(z) 봤다. 추가로 누적 기여끼리의 코사인, 그리고 "공개 사진 500 장의 Fisher 로 봤을 때 기여가 공개 데이터에 민감한 방향에 얼마나 실려 있나"도 쟀다.

| 특징 | 위장자 5 의 z (나머지 5 명 기준) | 순위 /6 |
|---|---|---|
| 노름 (전체 / fc / conv1) | −1.5 / −2.4 / −1.2 | 6 / 6 / 6 (가장 작음) |
| 최대 특이값 비율 (전체 / fc / conv1) | +0.2 / −0.7 / +0.9 | 2 / 5 / 2 |
| 유효 랭크 (전체 / fc / conv1) | −0.5 / +0.7 / −0.4 | 4 / 2 / 5 |
| 질량 집중도 (전체 / fc / conv1) | +1.0 / +2.0 / −1.0 | 2 / 1 / 5 |
| 라운드 간 일관성 | +0.7 | 2 |
| 공개 Fisher 비율 | 27.5 (나머지 24.7~31.3) | 4 |

- 13 개 특징 모두 |z| < 2.5. 모양으로는 안 보인다. **예상대로다**: 위장자는 자기 데이터로 보통 학습을 했을 뿐이고, 트리거 사진은 전체의 10 % 안쪽이라 가중치 모양에 흔적을 남기지 않는다.
- 유일하게 튀는 것은 누적 기여의 코사인 **0 ↔ 5 = 0.95** (다른 쌍 0.50~0.79). 그러나 이것은 이 궤적에서 공격자 0 과 위장자 5 가 **같은 깨끗한 데이터(clean0)를 공유**하도록 만든 설정의 흔적이지 공격의 흔적이 아니다. 실제 배치에서 둘이 데이터를 공유할 이유가 없으므로 신호로 쓸 수 없다 (FoolsGold 식 "닮은 갱신 벌점"과 같은 함정).
- FUBA 쪽에서 노름 AUROC 1.0 이 나온 것(`logs/latent_risk/summary_iid.md`)도 억제자가 **적대적으로 학습된** 기여라서 생긴 것이고, BadFU 류에는 옮겨지지 않는다.

### 확인 2 — 기여를 뺀 효과가 어디에 나타나는가 (선형화 + 부분 공개)

공개 사진 500 장(CIFAR 테스트 앞부분)과 위장 사진 500 장(트리거 + 정답 라벨, 요청자가 지우려는 것)에서, 각 클라이언트의 기여를 20 % 뺀 모델이 삭제 전과 답이 달라지는 비율(변경), 달라진 것 중 클래스 0(진짜 타깃)으로 간 비율(→0)을 쟀다. 네 가지 방식: 실제로 빼서 통과 / 가중치에 대해 선형 근사(JVP, BN 통계는 실제값) / 끝층(fc)만 바꿔서 / layer3 특징은 삭제 전 모델에서 받고 layer4+fc 만 바꿔서.

| 클라 | 공개: 변경 / →0 | 트리거: 변경 / →0 (실제) | 트리거: 선형 근사 | 트리거: fc 만 | 트리거: layer4+fc 만 | 실제 ASR |
|---|---|---|---|---|---|---|
| 0 공격자 | 9.4 % / 0.04 | 30.6 % / 0.00 | 30.4 % / 0.00 | 18.2 % / 0.00 | 22.4 % / 0.00 | 0.4 |
| 1 | 10.0 % / 0.18 | 21.2 % / 0.03 | 25.4 % / 0.67 | 13.2 % / 0.74 | 13.6 % / 0.79 | 12.2 |
| 2 | 11.0 % / 0.16 | 23.6 % / 0.01 | 22.0 % / 0.60 | 11.4 % / 0.72 | 9.0 % / 0.62 | 10.0 |
| 3 | 10.4 % / 0.17 | 21.0 % / 0.02 | 24.6 % / 0.63 | 8.0 % / 0.68 | 5.4 % / 0.67 | 11.2 |
| 4 | 8.2 % / 0.24 | 19.4 % / 0.08 | 23.2 % / 0.70 | 13.8 % / 0.83 | 10.0 % / 0.66 | 17.4 |
| **5 위장자** | 9.4 % / 0.02 | 22.8 % / **0.82** | 45.8 % / 0.89 | 12.2 % / **0.00** | 7.0 % / 0.74 | **41.6** |

읽는 법:
- **공개 사진에서 위장자는 보통 사람과 같다** (변경 9.4 %, 남들 8~11 %). →0 비율이 낮은 것(0.02)은 공격자 0 과 똑같은데, 둘 다 클래스 0·1 데이터를 가진 "소유자"라서다. 즉 공개 입력에서 보이는 것은 데이터 소유 구조이지 공격이 아니다. 이것이 non-IID 소유자 오탐의 정체이기도 하다.
- **트리거 사진에서만 다르다**: 위장자를 빼면 달라진 답의 82 % 가 타깃 0 으로 간다. 남들은 0~8 %. 변경 비율 자체(22.8 %)는 남들과 비슷하므로 "얼마나 변했나"가 아니라 "**어디로** 변했나"가 신호다.
- **끝층만 바꾸면 신호가 0 이 된다** (→0 = 0.00). layer3 에서 잘라도 남들과 구별이 안 된다(0.74 vs 0.62~0.79). 트리거를 알아보는 부분이 앞쪽 합성곱에 있고, 삭제 전 모델로 뽑은 특징에는 이미 "트리거 무시"가 구워져 있어서 뒤쪽 가중치를 바꿔 봐야 드러나지 않는다. **특징 공개(분할 학습식)로 사진 공개를 대신할 수 없다.**
- 가중치 선형 근사는 방향은 맞지만 크기를 과장한다(45.8 % vs 실제 22.8 %, 남들도 →0 을 0.6~0.7 로 부풀림). 선형화는 "순위 매기기"엔 쓸 수 있어도 "무너졌나" 판단엔 못 쓴다. 비용도 순전파와 같은 급이라 이득이 없다.

같은 입력에서 **기울기 내적**: 삭제 전 모델에서 클래스별 평균 손실의 기울기를 구하고, 각 클라이언트 기여의 20 % 와 내적했다 (양수 = 빼면 그 클래스 손실이 오름).

| 클라 | 공개 사진 (클래스 0 … 9) | 트리거 사진 (클래스 1 … 9; 0 없음) | 합 |
|---|---|---|---|
| 0 공격자 | +0.6 / 나머지 대부분 음수 | **전부 음수** (−1.2 … −6.9) | −34.7 |
| 1 (2·3 소유) | 2·3 에서 +0.9, +0.8 | 2·3 에서 +1.0, +2.3, 나머지 ≈ 0 | +3.2 |
| 2 (4·5 소유) | 4·5 에서 +0.4, +1.3 | 4·5 에서 +1.8, +1.6, 나머지 ≈ 0 | +5.0 |
| 3 (6·7 소유) | 6·7 에서 +0.5, +0.9 | 6·7 에서 +1.7, +1.3, 나머지 ≈ 0 | +4.8 |
| 4 (8·9 소유) | 8·9 에서 +0.3, +0.3 | 8·9 에서 +0.4, +1.0 | +0.7 |
| **5 위장자** | 0 에서 +0.4 (공격자와 같은 모양) | **9 개 클래스 전부 양수** (+0.5 … +3.0) | **+14.9** |

- 트리거 사진에서 위장자는 **모든 클래스의 손실을 고르게 올린다** (트리거 무시를 가르친 기여를 빼니 트리거 사진 전부가 흔들린다). 보통 사람은 **자기 클래스에서만** 올린다. 공격자는 전부 내린다(백도어를 빼니 트리거 사진이 편해진다).
- 이 모양 차이("고르게" vs "자기 것만")가 소유자 오탐을 가르는 손잡이가 된다. 합만 보면 위장자 +14.9 vs 보통 +0.7~+5.0 (약 3~4 σ), 모양까지 보면 더 벌어진다.
- 비용: 기울기 두 번(공개, 잊을 집합) + 내적 K 번. 모델을 K 개 만들어 1000 장씩 통과시키는 현행과 비교하면 K 에 비례하는 순전파가 사라진다.

## 3. 후보 표 (추천 순)

비용 열의 기준: 현행 한 단계 = 기여 빼기 K 번 + 모델 (K+1) 개 × 약 1000 장 순전파. K=100 ResNet 에서 분 단위.

| 순위 | 후보 | 서버가 필요한 것 | 비용 (현행 대비) | A FUBA | B BadFU | 핵심 가정 | 비교할 선행 |
|---|---|---|---|---|---|---|---|
| 1 | **기울기 내적 거르기** — 삭제 전 모델에서 공개 사진·잊을 사진의 (클래스별) 손실 기울기를 구하고 각 기여 벡터와 내적. 요청자를 남들과 같은 방식으로 비교. "고르게 오름 / 자기 클래스만 오름" 모양 추가 | 저장된 기여 K 개(이미 있음), 공개 사진, **잊을 집합의 입력**(라벨은 모델 예측으로 대체 가능할 듯, 미확인) | 역전파 2 번 + 내적 K 번. **순전파 K 배가 사라짐**(초 단위) | 기대됨(미확인: 억제자는 공개 사진에서 새므로 공개 기울기에 잡혀야 함) | **1 시드 확인**(합 +14.9 vs +0.7~+5.0, 모양 고르게) | 1 차 근사로 순위를 매겨도 된다 (크기는 믿지 않음). 무너짐·수정은 못 함 | FLTrust (Cao, NDSS'21: 뿌리 데이터 기울기와의 코사인), TracIn (Pruthi, NeurIPS'20), 영향 함수 (Koh & Liang, ICML'17), Qian KDD'23 / Liu AAAI'24 (요청 샘플의 기울기 영향), FedMUA 방어 (기울기 노름) |
| 2 | **현행 투여량 절차** (공개 + 잊을 집합에서 같은 양 비교, 건강 확인, 수정) | 위와 같음 | 기준 1× | 3 시드 확인 | 1 시드 확인(z 8.4) | 빼기 연산자가 깊은 망에서 전량 전에 무너짐 | MASA (WACV'25), Zhang 2023 단계 제거, 2026 clean-label Appendix E 대조군 |
| 3 | **2 단 결합 (추천)** = 1 로 거르고 걸린 요청만 2 | 위와 같음 | 정상 요청: 초 단위. 걸린 요청만 1× | 둘 다(1 의 재현율에 의존) | 둘 다 | 1 이 놓치면 2 도 안 돈다 → 1 의 문턱을 느슨하게 | 위 둘의 합 |
| 4 | 공개 사진만의 닫힌 집합 비교 (현행에서 잊을 집합 제거, 또는 공개 기울기 내적만) | 공개 사진 | 1× 또는 초 단위 | 잡힘 | **못 잡음** (확인 2: 위장자 = 클래스 소유자와 동일) | 효과가 공개 입력에 새야 함 | FLTrust, 우리 `--probe_mode clean` |

## 4. 추천

**2 단 구조 (후보 3).**

- 1 단 (매 요청, 초 단위): 삭제 전 모델에서 공개 사진과 잊을 집합(입력만, 무작위 일부, 해시 대조)의 클래스별 손실 기울기를 구한다. 저장된 기여 K 개와 내적해 클래스별 표를 만든다. 요청자의 표를 남들의 표와 같은 방식으로 비교한다(지금의 z 방식 그대로). 두 가지를 본다: 잊을 집합에서 손실이 **얼마나** 오르는가, 그리고 **몇 개 클래스에서 고르게** 오르는가. 자기 클래스에서만 오르면 소유자, 고르게 오르면 위장자.
- 2 단 (1 단에 걸린 요청만): 지금의 투여량 절차. 건강 상한, 같은 양 비교, 수정. 무너짐 판단과 수정은 1 단이 못 하므로 그대로 둔다.
- 정상 요청은 1 단만 거치고 기본 FU 와 같은 모델을 받는다(P1 유지). 비용은 정상 요청에서 거의 0 이 되고, 걸린 요청에서만 지금과 같다.
- 공개 범위: 라벨 없음, 사진 입력만, 요청자 사진의 무작위 일부(트리거 사진에서 신호가 82 % vs 8 % 로 크므로 수십~백 장이면 충분할 것으로 보이나 미확인), 삭제 처리 뒤 폐기.

왜 이것이 "가장 싼 하나의 신호"인가: 두 공격 모두 "요청자 기여를 빼면 어떤 입력의 손실이 오른다"는 한 문장으로 정의되고, 그 1 차 근사가 기울기 내적이다. FUBA 는 공개 입력에서, BadFU 는 잊을 입력에서 오른다. 입력 집합만 다르고 계산은 하나다.

아직 모르는 것 (설계 결정 전에 확인할 것, 실험 계획은 아님):
1. FUBA 궤적에서 공개 기울기 내적이 억제자를 가르는가 (기대는 됨, 숫자 없음).
2. 라벨 없이(모델 예측을 라벨로, 또는 예측 분포의 엔트로피 기울기) 해도 BadFU 신호가 남는가. 이번 확인은 정답 라벨을 썼다.
3. 시드 여러 개, K=20 설정에서 문턱.
4. 1 단이 놓치고 2 단이 잡는 경우가 있는지 (있다면 1 단 문턱을 더 느슨하게).

## 5. 잊을 집합 없이는 안 되는 것 (이유)

- **위장자 기여의 내용은 "이 무늬(트리거)를 무시하라"이다.** 그 내용은 무늬가 있는 입력에서만 드러난다. 서버는 무늬를 모른다. 무늬가 없는 어떤 입력(공개 사진, 합성 입력, 잡음)에서도 위장자 기여는 "클래스 0·1 데이터를 가진 보통 사람"과 똑같이 작동한다 (확인 2 의 공개 행).
- **가중치에는 흔적이 없다.** 위장자는 보통 학습을 했고 트리거 사진은 소수이므로 노름·스펙트럼·집중도·일관성 어느 것도 튀지 않는다 (확인 1). 유일한 흔적(공격자와의 0.95 코사인)은 데이터 공유 설정의 산물이다.
- **중간층 특징도 안 된다.** 트리거를 알아보는 뉴런은 앞쪽 합성곱에 있다. 삭제 전 모델로 뽑은 특징에는 "무시"가 이미 들어 있어서 뒷층을 바꿔도 안 보인다 (확인 2: fc 만 바꾸면 신호 0).
- **요청자가 계산해 주는 것은 못 믿는다.** BadFU 에서 요청자가 곧 공격자다. 보고·기울기·통계 무엇을 보내도 깨끗한 사진으로 만든 값을 보내면 그만이다. 해시 봉인은 "그때 그 사진"임을 보장할 뿐 내용을 알려 주지 않는다.
- **무늬를 서버가 직접 찾는 길(패치 탐색)** 은 이미 시도해 실패했고(`--probe_mode search`, z −1.8~+2.1), 트리거 형태 가정과 비용, Neural Cleanse 와의 중복 때문에 채택하지 않는다.
- 따라서 "지우려는 사진을 보지 않고 BadFU 를 잡는 방법"은 효과 기반이든 가중치 기반이든 없다. 남는 길은 **사진을 보되 가장 적게 보는 것**(입력만, 일부만, 봉인·폐기) 아니면 **보지 않고 계산하는 암호 계산**(후보 10, 후보 1 과 합치면 역전파 한 번) 둘뿐이다.
