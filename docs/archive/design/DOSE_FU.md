# 투여량 조절 연합 언러닝 (Dose-controlled FU) — 알고리즘 설계

작성 2026-10-11. 코드 기준: `FUBA/progressive_fu.py`, `FUBA/release_map.py` (빼기·모집단·수정 부품은 그대로 재사용).

## 0. 한 줄
삭제 요청을 **투여량**처럼 다룬다. 모델이 견디는 양만큼만 빼고(상한 c), 뺄 때마다 "다른 사람을 같은 양만큼 뺐을 때"와 비교해 이상하면 고치고, 다 뺄 때까지 반복한다. 멀쩡한 모델에서는 한 단계로 끝나 **한 번에 빼기와 같아진다**. 단계 수는 사람이 정하지 않고 모델의 약함이 정한다.

## 1. 입력과 기호
| 기호 | 뜻 | 어디서 오나 |
|---|---|---|
| θ_T | 학습이 끝난 전역 모델 | FL 결과 |
| U_j | 클라이언트 j 의 누적 기여 벡터 (라운드별 갱신의 가중합) | FedEraser 류 FU 가 이미 저장 |
| X_p | 라벨 없는 탐침 입력 n 장 (n≈500) | 서버 보유 공개 데이터 또는 합성 |
| k | 삭제 요청 클라이언트 | 요청 |
| R(θ, j, ρ) | j 의 기여를 비율 ρ 만큼 뺀 모델. 빼기 FU 에서는 θ − ρ·U_j | FU 연산자 |
| d(θ_a, θ_b) | X_p 에서 두 모델의 예측이 다른 비율 (0~1). 보조로 평균 확률 이동 | `divergence`, `shift` |
| c | 건강 상한: 한 단계에서 모집단 중앙값이 넘어서는 안 되는 d | 초모수 (0.15~0.3) |
| τ | 이상 문턱 (강건 z 점수) | 초모수 (3) |
| m | 모집단 표본 수 (m = K−1 이면 전원) | 비용 손잡이 |
| W | 누적 장부 창 길이 (라운드 수) | 쪼개기 공격용 |

## 2. 부품 셋

**부품 A. 건강한 투여량 고르기 (collapse guard)**
```
dose(θ, ρ_left):                       # ρ_left: 아직 안 뺀 비율
  for δ in [ρ_left, 0.8, 0.6, 0.4, 0.2, 0.1] (δ ≤ ρ_left 인 것만):
      h = median_j { d( R(θ, j, δ), θ ) }  # 요청자 제외 전원(또는 표본 m)
      if h ≤ c: return δ
  return δ_min (=0.1)                     # 그래도 넘으면 가장 작은 양
```
핵심: 상한은 **요청자**의 변화가 아니라 **모두**의 변화 중앙값에 건다. 요청자의 변화가 큰 것은 신호이고, 모두의 변화가 큰 것은 무너짐이다. 둘을 분리하는 것이 이 설계의 요점.

**부품 B. 같은 양 비교 (detection)**
```
check(θ, k, δ):
  P = { R(θ, j, δ) : j ≠ k, d(R(θ,j,δ), θ) ≤ c }     # 건강한 가상 제거 모집단
  ref = 중앙값 앙상블(P)                              # 입력별 확률의 중앙값
  s_k = d( R(θ, k, δ), ref )
  s_j = d( R(θ, j, δ), ref_{-j} )  for j in P        # 각자 자기를 뺀 기준으로
  z = ( s_k − median(s_j) ) / scale(s_j)        # scale: 기본 std, 옵션 MAD
  return z, ref
```
반환값 z > τ 이면 "행동 변경 요청"으로 표시. 모집단 P 는 요청자와 무관하므로 요청 한 건당 한 번만 만들고 캐시한다.
scale 에 MAD 를 쓰면 더 강건해 보이지만, FUBA 기본 설정(8 명 중 공격자 4 + 억제자 1)처럼 **제거 효과가 거의 0 인 멤버가
모집단의 절반을 넘으면** 중앙값·MAD 가 그쪽에 붙어 정상 요청(s=0.05)도 z=15 가 된다(2026-10-11 확인). 기본은 std.

**부품 C. 작은 수정 (repair)**
```
repair(θ_k, ref, X_p):
  목적: X_p 에서 θ_k 의 예측 분포를 ref 쪽으로. 손실 = KL( softmax(θ_k(x)) ‖ ref(x) )
  SGD lr 0.001, 최대 50 걸음, 기울기 클립 5, BN 통계 고정
  발산(NaN)하면 수정 전으로 되돌리고 실패 표시
  (조기 종료 옵션: N 걸음마다 check 해서 z ≤ rep_stop 이면 멈춤. 탐침 z 는 10 걸음이면 떨어지지만 ASR 은 더 걸려서
   조기 종료하면 ASR 19 가 남았다(50 걸음 전부: 8). 기본은 끔)
```
라벨 없음, 트리거 지식 없음. "남들 입력에서의 행동만 되돌린다"는 정의 2 의 뒷부분을 이 손실이 그대로 구현한다.

## 3. 본 알고리즘 (한 요청)
```
DOSE_FU(θ_T, k, c, τ):
  θ ← θ_T ; ρ ← 0 ; log ← []
  while ρ < 1:
      δ   ← dose(θ, 1−ρ)                 # 부품 A
      z, ref ← check(θ, k, δ)            # 부품 B (모집단 캐시)
      θ   ← R(θ, k, δ)                   # 실제로 뺀다
      ρ   ← ρ + δ
      if z > τ:
          θ, ok ← repair(θ, ref, X_p)    # 부품 C
      log.append( (δ, z, z>τ, ok) )
  return θ, log
```
출력은 언러닝된 모델 θ 와 단계 기록. 기록에 표시가 하나라도 있으면 요청은 "행동 변경 요청"이며 서버는 거부·감점·감사 등 정책을 적용할 수 있다. 이 알고리즘은 정책을 정하지 않고 사실만 넘긴다.

## 4. 성질 (주장할 것)
- **P1 정상 요청 동일성.** 어느 단계도 표시되지 않으면 θ_out = R(θ_T, k, 1) 로 기본 FU 와 **완전히 같은 모델**이다. 정상 요청자의 망각은 기본 FU 와 동일하고, 추가 비용은 확인뿐이다. (FUBA 세 시드에서 정상 요청자 표시 0 → 이 성질이 실제로 성립)
- **P2 건강.** 모든 중간 모델에서 모집단 변화 중앙값 ≤ c. 무너진 상태에서 확인·수정을 하지 않는다.
- **P3 정의 2.** 표시된 요청에 대해 출력의 X_p 예측은 모집단 띠 안(z ≤ τ)이다. 즉 "남들을 뺐을 때와 구분되지 않는 행동".
- **P4 적응성.** 멀쩡한 모델(FUBA LeNet)에서는 δ=1 로 한 단계에 끝나 한 번에 빼기와 비용이 같다. 약한 모델(BadFU ResNet, ρ≥0.8 에서 무너짐)에서만 단계가 늘어난다.

## 5. 누적 장부 (쪼개기 공격, 후보 1)
한 클라이언트가 요청을 나눠 내면 요청 한 건의 z 는 작다. 그래서 비교를 **누적 제거량**에 건다.
```
서버는 클라이언트별로 V_k = (최근 W 라운드 안에) 지금까지 뺀 k 의 기여 벡터 합을 보관.
새 요청이 오면 V_k ← V_k + (이번에 뺄 조각).
check 를 δ 대신 V_k 전체로 수행:  s_k = d( θ_cur − (이번 조각), ref )  대신
                                  s_k = d( θ_cur − (이번 조각), θ_cur + V_k_prev ) 를 기준으로 한 누적 z.
   즉 "k 의 요청을 하나도 안 들어줬다면"의 모델을 되살려(θ_cur + V_k_prev) 거기서부터의 총 변화를 모집단의 같은 크기 제거와 비교.
```
저장 비용: 클라이언트당 벡터 하나. 창 W 가 길면 느린 공격자까지 잡고, 정상 클라이언트의 정당한 큰 삭제가 쌓여 오탐이 는다. W 는 "공격자의 인내심 ↔ 방어자의 기억력"의 손잡이.

## 6. 비용
한 단계 = 모집단 m 개 만들기(벡터 빼기, 학습 없음) + (m+1) 모델에 n 장 통과 + (표시 시) 수정 50 걸음.
단계 수 S = ⌈1 / δ⌉, δ 는 부품 A 가 정함. 측정값(MNIST LeNet, n=500, 한 요청 전체):
K=8 전원 15 s / 표본5 7 s, K=100 전원 18 min / 표본5 47 s. 단계가 S 개면 S 배. ResNet CIFAR K=50 표본5 48 min (한 단계 기준 아님, 전체 지도 기준).

## 7. 트레이드오프 (손잡이별)
| 손잡이 | 작게 | 크게 |
|---|---|---|
| c (건강 상한) | 안전, 단계 多, 비용 ↑, 단계마다 수정하면 요청자 기여가 조금씩 되돌아와 망각 ↓ | 싸고 깨끗이 잊음, 무너짐·수정 실패 위험 ↑ |
| τ (문턱) | 민감, 오탐 ↑ (non-IID 에서 특히) | 둔감, 쪼개기에 약함 |
| m (표본) | 쌈, z 의 분산 ↑ | 정확, 비용 ∝ m |
| W (창) | 오탐 ↓, 느린 공격자 놓침 | 느린 공격자 잡음, 오탐 ↑, 저장 ↑ |

## 8. 범위 밖 (명시)
- 수정은 백도어를 **지우지** 않고 **다시 재운다**. 공격자 클라이언트들의 오염 기여는 그대로다. 이 기법은 요청 처리의 안전 장치이지 백도어 제거기가 아니다.
- 탐침 X_p 에 트리거가 없으면 트리거가 "안 보이는" 공격(BadFU 패치)은 확인이 약하다. 부품 B 의 입력을 넓히는 문제(패치 열거 등)는 별도.
- 정상 요청자의 망각 수치(MIA)는 MNIST IID 에서 측정 불가(AUROC≈0.5). P1 은 "기본 FU 와 동일"로만 말한다.

## 9. 이미 있는 것과의 관계
- 단계별 언러닝 스윕은 **공격 평가**에 쓰였다: Zhang et al. 2023 은 위장 샘플을 20 % 씩 지우며 ASR 을 표로 냈다(Table 7/8). 방어 알고리즘의 제어 흐름으로 쓴 것은 아니다.
- "같은 양의 임의 샘플 제거"는 **대조군**으로 쓰였다: 2026 clean-label 공격 논문의 Appendix E (임의 제거 +3 vs 위장 제거 +75). 우리의 부품 B 는 이 대조군을 매 요청마다 자동으로 세우는 것이다.
- MASA(WACV'25)는 학습 중 각 로컬 모델에 깨끗한 데이터로 언러닝을 걸어 손실을 모집단 중앙값과 비교한다. 우리는 요청 시점에, 라벨·학습 없이, 요청된 제거 자체를 수행해 비교한다.
