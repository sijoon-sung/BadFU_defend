# 삭제 요청을 이행하면서 백도어를 정화하는 연구 미팅 자료

2026년 10월 8일 · 교수님 연구 미팅용

**연구 목표는 탐지용 언러닝을 추가 실행하지 않고, 삭제 요청자와 잔존 클라이언트의 업데이트 상쇄 관계를 찾아 실제 연합 언러닝 과정에서 백도어 성분을 줄이는 것이다.** 탐지가 틀려도 요청된 삭제 대상은 바꾸지 않는다. 정상 성능, 삭제 효과, 공격 억제, 추가 비용을 함께 평가한다.

현재 단계는 **제한된 예비 실험에서 가능성을 관측하고, 실제 FU 안에서 검증할 GPU 코드를 준비한 단계**다. 실제 GPU 성능과 낮은 오탐률은 아직 검증되지 않았다. 구현 설명의 기준은 커밋 63559b7이다. 이번 미팅에서는 적용 범위, 새로움의 기준, 다음 실험의 성공 조건을 합의하고자 한다.

## 교수님께 설명할 발표문

“제가 다루려는 문제는 언러닝을 하면 오히려 숨겨진 백도어가 활성화되는 경우입니다. 백도어를 심는 기여와 이를 감추는 위장 기여가 학습 중 상쇄되다가, 위장 쪽의 삭제 요청이 이행되면 잔존 백도어가 드러날 수 있습니다.

저는 탐지를 위해 별도의 언러닝을 실행하지 않고, 서버가 가진 과거 업데이트에서 삭제 요청자와 다른 참여자의 반복적인 상쇄를 찾으려고 합니다. 요청자가 이미 알려져 있으므로 모든 클라이언트 쌍을 비교할 필요를 줄일 수 있습니다. 이후 실제 언러닝이 계산하는 잔존 업데이트 중 의심 방향의 성분만 감쇠합니다.

탐지를 완벽하게 맞히는 것만을 목표로 삼기보다, 탐지 오류가 있을 때도 정상 성능의 손실을 제한하면서 공격 위험을 얼마나 줄일 수 있는지 보려고 합니다. 위장 데이터를 남겨 백도어를 다시 감추는 방식은 사용하지 않습니다.

기존 소규모 실험에서는 상쇄 신호와 근사 정화의 가능성을 보았지만 실제 FU에서는 아직 충분한 증거가 없습니다. 지금은 BadFU 공식 코드의 분리형 설정을 대상으로, 정화 없음·정답 후보 방향·탐지 방향·무작위 방향·재학습을 비교하는 GPU 실험 코드를 준비했습니다.

다음 단계는 실제 FU에서 유효한 정화 방향이 존재하는지 먼저 확인하는 것입니다. 그다음 정상 오탐과 망각 효과, 전체 비용을 평가하고, 정화 이후에도 학습이 이어질 때 백도어가 감소하거나 다시 살아나는지를 검증하겠습니다.”

## 공격 설정과 첫 논문의 범위

| 대상 | 공격 구조와 삭제 단위 | 우리 방법과의 관계 |
|---|---|---|
| FUBA | 백도어 주입 역할과 억제 역할을 분리하고 억제 역할이 언러닝 요청 | 요청자와 잔존 공격자의 관계를 보는 직접적인 동기 |
| BadFU 논문 arXiv v1 | 악성 클라이언트 내부에 백도어와 위장 데이터를 함께 두고 위장 샘플 삭제 | 클라이언트 사이에서 상쇄 쌍이 보인다는 보장이 없음 |
| BadFU 공식 예제의 ul 경로 | client 0에 정상+백도어, client 5에 정상+위장을 두고 client 5 제외 | 현재 GPU 패키지의 주 평가 범위 |

근거: [FUBA 출판사 초록](https://ieeexplore.ieee.org/document/11231135/), [BadFU IV절과 V절](https://arxiv.org/html/2508.15541v1), [BadFU 공식 데이터 배치](https://github.com/BingguangLu/BadFU/blob/0a2117feab58faf5b7e2a1e5e1759112087d6049/badfu.py#L159-L168), [공식 FU 경로](https://github.com/BingguangLu/BadFU/blob/0a2117feab58faf5b7e2a1e5e1759112087d6049/badfu.py#L505-L561).

현재 삭제 단위는 **client 5 전체의 참여 기여**다. 공식 예제에서는 client 0의 정상 데이터를 client 5에도 복제하므로, 양쪽에 공유된 정상 샘플 자체를 전역에서 삭제하는 실험과는 다르다. 이 중복 구조를 맞춘 정상 대조군이 필요하며, 후속으로 중복 없는 분할에서도 검증해야 한다.

첫 논문은 서버가 개별 업데이트를 볼 수 있는 분리형 공격으로 범위를 정하는 것이 현실적이다. 단일 클라이언트 내부 상쇄와 secure aggregation은 별도의 정보 접근 문제가 있다. 같은 관측 기록에서 서로 다른 내부 구성을 구별할 수 없는 경우에는 기록만으로 원인을 특정할 수 없다. 두 설정을 모두 해결했다는 주장은 별도 검증이 필요하다.

## 알고리즘의 흐름

~~~mermaid
flowchart TD
    H["학습 중 저장한 업데이트 기록"] --> D["요청자와 잔존자의 상쇄 검사"]
    Q["실제 삭제 요청 q"] --> D
    D --> S["무경보 또는 후보와 의심 부분공간 B"]
    Q --> U["q를 제외하는 실제 FU"]
    U --> C["잔존 업데이트의 의심 성분 감쇠"]
    S --> C
    C --> G["노름 상한과 정상 손실 검사"]
    G --> O["최종 모델과 삭제 및 보안 평가"]
~~~

1. **기록을 맞춘다.** 같은 글로벌 모델에서 시작한 로컬 업데이트를 사용하고 실제 집계 가중치를 반영한다.
2. **요청자만 기준으로 검사한다.** 요청자 q와 공동 참여한 잔존자들의 클래스별 반대 방향, 상쇄량, 크기, 반복성을 계산한다.
3. **무경보를 허용한다.** 정상 학습 궤적에서 보정한 요청 임계값을 넘지 않으면 후보를 강제로 만들지 않는다. 관측 부족도 별도 상태로 기록한다.
4. **의심 부분공간을 만든다.** 선택된 잔존자·클래스의 헤드 업데이트에서 비중심 SVD로 기저 B를 만든다. 각 클래스 행을 정규화하고 점수의 제곱근으로 가중한다. 기본 후보 상한은 8명·클라이언트당 2개 클래스이며, 에너지 90% 기준과 최대 랭크 8을 적용한다. 첫 버전의 B는 실제 FU가 진행되는 동안 고정한다.
5. **실제 FU에 정화를 결합한다.** FU가 계산한 잔존자의 보정 기여 중 B 성분을 탐지 점수에 따라 감쇠한다. 탐지용으로 FU를 다시 실행하지 않는다.
6. **정상 피해를 제한한다.** 제거 노름 상한과 깨끗한 검증 손실을 검사한다. 해당 단계의 정화가 거절돼도 실제 FU는 진행한다.

깨끗한 검증 손실을 비교하는 추가 추론 비용은 존재한다. 이것은 가상의 FU를 수행하는 절차가 아니지만, 전체 방어 비용에 반드시 포함한다.

## 현재 구현과 일치하는 핵심 수식

클래스 수를 C, 한 클래스의 헤드 가중치와 bias를 합친 차원을 d라고 둔다. 위장 데이터는 혼동을 피하려고 $D_{\rm cam}$으로 표기한다. 요청자 q는 입력으로 주어지며 탐지 결과로 바꾸지 않는다.

라운드 t, 클라이언트 i, 클래스 c의 집계 기여는 다음과 같다.

$$
x_{i,t,c}=p_{i,t}\operatorname{head}_c(\theta_{i,t}-\theta_t).
$$

공동 관측 라운드 집합을 $\mathcal T_{qi}$, 참여 클라이언트의 클래스별 노름 중앙값을 $m_{t,c}$라 하면, 단일 라운드의 점수는 다음 세 항의 곱이다.

$$
a_{qi,t,c}=[-\cos(x_{q,t,c},x_{i,t,c})]_+,
$$
$$
b_{qi,t,c}=\left[1-\frac{\|x_{q,t,c}+x_{i,t,c}\|}
 {\max(\|x_{q,t,c}\|+\|x_{i,t,c}\|,\varepsilon)}\right]_{[0,1]},
$$
$$
g_{qi,t,c}=\min\left(4,\frac{\min(\|x_{q,t,c}\|,\|x_{i,t,c}\|)}
 {\max(m_{t,c},\varepsilon)}\right),\qquad
r_{qi,t,c}=a_{qi,t,c}b_{qi,t,c}g_{qi,t,c}.
$$

구현은 코사인 분모의 노름 곱에도 epsilon 하한을 적용한다. 미참여·영벡터의 점수는 0이다. 최종 점수는 평균과 반복성의 곱이다.

$$
s_{qi,c}=
\left(\frac{\sum_{t\in\mathcal T_{qi}}r_{qi,t,c}}{|\mathcal T_{qi}|}\right)
\left(\frac{\sum_{t\in\mathcal T_{qi}}\mathbf1[r_{qi,t,c}\ge0.1]}
 {|\mathcal T_{qi}|}\right).
$$

공동 관측이 3회 미만인 후보는 제외한다. 요청 점수는 $R_q=\max_{i\ne q,c}s_{qi,c}$다. 현재 정책은 정상 기록의 요청 최대 점수 99% 분위수와 쌍 점수 95% 분위수를 사용한다. **이 분위수 설정 자체는 운영 FPR 1%를 보장하지 않는다.**

잔존자 i의 제어 가중치는 다음과 같다.

$$
\gamma_i=\operatorname{clip}_{[0,1]}
 \frac{\max_c s_{qi,c}-\tau_{\rm pair}}
 {\tau_{\rm high}-\tau_{\rm pair}}.
$$

선택된 클라이언트만 양의 가중치를 갖는다. $\gamma_i$는 악성 확률이 아니다. 현재 정상 궤적 두 개로는 정확한 확률 보정을 주장할 수 없다.

실제 FU의 한 단계에서 잔존자 i의 **층별 보정과 집계 가중치를 반영한 헤드 기여**를 $d_{i,r}$, 그 합을 포함한 기본 FU 모델을 $\theta^{\rm base}_{r+1}$라 한다.

$$
v_r=BB^\top\sum_{i\ne q}\gamma_i d_{i,r},\quad
\lambda_r=\min\left(\lambda_{\max},
 \frac{\min(b_{\rm abs},b_{\rm rel}\|\Delta^{\rm FU}_r\|)}
 {\max(\|v_r\|,\varepsilon)}\right),
$$
$$
\theta_{r+1}=\theta^{\rm base}_{r+1}-E_h(\lambda_r v_r).
$$

$E_h$는 헤드의 보정 벡터를 전체 모델의 해당 위치에만 넣는다. 기본값은 $\lambda_{\max}=0.5$, $b_{\rm rel}=0.25$, $b_{\rm abs}=1.0$이다. 검증 손실이 같은 단계의 기본 FU보다 0.01을 초과해 증가하면 그 단계는 기본 FU 모델을 채택한다.

정화 강도 0에서는 기본 FU와 모델 해시가 같아야 한다. 노름 제한은 개입량의 제한일 뿐 ASR·정확도·망각을 보장하는 정리는 아니다. 코드: [탐지와 투영](../../experiments/request_purify/core.py), [실제 FU 통합](../../experiments/request_purify/engine.py). 확장 설계: [알고리즘 명세](ALGORITHM_SPEC_2026-10-08.md).

| 망각 및 지속성 | 평가 보강 필요 | 삭제 데이터 손실만으로 망각이나 후속 안전을 주장하지 않음 |

과거 수치의 조건과 산출물은 [연구 현황](RESEARCH_STATUS_2026-10-07.md), 재현상의 문제는 [공격 구현 감사](ATTACK_FIDELITY_AND_DIRECTION_2026-10-08.md)에 있다. 새 GPU 결과를 이 과거 표에 섞지 않는다.

## 논문으로서의 기여와 선행연구와의 관계

연구의 가치는 “새 탐지 점수 하나”보다 **요청 이행과 백도어 위험의 충돌을, 관측 가능한 업데이트 관계와 제한된 정화로 다루는가**에 달려 있다. 다음 세 가지가 기여 후보이며 아직 입증된 결론은 아니다.

| 기여 후보 | 필요한 증거 |
|---|---|
| 요청자 중심 상쇄 신호가 삭제 후 위험을 설명 | 정상 non-IID와 구분, 전체 쌍 대비 누락률, 점수와 FU 후 위험의 관계 |
| 불완전한 탐지에서도 선택적 정화가 유용 | 실제 FP/FN·방향 오차에 따른 정상 성능·ASR·망각의 변화 |
| 탐지용 언러닝 0회로 낮은 추가 비용 달성 | 같은 성능·정보 접근 조건에서 기록·I/O·SVD·검증까지 포함한 비용 |

MASA는 로컬 모델에 개별 언러닝을 수행해 판별하므로 탐지 연산의 차이를 설명할 비교 대상이다. 반면 FoolsGold·FLDetector·FLAME도 탐지용 언러닝을 필요로 하지 않는다. 따라서 “시뮬레이션이 없어서 최초” 또는 “기존 방어는 모두 시뮬레이션한다”는 주장은 성립하지 않는다. [MASA 원문](https://arxiv.org/html/2411.01040v1), [관련 논문 비교표](LITERATURE_REVIEW_2026-10-08.md).

**새로 확인한 근접 연구:** INFOCOM 2026의 *Malicious Forgetting*은 저자 초록에서 FU 공격과 방향 부분공간 변화 기반 탐지를 제안한다. 이는 방향·부분공간 탐지만으로 차별점을 주장하기 어렵게 한다. 본문 접근이 제한되어 탐지 시점·정보 요구·삭제 이행·정화 방식의 세부 중복은 아직 확정하지 않았다. 다음 논문 검토의 최우선 대상이다. [저자 논문 페이지](https://wenwei-zhao.github.io/publication/conference-paper/3/)

| 1 공격 활성화 | 같은 seed에서 FL 종료 모델과 정화 없는 FU의 ACC·ASR 비교 | 잠복·활성화가 충분하지 않으면 공격 재현 조건부터 확인 |
| 2 경로 일치 | none과 zero의 모델 해시 비교 | 다르면 정화 성능 해석 전에 구현 수정 |
| 3 정화 가능성 | oracle 후보 방향과 none·동일 조건 random 비교 | 후보 방향이 유효한 개선을 만드는지 확인 |
| 4 탐지 결합 | detected와 oracle 후보, 정상 요청 비교 | 효과 차이를 후보 선택·방향·강도·guard 거절로 분해 |
| 5 삭제 진단 | 요청자 제외 retrain 및 추가 망각 평가 | 정화가 삭제 효과를 훼손하는지 평가 |
| 6 지속성 | 정상 학습·지속 공격·공격 재개별 후속 곡선 | 최대 ASR·곡선 면적·정상 성능·재정화 필요성 평가 |

현재 oracle은 **정답 공격자와 타깃의 헤드 기록으로 만든 후보 공간**이다. 순수 백도어 성분의 완벽한 정답은 아니며, 실패하면 “정화 자체가 불가능하다”는 결론을 내릴 수 없다. 헤드 표현력, 기저 정렬, 정화 강도와 guard 거절부터 확인한다.

기본 실험은 CIFAR-10·ResNet18·FL 40라운드·로컬 5 epochs·FU 1 epoch·평가 seed 3개·후속 FL 10라운드다. FU는 통제된 FedEraser 계열 구현이며 원본 그대로의 재현은 아니다. 기본 후속 10라운드는 초기 궤적을 보는 범위이고 장기 지속성 증거는 더 긴 실험이 필요하다. [실행 조건과 차이](../../experiments/request_purify/README.md)

## 다음 단계에서 보강할 실험

우선 새로운 탐지 기능을 늘리기보다 위의 여섯 비교를 완료한다. 그 뒤 정상 궤적 수를 늘리고 개발·보정·최종 평가 seed를 분리한다. 같은 궤적의 여러 요청을 독립 반복처럼 세지 않는다. 현재 3개 평가 seed는 초기 판단용으로 보고, 최종 통계는 독립 반복을 확대한다.

| 축 | 추가할 비교 | 목적 |
|---|---|---|
| 탐지 | 반대 방향만 / 상쇄량 추가 / 크기 추가 / 반복성 추가 | 각 항의 실질적 기여와 non-IID 오탐 확인 |
| 탐지 범위 | 전체 쌍 / 요청자 중심 / 후속 저차원 요약 | 검사 축소의 비용과 후보 누락률 확인 |
| 정화 | 강도·랭크·적용 층·정상 guard / 고정 강도와 점수 가중 | 과도한 개입과 방향 추정 오류의 영향 확인 |
| 비교군 | FoolsGold·FLDetector·FLAME, MASA | 추가 학습 없는 방어와 있는 방어 모두 비교 |
| 망각 | 깨끗한·삭제 관련 입력의 예측, MIA 등 복수 진단 | 백도어 억제를 망각과 혼동하지 않기 |
| 강건성 | FUBA 통합, 여러 공격자, 부분 참여, 중복 없는 데이터 | 분리형 기본 조건 밖으로 확장 |
| 후속 학습 | 장기 FL, 지속 공격, 공격 재개, Neurotoxin 계열 조건 | 낮은 직후 ASR이 지속되는지 평가 |

ASR 10~15%는 후보 연구 목표다. 운영 중 원 트리거를 알고 ASR을 읽어 그 값까지 정화할 수 있다고 가정하지 않는다. 깨끗한 모델의 동일 트리거 ASR과 비교하고, 목표를 달성한 뒤에도 재발 여부를 측정한다. 정상 학습이 백도어를 자동 제거한다는 전제는 Neurotoxin 같은 지속성 연구와 맞지 않는다. [Neurotoxin](https://proceedings.mlr.press/v162/zhang22w.html)

요청 단위 점수 계산은 N명·기록 창 W·클래스 C·행 차원 d에서 $O(WNCd)$이며, 전체 쌍의 $O(WN^2Cd)$와 구분한다. 전체 파이프라인에는 SVD·정렬·기록·FU·검증이 추가된다. 현재 SVD는 전체 SVD 후 랭크를 선택하고, 기록도 최근 W개만 저장하도록 제한돼 있지 않다. 전체 시간·메모리까지 선형 또는 저비용이라고 말하려면 별도 측정이 필요하다.

## 교수님께 받을 결정과 예상 질문

미팅에서 결정할 사항은 **첫 논문의 범위를 분리형으로 둘지**, **깨끗한 검증 데이터 접근을 허용할지**, **정상 성능과 삭제 효과의 허용 손실을 얼마로 둘지**다. 가까운 선행연구와의 차별점 확인을 성능 실험과 함께 진행한다.

| 예상 질문 | 답변의 핵심 |
|---|---|
| 그냥 코사인 유사도 탐지 아닌가 | 요청에 조건화된 반복 상쇄와 실제 FU 내부 정화의 결합을 검증한다. 조합만으로 기여가 충분하다고 단정하지 않는다. |
| 왜 여러 번 FU를 실행하는가 | 오프라인에서 비교 방법을 각각 실행하는 것이다. 배포할 detected 경로는 탐지용 FU 0회, 실제 요청 이행 경로 1회다. |
| 언러닝을 했으면 삭제가 보장되는가 | 근사 FU와 정화의 결합은 별도 망각 검증이 필요하다. 낮은 ASR은 삭제 증거가 아니다. |
| 위장 데이터를 조금 남기면 안 되는가 | 위장 데이터가 삭제 대상이면 남기는 정책은 연구의 삭제 이행 제약과 충돌한다. 잔존 모델에 개입한다. |
| 한 클라이언트 안에서 상쇄하면 어떻게 하나 | 현재 쌍 탐지의 적용 범위 밖이다. 샘플 단위 FU와 추가 관측을 갖춘 별도 확장이 필요하다. |
| 정상 손실 guard가 정화를 거절하면 안전한가 | 정상 피해를 제한한 것이며 보안 문제는 남는다. 미해결 비율을 결과로 보고한다. |
| 재학습 모델보다 ASR이 낮으면 잘못된 언러닝인가 | 요청자만 뺀 재학습에도 잔존 공격 데이터가 있다. 보안 정화와 요청 삭제의 기준을 분리해 평가한다. |

요청자의 과거 업데이트로 만든 기저와 탐지 상태도 삭제 대상의 정보를 담을 수 있다. 연구용 감사 기록의 보존과 실제 삭제 서비스의 상태 정리는 구분하며, 파생 상태까지 포함한 망각 평가는 후속 과제다.

다음 보고에서는 **공격 활성화, 실제 FU 정화, 정상 요청 피해, 삭제 진단, 전체 비용**의 다섯 결과를 제시한다. 각각 성공 기준을 사전에 정하고, 개선이 없는 경우에도 실패 위치를 분해할 수 있는 실험을 우선한다.
