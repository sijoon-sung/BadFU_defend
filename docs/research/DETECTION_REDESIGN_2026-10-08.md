# 방어 논문의 전개 방식과 탐지 방향 재설계

2026년 10월 8일

**권장 방향은 전체 업데이트의 반대 방향 쌍을 필수 조건에서 제외하고, 삭제 요청에 연결된 기능 변화와 실제 FU 과정의 관측으로 탐지 근거를 찾는 것이다.** BadFU·FUBA를 핵심 대상으로 유지한다. 새 점수들을 먼저 결합하지 않고, 정상 요청과 공격 요청을 구별하는 관측이 실제로 존재하는지부터 검증한다. 아래는 연구 가설이며 구현된 방어 또는 입증된 노벨티가 아니다.

## 현재 실패가 바꾸는 가정

[GPU seed 42 점검](../results/GPU_SEED42_ASR_AUDIT_2026-10-08.md)에서 실제 공격자 0과 요청자 5의 최종 클래스별 점수는 모두 0이었다. 공격 요청의 최대 점수는 정상 대조군보다 낮았고, oracle의 rank 1 헤드 정화도 39회 적용 후 ASR 100%였다. 탐지와 정화를 각각 재검토해야 한다. 삭제 전 ASR도 69.77%여서 공격 은폐 조건을 확인하는 작업이 선행한다.

공격 관련 성분의 상쇄가 전체 업데이트의 역방향을 뜻하지는 않는다. 다음은 실제 결과의 측정값이 아닌 설명용 반례다.

```text
공통 정상 기여 c = (10, 0)
백도어 관련 기여 b = (0, 1)
공격자 업데이트 = c + b = (10, 1)
위장자 업데이트 = c - b = (10, -1)
내적 = ||c||² - ||b||² = 99
코사인 = 99 / 101 ≈ +0.9802
```

공격 성분은 상쇄되지만 전체 벡터는 거의 같은 방향이다. 현재 실행에서 두 클라이언트가 정상 이미지 9,478개를 공유한다는 사실은 이 가설을 조사할 이유다. 그러나 저장된 raw 업데이트 없이 이 반례가 실제 실패 원인이라고 확정할 수는 없다. 두 클라이언트의 평균을 빼면 항상 반대가 되는 인위적인 전처리는 쓰지 않는다.

## 다른 방어 논문은 어떤 순서로 방법을 도출했는가

각 행의 마지막 열은 원 논문의 주장이 아니라 우리 연구에 대한 해석이다. 원문에서 소개·동기·방법·해당 실험 절을 대조했다.

| 논문 | 출발한 문제 | 관측에서 알고리즘으로 연결한 방식 | 우리에게 필요한 검증 |
|---|---|---|---|
| [MASA, WACV 2025](https://arxiv.org/html/2411.01040v1), §3–4 | 정상·백도어 목적이 섞여 단순 파라미터 통계가 유사함 | 정상 보조 데이터의 언러닝 반응에서 차이를 관측하고, 모델 fusion으로 non-IID 혼동을 줄인 뒤 loss 이상을 탐지 | 관측 대상을 바꿀 이유를 먼저 제시. 개별 모델 언러닝은 우리의 추가 탐지 FU 0회 조건에 맞지 않으므로 그대로 채택하지 않음 |
| [AlignIns, CVPR 2025](https://arxiv.org/html/2503.07978v1), §4–6, 부록 §10 | 크기 통계와 전체 방향에서 작은 악성 신호가 묻힘 | 업데이트와 글로벌 모델의 방향 정렬, 큰 절댓값 좌표의 부호 정렬을 결합하고 구성요소·clipping을 분리 평가 | 좌표 선택이 실제 식별력을 만드는지 검증. 기존 부호·마스크를 붙이는 것 자체는 새 기여가 아님 |
| [FLDetector, KDD 2022](https://zaixizhang.github.io/ZaixiZhang_files/FLDetector.pdf), §4–5 | 한 라운드 집계만으로 많은 악성 참여자에 대응하기 어려움 | 과거에서 예측한 업데이트와 실제 업데이트의 반복 불일치를 점수화하고, 남은 공격은 robust aggregation과 함께 평가 | 시계열 신호의 원인을 설명하고 방어를 아는 회피도 시험. 일관되게 오염된 이력은 중요한 반례 |
| [FLARE, ASIA CCS 2022](https://ning-wang1.github.io/files/flare.pdf), §4–7 | 파라미터가 가까워도 기능이 다를 수 있음 | 보조 입력에 대한 마지막 은닉층 표현 차이를 관측하고, MMD·이웃 관계로 신뢰 가중치를 계산 | 기능 공간을 측정하는 것 자체는 선행연구. 요청 조건이 제공하는 추가 정보와 probe 한계를 입증해야 함 |
| [DeepSight, NDSS 2022](https://arxiv.org/html/2201.00763v1), §II-C, IV–VI | 단순 이상치 제거가 정상적인 데이터 이질성까지 배제함 | 출력·헤드 에너지·군집으로 강한 오염을 분리하고 놓친 기여는 clipping으로 제한한다는 공격자 절충 논리 | 탐지와 잔존 위험 제어의 연결을 검증. FU 뒤 활성화에는 학습 중 영향이 작다는 사실만으로 충분하지 않음 |
| [BackdoorIndicator, USENIX Security 2024](https://www.usenix.org/system/files/usenixsecurity24-li-songze.pdf), §3–4 | 악성/정상 업데이트 통계가 겹치는 경우 | OOD indicator 과제를 심고 이후 백도어 학습이 이를 유지하는 반응을 이용. BN 통계 교란도 통제 | 수동 관측이 부족하면 관측 수단을 새로 설계할 수 있음. 다만 추가 학습·프로토콜 변경이 필요하며 FPR도 검증 대상 |
| [UnlearnGuard, WWW Companion 2025](https://arxiv.org/html/2501.17396v1), §4–5 | 실제 FU 과정의 악성 제출이 복구를 방해함 | FL 이력 기반 예측을 검증하고 필요하면 실제 업데이트를 요청하며 방향·크기를 보정 | 실제 FU를 관측하는 접근 자체도 기존 연구. 과거에도 존재했던 잠복 공격을 새롭게 식별해야 함 |

이 논문들에서 배울 전개는 **기존 관측의 실패 → 다른 관측에서의 차이 → 정상 변동이라는 혼동 요인 통제 → 알고리즘 → 구성요소와 적응적 공격 검증**이다. 논문마다 이론과 실험의 범위는 다르며, 모든 공격에 대한 보장을 제시한 것은 아니다.

특히 BackdoorIndicator는 흥미로운 현상을 찾은 뒤 BN 통계가 그 해석을 가릴 수 있음을 확인하고 측정 절차를 통제한다. 우리도 표현 변화가 보인다는 사실만으로 공격 신호라고 결론 내리지 않아야 한다. 논문 자체도 동기 실험의 유지 효과가 임의의 백도어 조합에 모두 성립하는 것은 아니라고 명시한다. [원문 §3.2](https://www.usenix.org/system/files/usenixsecurity24-li-songze.pdf)

## 우리가 먼저 검증할 관측

주 연구 질문은 다음과 같다.

> 삭제 전에는 정상 기여에 가려져 있던 위험 기능을, 요청 정보와 실제 FU에서 얻는 증거로 구별할 수 있는가? 그 판단을 위해 별도 FU 경로를 실행하지 않을 수 있는가?

‘기능’은 추상적인 이름으로 남기지 않는다. 고정된 입력 집합에서 얻는 클래스별 logit/margin, 선택한 중간층의 표현을 후보로 둔다. 탐지기에는 공격 타깃·트리거·테스트 ASR을 주지 않는다. 후보 셋은 공격 테스트 결과를 보고 선택하지 않는다.

### 후보 1 독립적인 정상 기준을 사용한 잔여 업데이트

정상 기여가 커서 가려지는지 확인하기 위한 저비용 비교군이다. 정상 보조 데이터나 별도 정상 이력에서 추정한 기준을 사용한다. 같은 두 클라이언트만으로 기준을 만들어 자동으로 역방향을 유도하지 않는다. 정상 non-IID 방향까지 제거하지 않는지 검증한다. 이 후보는 원인 분석과 기준선 역할이며, 그 자체를 노벨티로 삼지 않는다.

### 후보 2 이미 받은 모델의 기능 변화

동일한 probe x에 대해 이미 제출된 로컬 모델 theta_i,t와 그 라운드 시작 모델 theta_t를 평가한다. 예를 들어 클래스 c의 margin을 m_c라 하면 다음을 기록한다.

```text
phi_i,t(x,c) = m_c(theta_i,t, x) - m_c(theta_t, x)
```

모델 재학습이나 가상 삭제 모델 생성 없이 forward로 측정한다. 현재 클래스 행 하나 대신 입력·클래스·층별로 어떤 기능을 강화하거나 억제했는지 비교한다. 요청자와 잔존 기여가 같은 기능에 반대 효과를 보이는지는 후보 증거지만 필수 조건으로 강제하지 않는다.

이 관측도 정상 두 클라이언트의 전문 분야 차이를 잡을 수 있다. 요청과 무관한 기능 이상 점수, 강한 non-IID 정상 요청, 같은 분포를 가진 정상 클라이언트 쌍을 반드시 비교한다. logit/표현 검사 자체는 FLARE·DeepSight와 겹치므로 요청 정보의 추가 효과가 핵심이다.

### 후보 3 실제로 이행하는 FU의 기능 변화

실제 FU의 각 단계 전후에서 같은 probe의 반응과 잔존 클라이언트의 실제 기여를 기록한다. 요청자와의 과거 쌍을 발견하지 못했더라도 FU 중 관측을 수행한다. 탐지기 검사용 삭제를 여러 번 실행하지 않으며, 실제 FU의 로컬 학습을 재사용한다.

정상 요청의 변화와 비교할 때는 삭제 규모·클래스 구성·FU 단계·정상 성능 변화를 맞춰야 한다. 초기 모델부터 재생하는 FU에서는 초기의 큰 학습 변화가 정상이라는 점도 중요하다. 동일한 정상 이력으로 예측한 변화와의 오차는 보조 후보지만, 그 오차만으로는 꾸준히 오염된 모델을 놓칠 수 있다.

이 후보의 출력은 사전 위험 예측이 아니라 **FU 중 탐지**다. ASR이 이미 상승한 후에만 경보를 내면 탐지 지연을 보고한다. 최종 모델을 배포하기 전에 실제 FU 안에서 정화가 가능한지도 함께 측정한다. 모든 후보를 먼저 합치는 대신 각각의 추가 정보를 확인한 뒤 결합 여부를 정한다.

## 관측의 한계와 대안

깨끗한 입력에서만 동일하게 반응하는 잠복 백도어는 clean probe로 구별되지 않을 수 있다. 다른 입력 집합의 관측이 필요한지 시험할 수 있지만, 임의의 OOD 입력이나 augmentation이 미지의 트리거를 반드시 드러낸다는 보장은 없다. probe 수를 늘리면 비용과 오탐도 함께 측정한다.

입력 집합은 정상 보조 데이터, 미리 정한 변환, 별도 공개/OOD 자료로 구성할 수 있다. 공격 테스트 이미지로 probe를 선정하거나 실패한 트리거를 추가해 성능을 보정하면 정보 누출이다. 정상 학습·정상 삭제에서도 동일한 관측을 수집해야 한다. BN 원래 상태와 통제 상태의 비교는 분석용 ablation으로 구분하고 원본 평가를 대체하지 않는다.

수동 관측이 분리되지 않으면 BackdoorIndicator 같은 능동 관측을 별도 연구 범위로 검토한다. indicator 학습은 FU 시뮬레이션은 아니지만 추가 학습·모델 변경·저장 비용이 생긴다. 현재 제안에 조용히 포함하거나 비용 0이라고 쓰지 않는다.

한 클라이언트 내부에 백도어·위장 데이터가 함께 있고 서버에 합쳐진 업데이트만 보인다면 사전 단계의 쌍 신호는 없을 수 있다. 실제 **샘플 삭제**를 수행하는 FU 중 관측은 후보이지만, 이를 실행하지 않은 클라이언트 전체 삭제 실험으로 대신할 수 없다. 관측 정보가 동일한 정상·공격 사례를 같은 탐지기가 구별할 수는 없다는 한계를 인정해야 한다.

## 최소 실험과 채택 기준

| 검증 | 비교 | 채택 또는 중단 기준 |
|---|---|---|
| 공격 재현 | 삭제 전 은폐, 삭제 후 활성화, 위장 원본·라벨 확인 | 잠복 조건이 무너지면 방어 성공/실패의 일반화 전에 재현 원인부터 확인 |
| 관측 선택 | raw geometry, 독립 정상 기준 residual, 기능 반응, 실제 FU 변화 | 고정 정상 FPR에서 분리력이 없는 후보는 결합으로 숨기지 않음 |
| 요청의 필요성 | 같은 checkpoint에서 위장·백도어·정상 삭제를 각각 평가; 탐지 입력 q만 섞는 별도 ablation | 요청 정보를 무시해도 같으면 요청 조건부 노벨티를 축소 |
| 정보 상한 | 평가 전용 알려진 트리거에서 기능 신호가 있는지, 실제 probe에서도 보이는지 분리 | 전자만 성공하면 관측 범위 문제. 정답 입력을 운영 탐지기로 가져오지 않음 |
| 정화 연결 | 알려진 공격자, 실제 탐지, 무작위 방향을 같은 정상 손상 예산에서 비교 | 알려진 공격자 조건도 실패하면 탐지 점수 튜닝보다 정화 위치·공간 검토 |
| 일반화 | FUBA, BadFU 배치 변형, 사전 지정 FedMUA/BadUnlearn | 같은 설정의 이전 효과와 실패를 각각 보고 |
| 회피와 비용 | 탐지식을 아는 공격, 정상 minority 손상, 기록·forward·backward·통신·보정 비용 | 원본 공격 ASR만 낮고 쉬운 회피에 무너지면 강건성 주장 제한 |

첫 실험의 목표는 최종 ASR 표를 더 만드는 것이 아니라, 논문 첫 동기 그림이 될 **정상·공격 관측 분포와 실패 반례**를 확보하는 것이다. 정상 FPR 기준은 별도 정상 보정에서 정하고, 클라이언트·클래스·라운드 최대값을 탐색하는 전체 요청의 오탐률을 측정한다. 반복 관측 라운드나 같은 seed의 여러 요청을 독립 표본으로 세지 않는다.

기존 방어는 학습 중 예방과 요청 시점 적용을 구분해 비교한다. 동일 FU의 비교와 원 논문의 전체 pipeline 비교도 구분한다. MASA는 계산량 비교에서 유용하지만 탐지용 추가 언러닝이 허용된 더 비싼 기준선이다. FLDetector/UnlearnGuard류의 이력 예측을 추가하는 것만으로 새 방법이라고 주장하지 않는다.

## 현재 코드에서 가능한 일과 추가로 필요한 기록

현재 history에는 라운드별 헤드 업데이트와 잔존 집계의 층별 노름, 초기·최종 글로벌 state가 있다. 과거 모든 로컬 모델의 중간층 표현을 재구성할 수 있는 기록은 없다. **기존 head history만으로 새 기능 탐지기를 재평가했다고 할 수 없다.**

우선 GPU 장비에 남은 history를 [저장 결과 진단 도구](../../experiments/request_purify/audit.py)로 분석한다. 다음 관측 실행에서는 `train_history`가 이미 계산한 로컬 모델을 폐기하기 전에 고정 probe의 특징을 저장하고, 실제 FU에서도 같은 특징을 저장하도록 계측한다. 전체 로컬 모델을 영구 저장하지 않아도 되지만, 추가 forward 시간과 특징 저장량은 비용이다. 기존 결과의 누락된 관측을 채우기 위한 재학습을 운영 탐지 비용과 혼동하지 않는다.

삭제 요청자 기록에서 추출한 특징도 삭제 대상의 영향을 담을 수 있으므로, 보존 상태와 망각 평가를 함께 설계해야 한다. 탐지 신호 발견이 삭제 이행 인증을 대신하지 않는다.

## 노벨티를 판정할 지점

중심 후보는 **요청이 제거할 억제 효과와 실제로 남는 위험 기능의 관계를, 추가 진단 FU 없이 구별하는 추정 방법**이다. 기능 특징, 시간 이력, 투영을 조합했다는 설명만으로는 부족하다. 요청이 다른 경우 위험을 구분하고, 기존 특징·기존 FU 모니터보다 같은 정보와 정상 손상 예산에서 이득이 있어야 한다.

[Fusion/ Malicious Forgetting](https://wenwei-zhao.github.io/publication/conference-paper/3/)은 FU의 방향 부분공간 변화 탐지를 이미 공개 소개한다. DOI는 [10.1109/INFOCOM59046.2026.11571403](https://doi.org/10.1109/INFOCOM59046.2026.11571403)이며, 이번에도 IEEE 본문 접근은 되지 않았다. 구체적 관측·알고리즘을 원문과 비교하기 전에는 차별성이 확보됐다고 단정하지 않는다.

교수님께는 다음과 같이 설명할 수 있다.

> 기존 쌍 탐지는 정상 기여가 크면 공격 성분의 상쇄를 놓칠 수 있음을 확인했습니다. 방어 논문들이 기존 통계의 실패에서 새로운 관측을 도출한 방식을 따라, 삭제 요청과 연결된 기능 반응 및 실제 언러닝 과정에서의 위험 변화를 먼저 검증하겠습니다. 추가 탐지용 언러닝은 실행하지 않고, 관측이 분리되는 조건과 한계를 확인한 뒤 정화 알고리즘으로 연결하겠습니다.
