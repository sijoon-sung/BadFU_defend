# 장력 관측을 실제 FU 갱신에 연결하는 알고리즘

2026-10-14. **최종 목표는 FL→FU 잠복 백도어의 활성화 억제이며, 현재 우선 목표는 탐지의 검증이다.** §8에서 정상 non-IID와 위험 요청을 어떻게 구분·채점할지 고정한다. 악성 의도를 판별하는 알고리즘으로 두지 않는다. 이 문서는 구현 명세이며 탐지·ASR·망각 성능이 입증된 방법 소개가 아니다.

**제어 개정안은 §7, 현재 평가 우선순위는 §8이다.** §7은 기존 시간 관측을 재사용하되, 원시 업데이트의 요청 조건부 상쇄 연산자와 강볼록 제약 최적화로 제어한다. top-k·경보 지속 횟수는 새 제어의 입력이 아니다. §6의 미구현 표기는 그 조건 정리 시점의 상태이며 §7에서 구현한 범위를 우선한다. 기존 기능 기반 제어는 비교군으로 보존한다.

**시계열 조건 정리·정정(2026-10-14):** §§1–5는 현재 구현된 기능 관측·제어 프로토타입이다. §6은 **이미 구현·실험한 시간 관측과 요청 장부**를 기준으로 정보 조건과 남은 범위를 정리한다. 시계열을 처음 도입하는 제안이 아니다. 원시 업데이트만으로 후속 방향을 선택한다면 기능 probe는 필수가 아니지만, 기존 성능 결과의 주된 관측은 공개 입력의 기능 변화였다. 구현·실행·미검증의 구분은 §6.0을 우선한다.

## 1. Problem Statement (해결하려는 핵심 문제)

FL의 주입과 억제는 최종 모델에서 서로 가려질 수 있다. FU가 억제를 제거하면 남은 기여가 드러난다. FUBA의 클라이언트 간 역할, 원래 BadFU의 같은 클라이언트 내부 표본 역할을 같은 구조로 본다. 다만 클라이언트 합계로 내부 표본의 효과를 복원할 수는 없다.

기존 장력 점수의 세 문제가 핵심이다. (1) 정상 non-IID도 상쇄를 만든다. (2) 과거의 위험 방향이 현재 FU가 움직이는 방향과 다를 수 있다. (3) 탐지해도 삭제 요청을 막거나 억제 기여를 다시 넣으면 올바른 방어가 되지 않는다.

따라서 **과거에 상쇄되었고, 이번 삭제가 그 균형을 깨며, 실제 FU 보정이 증가시키는 기능 방향**을 선택해 갱신을 수정한다. 모든 클라이언트의 신원을 먼저 판정할 필요는 없다.

## 2. Key Idea & Formulation (핵심 방법론 및 수식/원리)

### 입력·정보·신뢰 조건

- 삭제 해상도에 맞는 FL 기여 기록과 실제 누적 요청 r. r은 기능 기여의 제거율이다. 임의 표본 개수 비율을 대신 넣지 않는다.
- 고정 공개 입력 x와 사전 선언한 변환 a. 후보 좌표는 중심화 로짓 m의 차 \(q_p=m_c(a(x))-m_c(x)\). 공격 역할·표적·정답 트리거는 선택기에 주지 않는다.
- 실제 FU가 보존 데이터로 계산한 갱신 v. 여러 가상 삭제의 모델을 생성하지 않는다.
- 삭제 데이터와 독립적인, 클래스가 확보된 작은 보존 과제 proxy. 현재 실험은 MNIST 시험셋의 분리된 128개 라벨 입력이므로 추가 신뢰 가정이다. 원격 배치에서 기울기를 받는 방식은 아직 구현하지 않았다.

### 단계 1: FL에서 기능적 상쇄를 기록

가중된 실제 FL 갱신 u의 효과 \(e_{jp}=q_p(\theta+u_j)-q_p(\theta)\)를 기록한다. 현재 구현은 저장 궤적을 재생한다. 여러 시점 효과의 합은 비선형 모델의 정확한 삭제 기여가 아니라 고정 좌표의 관측 요약이다.

\[
P_p=\sum_j[e_{jp}]_+,\quad N_p=\sum_j[-e_{jp}]_+,\quad
H_p=\frac{2\min(P_p,N_p)}{P_p+N_p}.
\]

입력별 부호를 계산한 뒤 요약한다. 전체 클래스 평균을 먼저 내면 국소 효과를 잃을 수 있다. 입력에 무관한 클래스 bias는 q에서 소거되지만 모든 정상 non-IID 특징 변화가 없어지는 것은 아니다.

### 단계 2: 이번 삭제가 억제 쪽을 더 제거하는가

\[
B_p(r)=H_p\min(P_p,N_p)
\left[\frac{\sum_jr_j[-e_{jp}]_+}{N_p}-
\frac{\sum_jr_j[e_{jp}]_+}{P_p}\right]_+.
\]

분모 0인 항은 0이다. 양쪽을 동일한 기여 비율로 지우면 B=0. 완전 상쇄 P=N에서는 단순 양의 선형 삭제 효과로 환원되므로 이 수식만의 신규성을 주장하지 않는다.

### 단계 3: 실제 FU가 그 방향으로 움직이는가

FedEraser의 경우 남은 각 클라이언트에서 실제 보정 \(\hat u_j\)를 얻고

\[
v=\sum_{j\notin R}\bar w_j\frac{\|u_j^{FL}\|}{\|\hat u_j\|}\hat u_j
\]

를 만든다. **개별 보정 후 집계**이며 평균 후 노름 보정과 다르다. 실제 참여자는 라운드마다 다시 정한다. 과거 노름이 양수인데 새 방향이 0이면 실패를 보고하고 옛 방향으로 대체하지 않는다.

이미 계산된 실제 제안에 한 번 전방 평가를 하여

\[
A_p(v)=[q_p(\theta+v)-q_p(\theta)]_+,\qquad
S_p(r,v)=B_p(r)A_p(v),\qquad
\mathcal P=\operatorname{TopM}_{S_p>0}S_p.
\]

로 방향을 고른다. 첫 개발 실험에서 B만으로 고른 방법이 history-free보다 좋지 않아 **현재 갱신과의 일치 조건**을 추가했다. 같은 개발 모델에서 수정한 것이므로 수정 뒤 수치는 독립 확인 결과가 아니다. S는 순위 점수이며 현재 calibrated alarm이 아니다. logit scale 표준화와 정상 모델 보정은 미구현이다.

### 단계 4: 실제 갱신을 최소한으로 수정

현재 모델에서 \(g_p=\nabla q_p\), 보존 클래스 손실에서 \(h_y=\nabla L_y\)를 계산한다.

\[
d^*=\arg\min_d\tfrac12\|d-v\|^2+\lambda\sum_{p\in\mathcal P}[g_p^Td-\kappa_p]_+^2
\quad\text{s.t. }h_y^Td\le\epsilon_y,\;\|d\|\le\rho.
\]

기본값 λ=1, κ=ε=0, ρ=.25‖v‖는 동작 확인용이며 최적값이나 보안 문턱이 아니다. 실제 FU 상태는 θ+d로 진행한다. 삭제한 억제 기여나 삭제 전 모델 출력을 교사로 되넣지 않는다. Solver 실패는 오류, 진행 비율 \(d^Tv/\|v\|^2\le10^{-6}\)은 `stalled`로 보고한다. 정지한 상태를 삭제 완료로 세지 않는다.

보존 손실 제약과 gradient projection 자체는 [GEM](https://papers.nips.cc/paper/2017/hash/f87522788a2be2d171666752f97ddebb-Abstract.html) 등의 선행 설계다. 장력 점수+범용 투영을 결합했다는 이유만으로 신규성이 생기지 않는다. **S가 이력 없는 동일 제어보다 좋은 제어 방향을 고르는지**가 우리의 검증 대상이다.

### 계산 가능한 성질과 보장하지 않는 것

1. 최적해는 span{v,g₁,…,gM,h₁,…,hC}에 있다. 이 공간 밖 성분은 기능 반응과 선형 제약에 기여하지 않으면서 거리·노름만 늘린다. 구현은 최대 M+C+1차원 SVD 축소 뒤 SLSQP를 쓴다. D×D Hessian은 만들지 않는다. 메모리 O(D(M+C)), 기저 계산 O(D(M+C)²); 큰 모델에서는 여전히 무겁다.
2. ε,κ,ρ≥0이면 0이 가능해이므로 정확한 최적해에 대해 \(\lambda\sum[g_p^Td-\kappa_p]_+^2\le\|v\|^2/2\). q가 반지름 ρ 안에서 Lq-smooth라면 선택 좌표의 실제 증가 ≤κp+‖v‖/√(2λ)+Lqρ²/2. Lq를 모르므로 현재 수치 보안 인증으로 쓰지 않는다.
3. 보존 손실도 실제 증가는 εy+Lyρ²/2까지 가능하다. 선형 제약 만족은 실제 손실 불변이 아니다. ReLU 모델에 전역 smooth 가정을 자동 적용하지 않는다. 실행기는 실제 클래스 손실 변화를 별도로 기록한다.
4. 선택하지 못한 트리거, 분류 마진, 반복 단계의 누적 위험을 이 국소 식이 보장하지 않는다. ASR과 망각은 독립 평가가 필요하다.

### BadFU의 내부 역할을 어떻게 다룰 것인가

해상도가 맞는 과거 shard 기록이 있으면 같은 B를 적용한다. 없으면 클라이언트 합산 기록에 표본 삭제율을 넣지 않는다. 별도 후보는 **실제 보정이 제공하는 추가 정보**다: 같은 현재 θ에서 노름을 맞춘 과거 혼합 갱신과 camouflage 제거 후 보정 갱신의 \(J_q u\) 차이를 측정한다. 이는 내부 역할의 정확한 역산이 아니며 정상 삭제도 차이를 만든다. 이 경로는 아직 구현하지 않았고, 원래 BadFU 재현 없이 FUBA 결과를 두 공격 방어로 확장하지 않는다.

## 3. Evaluation & Results (주요 실험 결과)

구현: `FUBA/tension_control.py`, `FUBA/unlearn_method/federaser_clientwise.py`. 벡터 `replay` API는 진짜 초기 상태·라운드별 실제 참여자·보존 보정 callback을 받아 실제 상태에 제어를 적용한다. PyTorch 어댑터는 현재 **buffer 없는 모델**만 지원한다. BN을 조용히 무시하지 않는다.

실행기: `FUBA/experiment_tension_control.py`. 기존 MNIST/LeNet(44,426 params), K20 seed522 궤적, 최근20개 FL 전이, 공개 입력32개, 보존 proxy128개, 별도 평가512개. 클라이언트 보정2batch, lr=.005. 원래 FL의 참여 명단을 복원하고 FedAvg 합 오차를 검증한다. 공격 중 재주입은 사용하지 않는 보정 단계 실험이다. 총11군: 무방어, clipping, 보존 제약만, history-free, 선형 삭제 영향, 장력만, 이력 섞기, B만, 선형×현재 증가, 섞은 이력×현재 증가, B×현재 증가.

**범위:** global_(t−1)에서 실제 한 단계만 실행하므로 과거 삭제 기여가 남아 있다. 전체 FU나 망각 실험이 아니다. 최초 스모크는 ASR 미측정이며, 후속 `--eval-target` 옵션은 해당 단계 ASR을 측정한다. `forgetting_verified=false`, `attack_efficacy_evaluated=false`는 전체 효능 미검증을 뜻하고 `step_asr_measured`로 단계 측정을 구분한다.

100라운드 단계의 개발 비교(요청4는 이 라운드에 불참, 이력에는 존재): B로 선택한 8좌표의 최대 실제 증가가 무방어 .86131, clipping .20220, B만 .04354, B×현재 증가 .01296, history-free .00385였다. **현재까지 제안이 history-free보다 좋다는 근거가 없다.** 각 좌표를 임의 트리거 위험으로 해석할 수 없다. B×현재 증가의 정상 평가 ACC는98.24%, history-free98.44%; 한 모델·512개 입력의 미세 차이에 통계적 유의성을 붙이지 않는다. 요청4가 실제 참여한99라운드도 별도로 실행해 부분 참여 동작을 확인한다.

### 대리 좌표 결과를 ‘이론 실패’로 읽지 않기 위한 추가 검사

사용자의 지적 후 동일99단계를 실제 저장 트리거로 평가했다. 선택32개·보존128개와 겹치지 않는512개 중 표적8 제외458개가 ASR 분모다. 같은 시작 상태의 ASR은12.45%, ACC98.83%다.

| 무방어 실제 보정 |20.74%|88.67%|
| clipping만 |12.23%|98.83%|
| 보존 제약만 |11.35%|99.02%|

**해석:** 제어가 실패했다는 결과가 아니다. 그러나 선형 기준선과의 동률 및 clipping/보존 제약만으로 얻는 큰 효과 때문에 장력 이력의 추가 가치는 아직 입증되지 않았다. 선택 좌표의 증가량은 ASR과 다른 지표다. `history_action`과 history-free의 ASR 차이는 이 작은 평가셋에서5개 입력 차이로, 독립 학습 시드의 통계적 근거가 아니다. 정답 트리거를 관측해도 top-k 선택·국소 벌점이 자동으로 최선의 ASR을 만들지는 않는다. 상한은 정보 제공 조건이며 성능이 단조롭게 좋아진다는 뜻이 아니다. 두 후속 실행의 시간은 병렬 실행 영향이 있어 비용 벤치마크로 사용하지 않는다.

원본 로그: `loc_k20paper_s0_step99_req4_brightness_eval.json`, `loc_k20paper_s0_step99_req4_oracle_eval.json` (`FUBA/logs/tension_control/`). 이들은 같은 학습 모델·같은 한 단계이며 두 독립 실험 시드가 아니다.

**장력 구조 자체의 진단:** oracle 입력으로 B만 계산했을 때 상위8개 좌표가 모두 실제 표적 클래스8이었다. 밝기 입력의 B 상위8개는 7,4,7,5,2,3,0,6이었다. 점수 계산에 표적 번호는 전달하지 않았다. 따라서 이 모델에서 실제 트리거 영역의 역사적 장력이 관측된다는 증거가 있고, 공개 변환 관측으로 옮기는 단계가 부족하다. 이것은 한 모델의 정답 트리거 진단이며 일반적 식별 보장이 아니다. 더구나 현재 증가를 결합하면 선택이 달라지므로 ‘장력을 보았다’와 ‘FU를 안전하게 제어했다’를 분리해야 한다.

## 4. Limitations & Critical Discussion (한계점 및 의문점)

**가장 중요한 목적 충돌:** 보존 데이터에 백도어가 남으면 일반 재학습도 위험할 수 있다. 방어한 FU가 일반 재학습과 다르다는 사실만으로 망각 실패/성공을 결정할 수 없다. 일반 재학습과 **동일한 방어 학습 목적을 적용한 보존 데이터 재학습**을 모두 보고해야 한다. 후자의 일치도도 통계적·형식적 삭제 인증을 자동 제공하지 않는다.

역사 기반 좌표 선택 자체가 삭제 데이터의 흔적을 보유할 수 있다. 원시 장부를 지우는 것만으로 유도된 선택·파라미터의 의존성이 없어진다고 주장하지 않는다. 엄격한 삭제 보장을 목표로 한다면 공개/보존 자료만으로 선택 기준을 재구성하거나 유도 상태까지 포함한 별도의 삭제 분석이 필요하다. 현재 방법은 그러한 인증을 제공하지 않는다.

추가 위험: 변환이 공격 특징을 건드리지 못함, 시간에 따른 Jacobian 변화, 정상 희귀 클래스와 위험 방향 충돌, 여러 삭제 요청의 누적 오차, 보정 노름의 증폭, 안전한 영구 정지로 위장한 미망각, 적응형 공격. scalar scale 정규화·교환 가능 정상 보정·BN 정책·원래 BadFU 어댑터는 남은 작업이다.

## 5. Takeaway & Next Actions (내 연구/프로젝트와의 접점)

논문 핵심 문장 후보:

> FL에서 함께 학습된 기여의 상쇄가 선택적 삭제와 실제 FU 갱신에서 풀리는 방향을 식별하고, 보존 클래스의 효용 제약 아래 그 방향의 증가를 제어한다.

‘식별’은 기능 방향 선택이며 악성 의도 확정이 아니다. 현재는 **검증할 가설**이다. 아래 순서로 가설을 기각할 기회를 만든다.

### 6.1 무엇이 시계열인가

클라이언트별 모델 업데이트를 시간 순서가 있는 다변량 관측으로 다룬다. FL은 모델과 참여자가 계속 바뀌므로 정상성을 가정한 하나의 고정 분포 시계열로 취급하지 않는다. 서버의 기본 관측은

\[
\mathcal H_T=\{t,i,m_{it},\theta_t,\Delta_{it},a_{it},h_{it}\},\quad
\Delta_{it}=\theta^{\mathrm{local}}_{it}-\theta_t,\quad
x_{it}=a_{it}\Delta_{it}.
\]

m은 참여 여부, a는 실제 집계 가중치, h는 학습률·로컬 step 수·optimizer 등 알려진 설정이다. h는 선언된 설정이며 악성 클라이언트가 실제로 준수했다는 증명이 아니다. 기본 범위는 같은 모델 구조·동기식 FedAvg다. 이때 실제 집계가 가중합이면 \(\theta_{t+1}-\theta_t=\sum_i x_{it}\)를 검사할 수 있다. 서버 optimizer나 비선형 강건 집계에는 별도 기록·정의가 필요하다.

누적 U_i 하나만 보관하면 순서가 사라진다. 예를 들어 (+5,-5)와 (-5,+5)는 누적합이 같지만 요청 직전의 동향이 다르다. 전체 또는 여러 길이의 창을 보존해야 지속성·전환 시점·시차를 시험할 수 있다. **누적합을 쓰는 것과 시간 순서의 정보를 쓰는 것은 다른 주장이다.**

미참여 때 실제 집계 기여는 0이지만 그 클라이언트의 잠재적 업데이트를 관측한 것은 아니다. 동역학 예측에는 missing mask·참여 간격을 넣고, 가짜 0 관측으로 채우지 않는다. 서로 다른 시점의 파라미터 좌표는 같아도 기능적 의미는 변하므로 전 기간의 방향 불변을 가정하지 않는다.

신뢰하는 서버 기록은 클라이언트가 제출한 값을 정확히 기록한다는 뜻이다. 제출값이 정직한 gradient라고 가정하지 않는다. 정상 과반을 이용하는 중앙값·군집·추세 추정기를 채택하면 그 오염률 가정을 별도로 명시해야 하며, 서버 신뢰가 정상 과반을 뜻하지 않는다.

### 6.3 두 정보를 어떻게 결합할 것인가 — 아직 검증할 설계

클라이언트 전체 삭제 요청 R에서 각 시점의 기여를

\[
d_{R,t}=\sum_{i\in R}x_{it},\qquad k_{R,t}=\sum_{i\notin R}x_{it}
\]

로 나눈다. 전체 벡터의 한 코사인만 쓰면 정상 공통 학습에 작은 공격 성분이 묻힐 수 있으므로 층별·고정 저차원 투영별 시계열도 후보로 둔다. 투영은 창 안에서 고정하고, 시험 정답으로 고르지 않는다. 압축은 관측 손실을 만드는 선택이며 모든 백도어 방향을 보존한다는 가정은 두지 않는다.

검토할 신호는 **반대 방향의 지속성 → 이번 요청이 한쪽에 집중되는 정도 → 실제 FU 갱신과의 정렬**이다. 지속성·요청 점수·창 비교는 이미 구현돼 있다. 시차 반작용은 R-012에서 효과가 없었으므로 기본 신호로 다시 추천하지 않는다. 참여 간격·표현·정렬의 변경 근거가 있을 때만 별도 가설로 재검토한다. 시차 상관을 인과관계나 공모의 증거로 부르지 않는다. 의사결정 시각 이후의 데이터도 사용하지 않는다.

크기 채널 x와 정규화한 방향 채널을 함께 유지한다. 학습률·로컬 학습량·모델 수렴 단계에 따른 변화를 비교할 때 보정하되, 정규화한 값의 합을 실제 기여량이라고 부르지 않는다. 집단 공통 추세를 제거한 잔차는 보조 관측으로만 쓰고 원래 채널도 남긴다. 공격이 공통 추세에 섞여 있을 수 있기 때문이다.

요청으로 나눈 d와 k는 **실제 FL 궤적에서의 기록 분해**다. \(-\sum_t d_{R,t}\)가 실제 FU 변화와 같다고 두지 않는다. FU에서는 이후 보존 업데이트와 모델 궤적이 달라지므로 실제 FU 갱신과 비교하는 단계가 필요하다.

같은 기록은 정상 non-IID에서도 생길 수 있다. 위 신호로 선택한 방향은 제어 후보이며 공격자 판정이 아니다. 작은 clean validation은 정상 손실·클래스별 손상을 점검하는 데 쓰며, clean 손실 보존만으로 미지 트리거 안전성이 증명되지는 않는다. 데이터로 읽히는 기능 상쇄가 반드시 큰 parameter 반대 정렬로 나타난다는 정리도 현재 없다.

| 우선순위 | 기존에 고집하지 않을 제약 | 허용할 정보·행동 | 얻는 것과 대가 |
|---|---|---|---|
| 1 — 주 설정으로 권고 | 서버에 정상 데이터가 전혀 없음 | 소량의 독립 라벨 validation; 크기·클래스 커버리지 명시 | 정상 non-IID의 효용 손상 점검. 미지 트리거 탐지를 보장하지 않음; 동일 자료를 쓰는 fine-tuning·clipping·MASA 등과 비교 필요 |
| 2 — 주 설정으로 권고 | 추가 기록·추가 보정 비용이 전혀 없음 | 참여·가중치·설정 메타데이터, 시간별 sketch, 필요한 실제 FU 보정 라운드 | 불완전한 관측을 보완. 저장·통신·시간의 증가를 모두 측정; sketch는 FedEraser의 원래 기록을 완전히 대체하지 못할 수 있음 |
| 3 — BadFU 표본 삭제에 조건부 필요 | 삭제 요청은 ID만 전달하며 내부 기여 정보는 없음 | 아래 중 하나의 검증 가능한 삭제 단위 인터페이스 | 같은 클라이언트 내부 역할을 다룰 단서. 자동으로 이용 가능한 정보가 아니며 강한 프로토콜 변경 |
| 4 — 후속 대안 | 서버는 수동 관찰만 함 | OOD indicator 등 공개된 능동 과제 | BackdoorIndicator와 같은 관측 확장. FL 자체 변경·추가 비용·적응형 평가가 필요하므로 첫 시계열 실험에는 넣지 않음 |

BadFU의 표본 삭제를 포함하기 위한 대안은 (a) 학습 시부터 삭제 가능한 batch/shard의 기여를 기록하거나, (b) 요청 자료에 대한 제한된 접근/검증 가능한 연산으로 저장 checkpoint에서 요청 자료의 gradient를 구하는 것이다. (a)도 여러 로컬 step의 상호작용 때문에 정확한 독립 기여는 아니다. (b)는 요청과 관련된 방향의 **국소 추정**이며 역사적 기여 복원이나 FU 시뮬레이션이 아니다. 악성 요청자가 임의로 보낸 gradient를 믿는 것으로 대체할 수 없고, 자료의 학습 이력·대상과의 연결 및 검증 방법을 명시해야 한다. 원자료 접근을 허용한다면 그 사실을 별도 정보 조건으로 보고하고 요청 자료·유도 상태의 보존 정책도 정해야 한다.

BadFU와 FUBA는 같은 상쇄 제거 구조로 정식화하되 **정보 인터페이스까지 이미 동일하다고 주장하지 않는다**. 한 클라이언트 내부에서 매 라운드 상쇄된 두 기여는 합계의 시계열만 늘려도 항상 분리할 수 있는 것이 아니다.

완화하지 않을 핵심은 실제 요청의 삭제 이행, 알려지지 않은 트리거·표적, 정상 non-IID 평가, 그리고 잠복 공격 활성화라는 위협이다. FU 중 재주입은 별도 조건으로 보고한다. 특히 FUBA의 재학습형 실험을 그대로 쓰면 잠복 해제와 재주입이 섞일 수 있다.

## 7. 개정 알고리즘: 요청 조건부 상쇄 연산자와 제약 최적화

### 7.1 기존 규칙에서 무엇을 바꾸었는가

기존 장부·캐시·실제 FedEraser 보정은 유지한다. 새 경로는 top-k 좌표 선택, 악성 신원 임계값, 연속3회 경보를 FU 제어의 필수 단계로 사용하지 않는다. 요청 경계를 가로지르는 모든 수치적으로 양인 상쇄 방향을 연산자로 표현한다. 고유값의 수치 영점 1e-12는 선형대수 오차 처리이며 데이터로 조정하는 탐지 문턱이 아니다.

학습 창, 평활 강도, 허용 손실·진행량·위험 예산은 여전히 설계 변수다. 이를 숨기거나 “가정 없는 비휴리스틱 방어”라고 부르지 않는다. 각 변수가 명시된 추정 문제 또는 제약의 의미를 가지도록 바꾼 것이다.

### 7.2 시간 추정과 상쇄 연산자

각 라운드의 가중 기여로부터 삭제 쪽 d_t와 보존 쪽 k_t를 만든다. 행렬 D,K의 행은 시간이다. 미참여의 집계 기여는 0이며, 미관측 local gradient를 0으로 관측했다는 뜻은 아니다. 같은 창에 있는 전체 관측에 다음 추정을 적용한다.

\[
\widehat X=\arg\min_Z\{\|Z-X\|_F^2+
 \tau\sum_{t=1}^{T-1}\|Z_{t+1}-Z_t\|^2/(s_{t+1}-s_t)\}
 =(I+\tau L)^{-1}X.
\]

s는 라운드 시각, L은 1차 차분의 시간 Laplacian이다. 이 식은 완만하게 변하는 집계 성분을 추정한다는 모델 가정이다. 과거 실패한 lag 상관 검출기를 다시 쓰는 것이 아니다. 요청 시점에 이미 존재하는 FL 창만 사용하며, 이후 FU 관측은 평활에 넣지 않는다. τ=0인 무평활과 창 전체 누적을 별도 기준선으로 둔다.

\[
E=\|\widehat D\|_F^2+\|\widehat K\|_F^2,\quad
C_R=-\frac{\widehat D^\top\widehat K+\widehat K^\top\widehat D}{E},
\qquad
P_R=\arg\min_{P\succeq0}\|P-C_R\|_F^2=[C_R]_+=G^\top G.
\]

E=0이면 P_R=0이다. 방향 z에서 \(z^\top C_Rz=-2\sum_t
\langle z,\hat d_t\rangle\langle z,\hat k_t\rangle/E\)이므로, 반대로 작용한 방향에 양의 값이 생긴다. PSD 투영은 이 부호가 있는 관측으로부터 비음수인 제어 벌점을 얻는 유일한 Frobenius 최소거리 해다. 이것은 **기하학적 상쇄 노출량**이지 실제 ASR이나 악성 확률이 아니다.

전체 파라미터 수를 p라 할 때 p×p 행렬을 만들지 않는다. 쌓은 [D;K]의 행공간에서 최대2T차원의 고유값 문제를 풀고 G만 반환한다. 원시 창 메모리는 O(Tp), 작은 기저 계산은 대략 O(pT²+T³)이다. 장기간 전체 FL 기록의 비용이 사라지는 것은 아니다.

**성질 1 — 균일 삭제 소거.** 모든 단위에 같은 제거율 r을 적용하면 D=rX, K=(1-r)X이다. 같은 선형 평활 후 C_R은 음의 준정부호이므로 P_R=0이다. 반대로 남은 것과 삭제된 것이 같은 방향 v에서 정확히 반대이고 다른 성분이 없으면 P_R=vvᵀ/‖v‖²이다.

**성질 2 — 규모·좌표와 무관한 관측.** 공통 배율은 E에서 상쇄된다. 직교 좌표 변환에 대해 P_R도 같은 방식으로 변환되고 \(\|P_R\|_2\le1\)이다. 마지막 부등식은 \(2|ab|\le a^2+b^2\)를 각 라운드에 적용하면 얻는다. 클라이언트마다 다른 배율이나 임의 신경망 재매개화에 대한 불변성은 아니다.

### 7.3 실제 FU의 제어 문제

v는 실제 보존 데이터로 계산한 FedEraser 제안이다. H의 행은 사전에 정한 정상 validation의 클래스별 손실 gradient다. 기본 개정안은 벌점 계수를 튜닝하는 대신 상대 노출 예산 η를 직접 지정한다.

\[
\begin{aligned}
\delta^*=\arg\min_\delta\;&\tfrac12\|\delta-v\|^2\\
\text{s.t. }&
\|G\delta\|\le\eta\|Gv\|,\qquad H\delta\le\epsilon,\\
&\|\delta\|\le\rho,\qquad
v^\top\delta\ge\gamma\|v\|^2 .
\end{aligned}
\]

가능집합이 비어 있지 않으면 강볼록 목적 때문에 해는 유일하다. 해는 span(v, G의 행, H의 행)에 있으므로 작은 공간에서 푼다. 선택적 벌점 버전은 목적에 \(\lambda\|G\delta\|^2/2\)를 더하며, 제약이 없는 경우 \((I+\lambda P_R)^{-1}v\)라는 해석적 해가 있다. 기존 공개 입력 기반 top-k는 새 G의 계산에 들어가지 않는다.

η=.1이면 **정의한 노출 노름**을 제안의10% 이하로 제한한다. ASR90% 감소라는 뜻이 아니다. γ=.1은 FU 제안 방향으로10% 이상의 진행을 요구한다. 이것도 실제 망각의10%라는 뜻이 아니다. ε=.01은 클래스별 cross-entropy 증가의 nats 단위 예산이며 1% 정확도 예산이 아니다. ρ=.25‖v‖, 창20, τ=1은 개발 기본값이고 독립 성능 평가 전 고정해야 한다.

**성질 3 — 수치 해의 검증.** 무차원 최적화 좌표 z에서 목적은 1-강볼록이다. 비음수 승수 μ, 볼록 제약 f_i(z)≤0, stationarity 잔차 r에 대해 가능점의 목적 오차는
\[
F(z)-F(z^*)\le\tfrac12\|r\|^2-\sum_i\mu_i f_i(z)
\]
로 상계된다. 구현은 가능성 오차·KKT 잔차·이 상계를 함께 확인한다. solver의 종료 메시지만으로 성공/실패를 판정하지 않는다. 수치 허용 오차 아래의 국소 최적화 검증이며 신경망 안전성 인증이 아니다.

### 7.4 실제 정상 손실 확인과 replay

선형 H 제약 뒤에 **실제** \(L_c(\theta+\delta)-L_c(\theta)\le\epsilon_c\)를 확인한다. 위반하면 1/2씩 backtracking하되 γ 진행 조건 아래로 내리지 않는다. 축소하면 노출·노름 제약은 유지된다. 조건을 함께 만족하지 못하면 control_not_accepted로 보고하고 replay를 중단한다. 0 갱신, 무방어 갱신, 삭제 전 교사로 몰래 대체하지 않는다. 불수용은 이 알고리즘이 무용하다는 일반 증명도, 수학적 불가능성의 증명도 아니다. 실패 사유를 그대로 기록한다.

클래스 손실 검사는 해당 validation·해당 단계에 대한 확인이다. 여러 단계에서 ε가 누적될 수 있으므로 전체 FU의 클래스별 손실도 별도 보고해야 한다. 트리거가 validation에 없으면 이 검사가 그 트리거를 보장하지 않는다.

구현: [연산자·QCQP·실제 검사·replay callback](../../FUBA/request_geometry.py), [기존 단계 실행기 확장](../../FUBA/experiment_tension_control.py), [전체 기록 replay 실행기](../../FUBA/experiment_request_replay.py). 전체 replay는 진짜 학습 전 모델과 실제 보존 데이터 archive를 요구한다. 백도어가 남아야 하는 보존 자료를 clean MNIST로 교체해 방어 성공처럼 보이게 하지 않는다. 새 학습은 round_0과 참여 명단을 저장하고 정상 궤적도 local 기록을 남긴다. 기존 궤적에 없는 초기 상태나 표본 기여를 역으로 만들어내지는 않는다.

### 7.6 BadFU/ResNet 실행 어댑터 (2026-10-14 추가)

`BadFU_src/BadFU-main/request_pipeline.py`가 새 FL의 초기값·로컬/전역 상태·참여 가중치·실제 클라이언트 입력/라벨을 독립 폴더에 보존하고, 같은 데이터로 실제 FU 비교를 자동 실행한다. 기존 공개 코드의 6클라이언트 분리형이 대상이며, 논문 본문의 한 클라이언트 내부 표본 삭제를 구현했다고 하지 않는다. legacy `round_0.pt[gm]`은 실제 학습 전 상태이므로 기존 15라운드 자료도 재학습 없이 등록할 수 있다. legacy 데이터는 명시한 원래 설정으로 재구성하므로 원본 데이터 동일성은 별도 미인증이다.

ResNet 전체 파라미터에 대해 `large_geometry.py`는 정규화 행렬 M=[v;D;K;H]의 Gram 행렬 MMᵀ를 청크로 계산한다. 양의 고유값 Λ와 고유벡터 U를 이용한 B=Λ^(-1/2)UᵀM은 수치 오차 내에서 행공간의 직교 기저다. 이 기저에서 동일한 상쇄 연산자·QCQP를 풀고 원래 좌표로 복원한다. 랜덤 sketch나 top-k 파라미터 선택은 없으며, float32 행 저장·float64 Gram 누적·고유값 수치 문턱과 행공간 잔차를 결과에 기록한다. 테스트에서 작은 독립 dense 풀이와 대조했다. 메모리는 여전히 O((2T+C+1)p)이므로 ResNet 기본 이력 창은3이다. 창 크기가 MNIST와 다르다는 것을 실험 설정에서 숨기지 않는다.

BN running mean/variance와 정수 카운터는 gradient 벡터에 섞지 않는다. 모든 군이 매 FU 단계 시작 시 고정된 정상 검증 입력으로 BN 통계를 재구성하고, 그 단계의 파라미터 제어 동안에는 BN을 **eval 모드로 고정**한다. 그러므로 H와 실제 손실 검사가 동일한 정규화 상태를 사용한다. 단계 사이 BN 재구성의 클래스별 손실 변화는 별도 기록이며, 파라미터 제어의 ε 예산으로 정규화까지 보장한다고 하지 않는다. 원 저자의 층별·격라운드 구현과 구분되는, 클라이언트별 전체 벡터 보정의 명시적 BN 정책 변형이다.

초기 구현의 candidate별 BN 재구성 검사 및 eval 복원 전 검사는 개발 로그로 보존하되 성능 근거에서 제외한다. 보고할 실제 비교는 `traj_full_step14_eval_fixed.json`이며, 전체 FU와 독립 시드 실험은 별도다. 거절은 실제 손실/진행 조건을 충족하지 못한 실패이며 안전한 FU 성공으로 간주하지 않는다.

## 8. 탐지 우선 평가 (2026-10-14)

현재 사용자가 실험을 실행 중이므로 학습·기록·제어의 설정은 유지한다. 당장의 연구 질문은 **“실제 FU를 수행하기 전에, FL 이력과 삭제 요청으로 잠복 공격의 위험 요청을 정상 non-IID 요청과 구분할 수 있는가?”**다. §7의 제어는 후속 과제로 남긴다. 탐지 가능성이 확인되기 전에 ASR 제어와 탐지의 신규성을 함께 주장하지 않는다.

### 8.1 관측과 판단 단위

관측은 참여자·집계 가중치를 포함한 업데이트 이력 \(\mathcal H_t\), 요청에 대응하는 기록별 제거율 r, 사전에 고정된 공개 입력이다. 탐지기는 \(A(\mathcal H_t,r)\)를 출력한다. 공격 역할·표적·트리거·FU 후 성능은 채점에만 쓴다. 클라이언트 전체 삭제는 클라이언트 이력으로 표현되지만, 같은 클라이언트 내부 일부 표본의 삭제는 그에 맞는 관측 단위가 필요하다. 보안 집계로 개별 기여가 숨겨지는 환경은 현 구현의 가정 밖이다.

판단 단위는 **요청**이고 통계적 독립 표본의 단위는 **독립 학습 궤적**이다. 한 모델의 요청20개·시점4개를80개 독립 실험으로 세지 않는다. 같은 공격 모델에서도 엉뚱한 요청만 경보가 나면 정답 요청의 탐지는 실패다. BadFU의 제어 불수락은 최적화/손실 조건의 실패이며 경보 정답이 아니다.

### 8.2 이번 결과에서 고정할 탐지 규칙

우선 이미 등록한 `selective_v3`와 `linear_release`의 비교를 유지한다. 기존 원시 업데이트 연산자의 제어 결과를 사후적으로 이 탐지기의 성능이라고 부르지 않는다. 기능 좌표 c에서 기록 i의 누적 관측 기여를 \(e_{i,c}^{\le t}\)라 하고,

\[
P_c=\sum_i[e_{i,c}^{\le t}]_+,\quad
N_c=\sum_i[-e_{i,c}^{\le t}]_+,\quad
P_{D,c}=\sum_i r_i[e_{i,c}^{\le t}]_+,\quad
N_{D,c}=\sum_i r_i[-e_{i,c}^{\le t}]_+
\]

로 둔다. 현재 점수는

\[
B_c(t,r)=\frac{2\min(P_c,N_c)}{P_c+N_c}
\min(P_c,N_c)
\left[\frac{N_{D,c}}{N_c}-\frac{P_{D,c}}{P_c}\right]_+,
\qquad S(t,r)=\max_c B_c(t,r).
\]

0 분모는 구현의0 규약을 따른다. 주 설정은 고정 공개 입력의 log-probability 효과를 입력 평균한 뒤 전체 이력으로 누적한다. 이 값은 측정한 업데이트 효과의 합이며, 비선형 모델의 정확한 삭제 영향이나 악성 확률은 아니다. 비교 점수는 \(S_{\rm linear}(t,r)=\max_c[N_{D,c}-P_{D,c}]_+\)다.

정상 보정 궤적 b의 등록된 모든 시점·요청 최대값을 \(M_b=\max_{t,r}S_b(t,r)\)로 둔다. n개 독립 정상 보정에서 \(k=\lceil(n+1)(1-\alpha)\rceil\), \(q=M_{(k)}\)로 정하고 \(S(t,r)>q\)일 때만 경보를 낸다. k>n이면 유한 문턱을 만들지 않는다. α=.05, 좌표·요청 가족·검사 시점·주 비교는 이미 등록된 값 그대로다.

교환 가능한 정상 에피소드와 고정된 점수 규약 아래 이 순위 문턱은 새 정상 에피소드의 가족 전체 경보 확률에 대한 **보정/새 에피소드에 걸친 주변적 보장**을 준다. 특정 보정 자료에서 얻은 문턱의 실제 FPR가 항상5% 이하라는 조건부 보장은 아니다. 분포 이동·사후 설정 선택·다른 방법과의 OR 결합은 이 주장에 포함하지 않는다. 유한 가족 밖의 임의 적응 요청도 포함하지 않는다.

### 8.3 어떤 결과가 탐지의 증거인가

1. 정상 IID와 owner non-IID를 각각 보정하고 각각 시험한다. 정상 에피소드 FPR와 정확 이항95% 신뢰구간을 보고한다.
2. 개발 공격과 독립 시험 공격을 분리한다. 정답 요청의 탐지율을 주로 보고하고, 다른 요청만 울린 비율을 따로 낸다. 최초 등록 경보 시점과 마지막 시점의 탐지는 구분한다. 실제 요청 발생 시각이 없으면 탐지 지연을 주장하지 않는다.
3. 두 점수에 같은 관측과 같은 정상 보정 목표를 적용한다. 검증할 가설은 장력·선택적 삭제율을 사용한 규칙이 단순 선형 삭제 영향보다 정상 충돌을 덜 오인하면서 위험 요청을 더 잘 잡는다는 것이다. 각 방법의 실측 FPR도 함께 보여야 한다. 같은 α가 같은 실측 FPR를 뜻하지 않는다.
4. **공격 역할 정답과 실제 활성화 정답을 분리한다.** 전자는 현재 점수 파일로 채점할 수 있다. 후자는 같은 요청·출발 모델·FU 방식의 무방어 실행에서 삭제 전/후 ASR, clean ACC, 정상 입력의 표적 예측 비율을 대조해야 한다. 잠복/활성화의 수치 기준은 개발 자료로 고정하고 독립 시험에 적용한다. 실제 FU는 이 정답을 검증하는 실험이며 사전 탐지기의 입력이 아니다.
5. 탐지 성능이 분리되지 않으면 정상/공격 역할 라벨로 문턱을 맞추지 않는다. 공개 입력의 기능 관측에 신호가 없는지, 입력 평균이 상쇄하는지, 시간 누적이 희석하는지 기존 보조 분석으로 원인을 좁힌다. 확인 자료를 보고 규칙을 수정했다면 그 자료는 이후 개발 자료이며 새 독립 시험이 필요하다.

`report_detection.py`는 기존 manifest/scores를 읽어1–2의 통계를 만들고4가 미검증임을 명시한다. 시간·요청 점수가 없는 BadFU 제어 결과를 억지로 변환하지 않는다. 각 파일 해시를 결과에 남기지만 원본 체크포인트의 진위를 다시 검사하는 도구는 아니다.

### 8.4 논문 주장과 남은 병목

현 단계의 **검증할 주장**은 “업데이트 이력에 삭제 경계의 방향성을 결합하면 정상 이질성과 FL→FU 잠복 공격의 위험 요청을 더 잘 구분할 수 있다”다. 시계열을 썼다는 사실, PSD 투영, 정상 보정 자체를 새 기법이라고 주장하지 않는다. 기존6개 개발 궤적의 순위나 한 단계 ASR 개선만으로 위 주장을 확정하지 않는다.

원시 상쇄 연산자는 \(P_R=P_{\bar R}\)이므로 그것만으로 삭제되는 쪽이 억제자인지 주입자인지 결정하지 못한다. 기능 좌표의 부호가 방향을 제공할 수 있지만 공개 입력이 공격 기능을 관측하지 못하면 놓친다. 정상 non-IID도 같은 상쇄를 만들 수 있고, 관측 분포가 같으면 의도까지 식별하는 보장은 세울 수 없다. 따라서 검증할 범위는 명시한 관측/분포에서의 오류율과 활성화 위험 분리다.

BadFU의 구조적 공통성과 현재 구현의 관측 충분성도 나눠 다룬다. 저장된6클라이언트 변형은 재분석 자산이다. 이를 두 번째 탐지 검증으로 쓰려면 같은 규약의 사전 점수와 정상 보정/시험 궤적이 필요하며, 원래 같은 클라이언트 내 표본 삭제는 더 세밀한 기록이 필요하다. 이 조건들을 충족하지 않은 결과를 FUBA와 합쳐 일반적 탐지율로 보고하지 않는다.

### 8.5 기본 baseline과 대조군의 역할

현재 주 비교는 동일 관측의 `selective_v3` 대 `linear_release`로 유지한다. `tension_only`는 요청 경계를 제거한 구성요소 대조, `removed_negative`는 삭제된 양의 기여를 무시한 대조, `cross_v2`는 이전 수식의 진단이다. 각 방법의 목적·구현명·실행법은 [RUN.md](../../RUN.md)의 baseline 표에 맞춘다. 시간창·입력 평균 등 보조 설정의 최고값을 사후에 주 baseline 성능으로 고르지 않는다.

**중복 성질.** 단일 기록 j만 비율 r로 삭제하면 각 좌표에서 \(N_D=r[-e_j]_+\), \(P_D=r[e_j]_+\)이므로 \([N_D-P_D]_+=N_D\)이다. 따라서 단일 기록 삭제에서 `removed_negative`와 `linear_release`의 원점수는 항상 같다. 여러 기록을 함께 삭제하면 양·음의 삭제 기여가 동시에 생겨 달라질 수 있다. 전체 요청 가족에 대한 정상 최대값으로 보정하므로 단일 요청 원점수가 같아도 두 경보 문턱은 다를 수 있다. 이를 서로 다른 단일 요청 식별 정보로 설명하지 않는다.

`tension_only`는 각 좌표에서 \(2\min(P,N)\)이며 r에 의존하지 않는다. 공격/정상 에피소드의 상쇄를 구분하는 데 참고할 수 있지만 모든 요청이 동점이므로 요청자 순위로 국소화를 주장할 수 없다. v2는 동일 비율 삭제에도 양의 점수를 내는 알려진 반례가 있어 이전 설계 진단으로만 표시한다.

모든 주 비교는 동일 이력·집계 가중치·공개 입력·좌표·요청 가족·시점·정상 보정 분할을 공유한다. 숫자로 같은 threshold가 아닌 동일 α의 **방법별 정상 보정**을 사용하고 실측 FPR와 탐지율을 함께 보고한다. `report_detection.py --include-controls`는 저장된 보조 점수에만 이 채점 규약을 적용하며 기존 실험/수집/점수 계산을 변경하지 않는다.

원시 gradient 이상치 점수나 Krum 점수 하나를 계산한 결과를 해당 논문 전체 방어 재현이라고 부르지 않는다. FL 중 모델을 바꾸는 방어와 사후 요청 탐지는 다른 실험이며, 실제 FU 제어의 `no_defense`/`retention_only` 역시 탐지 baseline이 아니다. 선행 방어 비교는 각 방법의 원래 정보 조건과 개입 시점·연산 비용을 명시하는 별도 층으로 남긴다.
