# 장력 관측을 실제 FU 갱신에 연결하는 알고리즘

2026-10-14. **목표는 FL→FU 잠복 백도어의 활성화 억제**다. 악성 의도를 판별하는 알고리즘으로 두지 않는다. 이 문서는 구현 명세이며 ASR·망각 성능이 입증된 방법 소개가 아니다.

## 1. Problem Statement (해결하려는 핵심 문제)

FL의 주입과 억제는 최종 모델에서 서로 가려질 수 있다. FU가 억제를 제거하면 남은 기여가 드러난다. FUBA의 클라이언트 간 역할, 원래 BadFU의 같은 클라이언트 내부 표본 역할을 같은 구조로 본다. 다만 클라이언트 합계로 내부 표본의 효과를 복원할 수는 없다.

기존 장력 점수의 세 문제가 핵심이다. (1) 정상 non-IID도 상쇄를 만든다. (2) 과거의 위험 방향이 현재 FU가 움직이는 방향과 다를 수 있다. (3) 탐지해도 삭제 요청을 막거나 억제 기여를 다시 넣으면 올바른 방어가 되지 않는다.

따라서 **과거에 상쇄되었고, 이번 삭제가 그 균형을 깨며, 실제 FU 보정이 증가시키는 기능 방향**을 선택해 갱신을 수정한다. 모든 클라이언트의 신원을 먼저 판정할 필요는 없다.

## 2. Key Idea & Formulation (핵심 방법론 및 수식/원리)

### 입력·정보·신뢰 조건

- 삭제 해상도에 맞는 FL 기여 기록과 실제 누적 요청 r. r은 기능 기여의 제거율이다. 임의 표본 개수 비율을 대신 넣지 않는다.
- 고정 공개 입력 x와 사전 선언한 변환 a. 후보 좌표는 중심화 로짓 m의 차 \(q_p=m_c(a(x))-m_c(x)\). 공격 역할·표적·정답 트리거는 선택기에 주지 않는다.
- 실제 FU가 보존 데이터로 계산한 갱신 v. 여러 가상 삭제의 모델을 생성하지 않는다.
- 삭제 데이터와 독립적인, 클래스가 확보된 작은 보존 과제 proxy. 현재 실험은 MNIST 시험셋의 분리된 128개 라벨 입력이므로 추가 신뢰 가정이다. 원격 배치에서 기울기를 받는 방식은 아직 구현하지 않았다.

### 단계 1: FL에서 기능적 상쇄를 기록

가중된 실제 FL 갱신 u의 효과 \(e_{jp}=q_p(\theta+u_j)-q_p(\theta)\)를 기록한다. 현재 구현은 저장 궤적을 재생한다. 여러 시점 효과의 합은 비선형 모델의 정확한 삭제 기여가 아니라 고정 좌표의 관측 요약이다.

\[
P_p=\sum_j[e_{jp}]_+,\quad N_p=\sum_j[-e_{jp}]_+,\quad
H_p=\frac{2\min(P_p,N_p)}{P_p+N_p}.
\]

입력별 부호를 계산한 뒤 요약한다. 전체 클래스 평균을 먼저 내면 국소 효과를 잃을 수 있다. 입력에 무관한 클래스 bias는 q에서 소거되지만 모든 정상 non-IID 특징 변화가 없어지는 것은 아니다.

### 단계 2: 이번 삭제가 억제 쪽을 더 제거하는가

\[
B_p(r)=H_p\min(P_p,N_p)
\left[\frac{\sum_jr_j[-e_{jp}]_+}{N_p}-
\frac{\sum_jr_j[e_{jp}]_+}{P_p}\right]_+.
\]

분모 0인 항은 0이다. 양쪽을 동일한 기여 비율로 지우면 B=0. 완전 상쇄 P=N에서는 단순 양의 선형 삭제 효과로 환원되므로 이 수식만의 신규성을 주장하지 않는다.

### 단계 3: 실제 FU가 그 방향으로 움직이는가

FedEraser의 경우 남은 각 클라이언트에서 실제 보정 \(\hat u_j\)를 얻고

\[
v=\sum_{j\notin R}\bar w_j\frac{\|u_j^{FL}\|}{\|\hat u_j\|}\hat u_j
\]

를 만든다. **개별 보정 후 집계**이며 평균 후 노름 보정과 다르다. 실제 참여자는 라운드마다 다시 정한다. 과거 노름이 양수인데 새 방향이 0이면 실패를 보고하고 옛 방향으로 대체하지 않는다.

이미 계산된 실제 제안에 한 번 전방 평가를 하여

\[
A_p(v)=[q_p(\theta+v)-q_p(\theta)]_+,\qquad
S_p(r,v)=B_p(r)A_p(v),\qquad
\mathcal P=\operatorname{TopM}_{S_p>0}S_p.
\]

로 방향을 고른다. 첫 개발 실험에서 B만으로 고른 방법이 history-free보다 좋지 않아 **현재 갱신과의 일치 조건**을 추가했다. 같은 개발 모델에서 수정한 것이므로 수정 뒤 수치는 독립 확인 결과가 아니다. S는 순위 점수이며 현재 calibrated alarm이 아니다. logit scale 표준화와 정상 모델 보정은 미구현이다.

### 단계 4: 실제 갱신을 최소한으로 수정

현재 모델에서 \(g_p=\nabla q_p\), 보존 클래스 손실에서 \(h_y=\nabla L_y\)를 계산한다.

\[
d^*=\arg\min_d\tfrac12\|d-v\|^2+\lambda\sum_{p\in\mathcal P}[g_p^Td-\kappa_p]_+^2
\quad\text{s.t. }h_y^Td\le\epsilon_y,\;\|d\|\le\rho.
\]

기본값 λ=1, κ=ε=0, ρ=.25‖v‖는 동작 확인용이며 최적값이나 보안 문턱이 아니다. 실제 FU 상태는 θ+d로 진행한다. 삭제한 억제 기여나 삭제 전 모델 출력을 교사로 되넣지 않는다. Solver 실패는 오류, 진행 비율 \(d^Tv/\|v\|^2\le10^{-6}\)은 `stalled`로 보고한다. 정지한 상태를 삭제 완료로 세지 않는다.

보존 손실 제약과 gradient projection 자체는 [GEM](https://papers.nips.cc/paper/2017/hash/f87522788a2be2d171666752f97ddebb-Abstract.html) 등의 선행 설계다. 장력 점수+범용 투영을 결합했다는 이유만으로 신규성이 생기지 않는다. **S가 이력 없는 동일 제어보다 좋은 제어 방향을 고르는지**가 우리의 검증 대상이다.

### 계산 가능한 성질과 보장하지 않는 것

1. 최적해는 span{v,g₁,…,gM,h₁,…,hC}에 있다. 이 공간 밖 성분은 기능 반응과 선형 제약에 기여하지 않으면서 거리·노름만 늘린다. 구현은 최대 M+C+1차원 SVD 축소 뒤 SLSQP를 쓴다. D×D Hessian은 만들지 않는다. 메모리 O(D(M+C)), 기저 계산 O(D(M+C)²); 큰 모델에서는 여전히 무겁다.
2. ε,κ,ρ≥0이면 0이 가능해이므로 정확한 최적해에 대해 \(\lambda\sum[g_p^Td-\kappa_p]_+^2\le\|v\|^2/2\). q가 반지름 ρ 안에서 Lq-smooth라면 선택 좌표의 실제 증가 ≤κp+‖v‖/√(2λ)+Lqρ²/2. Lq를 모르므로 현재 수치 보안 인증으로 쓰지 않는다.
3. 보존 손실도 실제 증가는 εy+Lyρ²/2까지 가능하다. 선형 제약 만족은 실제 손실 불변이 아니다. ReLU 모델에 전역 smooth 가정을 자동 적용하지 않는다. 실행기는 실제 클래스 손실 변화를 별도로 기록한다.
4. 선택하지 못한 트리거, 분류 마진, 반복 단계의 누적 위험을 이 국소 식이 보장하지 않는다. ASR과 망각은 독립 평가가 필요하다.

### BadFU의 내부 역할을 어떻게 다룰 것인가

해상도가 맞는 과거 shard 기록이 있으면 같은 B를 적용한다. 없으면 클라이언트 합산 기록에 표본 삭제율을 넣지 않는다. 별도 후보는 **실제 보정이 제공하는 추가 정보**다: 같은 현재 θ에서 노름을 맞춘 과거 혼합 갱신과 camouflage 제거 후 보정 갱신의 \(J_q u\) 차이를 측정한다. 이는 내부 역할의 정확한 역산이 아니며 정상 삭제도 차이를 만든다. 이 경로는 아직 구현하지 않았고, 원래 BadFU 재현 없이 FUBA 결과를 두 공격 방어로 확장하지 않는다.

## 3. Evaluation & Results (주요 실험 결과)

구현: `FUBA/tension_control.py`, `FUBA/unlearn_method/federaser_clientwise.py`. 벡터 `replay` API는 진짜 초기 상태·라운드별 실제 참여자·보존 보정 callback을 받아 실제 상태에 제어를 적용한다. PyTorch 어댑터는 현재 **buffer 없는 모델**만 지원한다. BN을 조용히 무시하지 않는다.

실행기: `FUBA/experiment_tension_control.py`. 기존 MNIST/LeNet(44,426 params), K20 seed522 궤적, 최근20개 FL 전이, 공개 입력32개, 보존 proxy128개, 별도 평가512개. 클라이언트 보정2batch, lr=.005. 원래 FL의 참여 명단을 복원하고 FedAvg 합 오차를 검증한다. 공격 중 재주입은 사용하지 않는 보정 단계 실험이다. 총11군: 무방어, clipping, 보존 제약만, history-free, 선형 삭제 영향, 장력만, 이력 섞기, B만, 선형×현재 증가, 섞은 이력×현재 증가, B×현재 증가.

**범위:** global_(t−1)에서 실제 한 단계만 실행하므로 과거 삭제 기여가 남아 있다. 전체 FU나 망각 실험이 아니다. 최초 스모크는 ASR 미측정이며, 후속 `--eval-target` 옵션은 해당 단계 ASR을 측정한다. `forgetting_verified=false`, `attack_efficacy_evaluated=false`는 전체 효능 미검증을 뜻하고 `step_asr_measured`로 단계 측정을 구분한다.

100라운드 단계의 개발 비교(요청4는 이 라운드에 불참, 이력에는 존재): B로 선택한 8좌표의 최대 실제 증가가 무방어 .86131, clipping .20220, B만 .04354, B×현재 증가 .01296, history-free .00385였다. **현재까지 제안이 history-free보다 좋다는 근거가 없다.** 각 좌표를 임의 트리거 위험으로 해석할 수 없다. B×현재 증가의 정상 평가 ACC는98.24%, history-free98.44%; 한 모델·512개 입력의 미세 차이에 통계적 유의성을 붙이지 않는다. 요청4가 실제 참여한99라운드도 별도로 실행해 부분 참여 동작을 확인한다.

사용자의 지적 후 동일99단계를 실제 저장 트리거로 평가했다. 선택32개·보존128개와 겹치지 않는512개 중 표적8 제외458개가 ASR 분모다. 같은 시작 상태의 ASR은12.45%, ACC98.83%다.

**해석:** 제어가 실패했다는 결과가 아니다. 그러나 선형 기준선과의 동률 및 clipping/보존 제약만으로 얻는 큰 효과 때문에 장력 이력의 추가 가치는 아직 입증되지 않았다. 선택 좌표의 증가량은 ASR과 다른 지표다. `history_action`과 history-free의 ASR 차이는 이 작은 평가셋에서5개 입력 차이로, 독립 학습 시드의 통계적 근거가 아니다. 정답 트리거를 관측해도 top-k 선택·국소 벌점이 자동으로 최선의 ASR을 만들지는 않는다. 상한은 정보 제공 조건이며 성능이 단조롭게 좋아진다는 뜻이 아니다. 두 후속 실행의 시간은 병렬 실행 영향이 있어 비용 벤치마크로 사용하지 않는다.

원본 로그: `loc_k20paper_s0_step99_req4_brightness_eval.json`, `loc_k20paper_s0_step99_req4_oracle_eval.json` (`FUBA/logs/tension_control/`). 이들은 같은 학습 모델·같은 한 단계이며 두 독립 실험 시드가 아니다.

**장력 구조 자체의 진단:** oracle 입력으로 B만 계산했을 때 상위8개 좌표가 모두 실제 표적 클래스8이었다. 밝기 입력의 B 상위8개는 7,4,7,5,2,3,0,6이었다. 점수 계산에 표적 번호는 전달하지 않았다. 따라서 이 모델에서 실제 트리거 영역의 역사적 장력이 관측된다는 증거가 있고, 공개 변환 관측으로 옮기는 단계가 부족하다. 이것은 한 모델의 정답 트리거 진단이며 일반적 식별 보장이 아니다. 더구나 현재 증가를 결합하면 선택이 달라지므로 ‘장력을 보았다’와 ‘FU를 안전하게 제어했다’를 분리해야 한다.

## 4. Limitations & Critical Discussion (한계점 및 의문점)

**가장 중요한 목적 충돌:** 보존 데이터에 백도어가 남으면 일반 재학습도 위험할 수 있다. 방어한 FU가 일반 재학습과 다르다는 사실만으로 망각 실패/성공을 결정할 수 없다. 일반 재학습과 **동일한 방어 학습 목적을 적용한 보존 데이터 재학습**을 모두 보고해야 한다. 후자의 일치도도 통계적·형식적 삭제 인증을 자동 제공하지 않는다.

역사 기반 좌표 선택 자체가 삭제 데이터의 흔적을 보유할 수 있다. 원시 장부를 지우는 것만으로 유도된 선택·파라미터의 의존성이 없어진다고 주장하지 않는다. 엄격한 삭제 보장을 목표로 한다면 공개/보존 자료만으로 선택 기준을 재구성하거나 유도 상태까지 포함한 별도의 삭제 분석이 필요하다. 현재 방법은 그러한 인증을 제공하지 않는다.

추가 위험: 변환이 공격 특징을 건드리지 못함, 시간에 따른 Jacobian 변화, 정상 희귀 클래스와 위험 방향 충돌, 여러 삭제 요청의 누적 오차, 보정 노름의 증폭, 안전한 영구 정지로 위장한 미망각, 적응형 공격. scalar scale 정규화·교환 가능 정상 보정·BN 정책·원래 BadFU 어댑터는 남은 작업이다.

## 5. Takeaway & Next Actions (내 연구/프로젝트와의 접점)

논문 핵심 문장 후보:

> FL에서 함께 학습된 기여의 상쇄가 선택적 삭제와 실제 FU 갱신에서 풀리는 방향을 식별하고, 보존 클래스의 효용 제약 아래 그 방향의 증가를 제어한다.

|---|---|---|
| 지금 | RUN.md의 저장 궤적 실제 보정 단계11군; 요청자·시점 바꾸기 | 코드·선형/실제 차이와 진행량 확인. ASR 성과로 쓰지 않음 |
| 관측 | raw/paired, 임의 변환/정답 트리거 상한, 정상 IID·Dirichlet·owner | oracle에서도 신호 없으면 장력 방향 선택을 중심 기여에서 내림 |

| 적응형 | 관측·제어 규칙을 아는 공격자 재학습, 이후 학습 재활성화 | 저장 공격 갱신 배율 조절만으로 대체하지 않음 |

**최우선 중단 기준:** history-free 또는 linear×현재 증가와 효용–ASR 곡선이 같으면 장력 이력은 비용만 늘린 것이다. 이 경우 기능 제어는 남길 수 있어도 장력 기반 신규성은 주장하지 않는다. 현재 단계 실험은 이미 이 비교가 필요함을 보여준다.
