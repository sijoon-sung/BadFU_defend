# 알고리즘 방향 정정: FL→FU 구조와 장력

**2026-10-14 구조 중심 수정:** 연구의 핵심은 언러닝 시뮬레이션 점수의 개선이 아니라, FL에서 가려진 주입–억제 관계를 FU의 선택적 삭제 경계와 연결하는 것이다. FUBA와 BadFU는 같은 구조이며 역할이 놓인 단위의 해상도가 다르다. 현재 수학은 [열린 원고 v7](draft_v7.tex) §§3–6, 구현은 `FUBA/tension_audit.py`다. v3는 \(T=2\min(P,N)\), \(H=T/(P+N)\)에서 \(B_r=H\min(P,N)[N_D/N-P_D/P]_+\)를 계산한다. 한 부호가 없으면0이다. v2의 양방향 경계 질량은 불완전 상쇄에서 동일 비율 삭제에도 양의 점수를 주므로 비교군으로 내렸다. 삭제 모델을 생성하지 않는다. 정상 장력도 있으므로 독립 정상 에피소드의 최대값을 보정하며 [RUN.md](../../RUN.md)에 실행 묶음과 반박 기준이 있다.

아래는 **이전 soft 반응 비교군의 수학 기록**이다. 본 알고리즘의 신규성 주장으로 사용하지 않는다. 정상 상쇄 불가능이라는 과도한 명제를 철회하는 것과 장력 기반 연구 자체를 포기하는 것은 다른 결정이다.

## 이전 기록: 삭제 반응 감사

2026-10-14. 구현: `FUBA/response_audit.py`. 연구 후보이며 CLI 기본 경로는 기존 DOSE다. 이전 균형 장부 중심 도출은 [보관본](../archive/paper_logic_20261013/ALGORITHMIZATION.md)에 있다. 정상 상쇄 불가능, 단일 운반자 배제, 독립성 없는 오탐 확률의 곱은 사용하지 않는다.

## 1. 문제와 관측 단위

서로 겹치지 않는 삭제 단위 집합을 \(\mathcal U\), 누적 삭제 비율을 \(r\in[0,1]^K\), 기준 모델을 \(M_0\)라 한다. 고정된 연산자·학습 기록·난수 규약에서

\[
M(r)=\mathcal R(M_0,\mathcal H,r;\xi),\qquad p_r(x)=\operatorname{softmax}f_{M(r)}(x).
\]

모든 누적 요청은 같은 기준에서 구성한다. FUBA의 클라이언트와 BadFU의 데이터 묶음을 단위로 표현할 수 있지만 **그 단위를 실제 제거하는 연산자와 기록이 있어야 한다**. 현재 체크포인트 어댑터는 \(M(r)=M_0-\sum_jr_jU_j\)인 클라이언트 기여 감산이며, 정확한 언러닝이나 원래 BadFU의 묶음 제거 구현이 아니다.

공개 입력 뷰와 정당하게 접근 가능한 요청 입력 뷰를 별도로 사용한다. 공격 표적·트리거·공격자 정답은 점수 계산에 넣지 않는다. 모든 프로브에 신호가 없다면 이 방법으로 탐지할 수 없다.

## 2. 비교 요청이 만드는 기준

비교 요청 \(r_b\)는 전체 요청과 삭제 단위 수 및 비율을 맞춘다. 각 뷰를 선택 집합 \(D\)와 확인 집합 \(H\)로 나눈다. 선택 집합에서 기준 모델과 argmax가 바뀐 비율이 0.3 이하인 비교 요청만 \(B\)에 남긴다. 이는 비교 가능성을 위한 휴리스틱이며 해당 단위가 정상임을 인증하지 않는다.

\[
 m_c(x)=\operatorname{median}_{b\in B}p_{r_b,c}(x),\quad
 q_c(x)=m_c(x)/\sum_d m_d(x).
\]

분모가 0이면 비교 예측의 평균으로 대체한다. 입력마다 동일한 모델 비교를 한다. 비교군 자체의 점수는 자기 자신을 뺀 기준 \(q^{(-b)}\)를 사용한다. 따라서 후보와 비교군의 기준 표본 수가 하나 다르고 점수들은 독립이 아니다. 이 절차에 conformal 유효성이 자동으로 따라오지 않는다. 현재는 표본 수·참여량·클래스 분포까지 일치시키지 못한다.

## 3. soft 확률 흐름

클래스 수 \(C\ge3\), 입력 집합 \(X\), 원래 클래스 \(a(x)=\arg\max_c q_c(x)\)에 대해

\[
 F_{a\to c}(r;X)=\frac1{|X|}\sum_{x\in X}\mathbf1\{a(x)=a,\ a\ne c\}
 [p_{r,c}(x)-q_c(x)]_+.
\]

\[
 m_c=\sum_{a\ne c}F_{a\to c},\quad
 h_c=\frac{-\sum_{a\ne c}\pi_{a,c}\log\pi_{a,c}}{\log(C-1)},\quad
 \pi_{a,c}=F_{a\to c}/m_c,\quad S_c=m_ch_c.
\]

\(m_c=0\)이면 \(S_c=0\). 특정 출력으로 이동하는 확률 질량과 원래 클래스의 다양성을 함께 잰다. \([p_{r,c}-q_c]_+\)를 \(\mathbf1\{\arg\max p_r=c\}\)로 교체한 것이 동일 절차의 `hard_heldout` 소거군이다. 기존 DOSE와는 기준, 표준화, 분할에도 차이가 있으므로 **soft 자체의 효과는 hard_heldout과 비교**한다.

이름이 flow여도 고유한 최적수송 분해를 뜻하지 않는다. 실제 양의 확률 증가를 원래 argmax 클래스별로 모은 통계다. 단일 원래 클래스에만 작용하는 공격, 여러 표적에 분산되는 공격, 희소 트리거 공격에는 약할 수 있다. 이진 분류에서는 원래 클래스 엔트로피가 항상 0이므로 구현은 `inconclusive`를 반환한다.

## 4. 선택과 판정

각 분할 \(A\in\{D,H\}\)에서 비교군의 leave-one-out 점수로

\[
\mu_c^A=\operatorname{median}_b S_{b,c}^A,\quad
s_c^A=\max\{1.4826\operatorname{median}_b|S_{b,c}^A-\mu_c^A|,\epsilon\},\quad
z_c^A=(S_c^A-\mu_c^A)/s_c^A
\]

를 계산한다. \(\hat c=\arg\max_c z_c^D\)로 정한 표적은 확인 집합에서 바꾸지 않는다.

\[
\text{alarm}_v=\bigwedge_{A\in\{D,H\}}
\{z_{\hat c}^A>\tau\ \land\ S_{\hat c}^A-\mu_{\hat c}^A>\delta\}.
\]

고정 실험값은 \(\tau=3,\epsilon=0.005,\delta=0.02\), 분할 seed 20261014, 뷰별 256개 입력을 128/128로 분할, 비교군 최소 3개다. 입력 32개 미만 또는 비교군 부족이면 판정 불가다. 어느 뷰에서든 경보가 있으면 보류한다. 공개 뷰 평균 TV가 0.15를 넘는 보존 실패는 별도 사유로 보류한다.

이 z는 휴리스틱이다. 표적 선택을 분리해도 같은 학습 모델, 비교 요청, 입력 출처를 공유하므로 독립성이 보장되지 않는다. OR로 합친 뷰·삭제 단계 전체에 대한 오탐률 보정은 아직 없다. 독립 정상 학습 에피소드로 전체 파이프라인을 고정·보정·시험하는 것이 필요하다.

## 5. 실제로 증명할 수 있는 성질

**명제 1 — 범위와 단일 원래 클래스.** \(0\le S_c\le1\). 하나의 원래 클래스에서만 \(c\)로 질량이 오면 \(S_c=0\).

증명: 양의 증가의 입력당 합은 두 확률분포의 TV로 1 이하이고 \(0\le h_c\le1\)이다. 한 클래스에서만 오면 \(\pi\)의 엔트로피가 0이다. 이것은 정상 non-IID를 모두 허용한다는 정리가 아니며 단일 출처 공격을 놓치는 이유이기도 하다.

**명제 2 — argmax 양자화의 사각지대.** 두 원래 클래스가 같은 수로 나타나는 3클래스 입력에서 기준을 각각 \((.65,.20,.15)\), \((.20,.65,.15)\)라 하자. 원래 최대 확률에서 \(0<\eta<.25\)를 빼 세 번째 클래스에 더하면 argmax는 모두 같으므로 hard 점수는 0이다. soft 점수는 \(S_3=\eta\)다.

증명: 변경 후 최대 클래스의 확률 \(.65-\eta\)가 \(.15+\eta\)보다 크다. 세 번째 클래스로 각 원래 클래스에서 \(\eta/2\)가 유입되어 질량은 \(\eta\), 정규화 엔트로피는 1이다. 이는 정보 보존의 구성적 예이며 실제 모든 모델에서 더 높은 탐지율을 보장하지 않는다.

**명제 3 — 공통 반응과 비식별성.** 후보가 모든 비교 요청과 같은 예측을 만들면 \(S_c=0\). 반대로 정상 삭제와 공격 삭제가 모든 관측 예측에서 같다면 이 알고리즘은 둘을 구별할 수 없다. 각각 \(p_r=q\)와 관측 함수의 동일성으로 바로 따른다.

## 6. 전체 방어 과정에서의 위치

```text
학습 기록 유지 → 요청과 삭제 단위 검증 → 누적 삭제 후보/비교 모델 생성
    → 공개·요청 뷰의 확률 흐름 선택/확인 → 경보·보존 실패면 보류
    → 필요한 경우 CCD/TRACE/공동삭제로 설명 수집
    → 전체 요청을 반영한 복구 → 별도 보존·잔여 공격·망각 검증 → 교체
```

경보는 악성 사용자 확정이 아니고, 상대 후보는 자동 배제 명단이 아니다. 경보가 없어도 망각 검증이 없으면 `audited_only`다. 현재 CLI의 `--components response`는 새 비교기를 요청 처리기에 연결하는 실험 옵션이며 기본값 `existing`을 대체하지 않는다. `--paired_confirm`은 확인 실패로 기존 위험을 취소하지 않는 별도 옵션이다.

## 7. 기여의 정확한 위치

공통 가설은 **삭제에 따른 조건부 행동 반응을 검사할 수 있다**는 것이다. 그 가설을 시험하기 위한 도구로 비교 요청, soft 흐름, 별도 입력 확인을 정식화했다. soft 치환·MAD·입력 분할 각각은 강한 신규성이 아니다. 출판 기여는 실제 삭제 연산자의 근사 오차와 정상 이질성을 통제하면서 서로 다른 잠복 구조에서 검출력을 확보하는 데서 성립해야 한다. 현재 실험은 그 결론에 도달하지 않았다.
