# 삭제 요청으로 깨어나는 백도어를 학습 중에 찾아 걷어내기: 서로 지우는 기여의 탐지

초안 v4 (2026-10-13). v3 를 쉬운 말로 다시 썼다. 비유 용어(장부·다리·헤지)는 쓰지 않는다. 각 양은 처음 나올 때 한 줄로 정의한다. 숫자는 `docs/RESULTS_LOG.md` 의 번호가 있는 것만 쓴다.

## 용어 (이 문서 전체에서 이 말만 쓴다)
| 말 | 뜻 |
|---|---|
| 심는 클라이언트 | 트리거가 붙은 입력을 타깃 클래스로 분류하도록 모델을 미는 공격자. 논문 설정에서 넷 (0–3) |
| 숨기는 클라이언트 | 심는 쪽의 효과를 같은 양만큼 되밀어 모델을 깨끗하게 보이게 하는 공격자. 한 명 (4). 나중에 삭제를 요청한다 |
| 소유자 | 한 클래스(3)의 데이터 90 % 를 가진 **정상** 클라이언트 (19). non-IID 조건에만 있다 |
| 공개 입력 | 서버가 가진 라벨 없는 시험 이미지 500 장 |
| 클라이언트 j 의 클래스 c 누적 영향 P_j(c) | j 가 참여한 라운드마다, j 의 갱신 하나가 공개 입력 위에서 클래스 c 의 로그확률 평균을 얼마나 바꿨는지를 더한 값. 양수면 j 는 c 를 올렸고, 음수면 내렸다 |
| 상쇄율 H(c) | 클래스 c 에서 모든 클라이언트의 누적 영향을 더한 합의 크기를, 각자의 영향 크기를 더한 값으로 나눠 1 에서 뺀 것. 모두가 같은 방향이면 0, 서로 지워서 합이 0 이면 1 |
| 가장 내린 클라이언트 | 클래스 c 의 누적 영향이 가장 작은(가장 음수인) 클라이언트 |
| 유의하게 올린 클라이언트들 | 클래스 c 의 누적 영향이 나머지 클라이언트들의 중앙값보다 MAD 의 2 배 넘게 큰 클라이언트들 |
| 공모 | 한 클래스에서 유의하게 올린 클라이언트가 둘 이상이고, 한 명이 올린 몫의 6 할을 넘지 않으며, 가장 내린 클라이언트가 그 합을 거의 다 지우는 상태 |
| 경보 | 같은 클래스가 세 라운드 연속 공모로 판정되는 것 |

## 초록
연합학습 서버가 삭제 요청을 받으면 저장해 둔 그 클라이언트의 갱신을 모델에서 걷어낸다. 최근 공격(FUBA, BadFU)은 이것을 이용한다. 공격자 몇 명이 백도어를 심고, 다른 한 명이 같은 양만큼 되밀어 학습이 끝난 모델을 깨끗하게 만든 뒤, 되밀던 사람이 삭제를 요청하면 백도어가 드러난다. 이 논문은 이런 공격이 학습 중에 반드시 남기는 흔적을 찾는다. 심는 쪽과 숨기는 쪽은 같은 입력에 서로 반대되는 학습 신호를 보내므로, 라운드마다 각 클라이언트의 갱신이 공개 입력 위에서 타깃 클래스의 확률을 얼마나 바꾸는지를 더해 보면, 한 클래스에서만 "여럿이 크게 올리고 한 명이 그만큼 내려서 합은 0" 인 모양이 나온다. 정상 학습에서는 이 모양이 나오지 않는다. 데이터가 많은 정상 클라이언트는 자기 클래스를 크게 올리지만 그것을 되미는 사람이 없고, 정상 클라이언트는 남이 올린 것을 되밀 이유가 없기 때문이다. 서버는 라운드마다 참여자 수만큼의 순전파로 이 양을 누적하고, 위 모양이 세 라운드 연속 보이면 경보를 내며, 경보에는 타깃 클래스·숨기는 클라이언트·심는 클라이언트들·되돌아갈 라운드가 함께 나온다. 대응은 그 라운드의 모델로 돌아가 공모자를 뺀 채 이어 학습하는 것이다. FUBA 논문 설정(클라이언트 20, 공격자 5, 100 라운드, 참여율 0.4, IID·non-IID 각 3 시드)에서 6 궤적 모두 11–16 라운드에 경보가 났고, 숨기는 클라이언트와 심는 클라이언트 넷을 정확히 가리켰으며, 소유자를 한 번도 공격자로 보지 않았다. 공모자를 뺀 재학습은 공격 성공률 0.5–0.6 %, 정확도 99 % 다. 갱신 하나의 크기나 방향을 보는 기존 방어는 소유자를 같이 잡거나 심는 클라이언트를 가장 정상으로 보았다.

## 1. 문제: 삭제가 백도어를 켠다
연합학습에서 서버는 클라이언트들의 갱신을 평균해 모델을 만든다. 삭제권을 지키려면 특정 클라이언트의 몫을 모델에서 걷어내야 하므로, 연합 언러닝 서버는 라운드별 갱신을 저장해 둔다.

공격은 이 걷어내기를 거꾸로 쓴다. FUBA 를 예로 들면 다음과 같다.
1. 심는 클라이언트 넷은 트리거 생성기를 함께 학습하며, 트리거가 붙은 입력이 클래스 8 로 분류되도록 갱신을 보낸다.
2. 숨기는 클라이언트 한 명은 전역 모델이 깨끗한 모델처럼 보이도록 되미는 갱신을 보낸다 (저자 표현으로 model-consistency 손실; 본문은 초록·슬라이드로 확인).
3. 서버가 평균을 내면 둘이 지워져 학습이 끝난 모델은 깨끗하다. 트리거 입력의 공격 성공률이 3–8 % 다 (표 1).
4. 숨기는 클라이언트가 삭제를 요청한다. 서버가 그 갱신을 걷어내면 되밀던 힘이 사라지고 공격 성공률이 46–93 % 가 된다.

서버가 요청을 더 정확히 이행할수록 공격은 더 잘 된다. 심는 클라이언트들을 남긴 채 처음부터 다시 학습해도 백도어 모델이 나온다 (K=8 예비, 30–44 %). 즉 "요청자를 잘 지우는 것"은 답이 아니다. 심는 쪽을 찾아 걷어내야 한다.

## 2. 기존 방어가 못 보는 이유
기존 연합학습 방어는 갱신 **하나**의 성질을 본다. 크기(노름, Krum 거리), 방향(서버 기준과의 코사인), 출력층의 에너지 분포. 또는 갱신들끼리 얼마나 닮았는지를 본다(FoolsGold). 언러닝 전용 방어(MASA, SubID)는 삭제를 요청한 **한 명**의 갱신만 본다.

이 공격에서는 두 가지가 동시에 일어난다 (표 3).
- 숨기는 클라이언트의 갱신은 크다. 크기 기준은 그를 잡는다. 그러나 데이터가 많은 정상 클라이언트(소유자)의 갱신도 커서 함께 잡힌다 (소유자의 z 3.8–65).
- 심는 클라이언트들의 갱신은 방향이 평범하다. 20 명 중 가장 중심에 있다 (평균 순위 18.5/20). 방향 기준으로는 보이지 않는다.

문제의 본질은 갱신 하나가 아니라 **둘 사이의 관계**다. 심는 쪽이 올린 만큼 숨기는 쪽이 내린다. 한 명씩 보면 아무 이상이 없고, 둘을 같은 저울에 올려야 보인다.

## 3. 공격이 남기는 흔적
### 3.1 왜 흔적이 남는가
모델의 출력은 클래스별 로그확률이다. 라운드 t 에서 클라이언트 j 의 갱신을 전역 모델에 더하면 출력이 조금 바뀐다. 이 변화를 공개 입력 500 장에서 평균하면 "j 의 이번 갱신이 클래스 c 를 얼마나 올렸나"가 된다. 순전파 한 번이면 된다. 이것을 j 가 참여한 라운드마다 더한 것이 **누적 영향 P_j(c)** 다.

심는 클라이언트는 트리거 입력에서 클래스 8 을 올려야 하므로 공개 입력에서도 클래스 8 을 조금 올린다. 숨기는 클라이언트는 전역 모델 전체를 깨끗한 쪽으로 되밀므로 공개 입력에서 클래스 8 을 크게 내린다. 둘의 합이 0 에 가까워야 모델이 깨끗해 보이고, 둘의 크기가 커야 삭제 뒤에 백도어가 켜진다. 그러므로 공격이 성공하려면 클래스 8 에서 다음 네 가지가 동시에 성립해야 한다.
1. 모든 클라이언트의 누적 영향을 더하면 0 에 가깝다.
2. 그런데 각자의 영향은 크다.
3. 가장 내린 클라이언트는 한 명이다 (숨기는 클라이언트).
4. 유의하게 올린 클라이언트는 여럿이다 (심는 클라이언트들).

### 3.2 실제로 그렇게 보이는가 (R-012, 그림 1)
논문 설정 6 궤적의 학습 끝에서 클래스 8 의 누적 영향은 다음과 같다.
| 역할 | 누적 영향 P(8) |
|---|---|
| 숨기는 클라이언트 4 | −29.7 … −39.4 (6 궤적 모두 최솟값) |
| 심는 클라이언트 0–3 | +3.3 … +16.3 (각자) |
| 정상 | −3.9 … +4.9 |
| 소유자 19 (non-IID) | +0.2 … +3.8 |
합의 크기는 각자 크기 합의 7–16 % 다. 네 조건이 전부 성립한다.

### 3.3 왜 정상 학습에는 없는가
정상 클라이언트의 갱신은 자기 데이터의 손실만 줄인다. 자기가 가진 클래스를 올리고, 남이 올린 것을 되밀 이유가 없다. IID 면 모두 비슷하게 올리므로 합이 크고 상쇄율은 0 에 가깝다. non-IID 면 소유자 한 명이 자기 클래스를 크게 올리고 나머지는 거의 안 움직이므로 역시 합이 크다. "한 명이 크게 내리고 그 크기가 여럿이 올린 합과 같다"는 모양은 데이터 분포의 차이로는 생기지 않는다. 그것은 다른 사람들의 학습을 **되돌리는** 행동이고, 정직한 손실 함수에는 그런 항이 없다.

### 3.4 소유자와 어떻게 구분하는가
non-IID 조건에서 숨기는 클라이언트는 클래스 8 만이 아니라 소유자가 가르친 클래스 3 도 내린다 (소유자 +30, 숨기는 클라이언트 −35). 전역 모델의 변화 전체를 되돌리기 때문이다. 그래서 클래스 3 도 "합은 0, 가장 내린 사람 한 명" 이다. 차이는 올린 쪽이다. 클래스 8 은 심는 넷이 나눠 올리고(한 명의 최대 몫 0.31–0.54), 클래스 3 은 소유자 한 명이 거의 전부 올린다(몫 > 0.6). 여럿이 나눠 올리면 공모, 한 명이 올리면 정상 큰손으로 본다. 소유자는 손대지 않는다.

## 4. 방법
### 4.1 서버가 하는 일 (라운드마다)
1. 참여자 j 마다: 전역 모델에 j 의 갱신(집계 가중치 적용)을 더한 모델로 공개 입력 500 장을 순전파하고, 클래스별 로그확률 평균의 변화를 P_j(·) 에 더한다. 순전파는 참여자 수 + 1 번.
2. 클래스 c 마다 네 수를 계산한다. 상쇄율 H(c); 가장 내린 클라이언트와 그 z 점수(나머지의 중앙값과 MAD 기준); 유의하게 올린 클라이언트들(z > 2); 올린 몫 중 최대 한 명의 비율.
3. 클래스 c 를 **공모**로 판정한다 ⇔ H(c) ≥ 0.8 이고, 가장 내린 클라이언트의 z ≤ −3 이고, 유의하게 올린 클라이언트가 2 명 이상이고, 그중 한 명의 몫이 0.6 이하. 올린 사람이 한 명이거나 몫이 0.6 을 넘으면 **정상 큰손**(소유자형)으로 보고 손대지 않는다. 올린 사람이 없으면 **내리기만 있음**으로 적어 두기만 한다 (숨기는 클라이언트는 타깃이 아닌 클래스도 내리므로 이런 클래스가 몇 개 생긴다).
4. 같은 클래스가 3 라운드 연속 공모이면 **경보**. 판정은 5 라운드부터, 두 번 이상 참여한 클라이언트만 후보로 둔다.

### 4.2 경보가 주는 것
타깃 클래스 c*, 숨기는 클라이언트 후보(가장 내린 사람), 심는 클라이언트 후보(연속 판정 동안 한 번이라도 유의하게 올린 사람들), 되돌아갈 라운드(경보 전에 H(c*) 가 0.8 아래였던 마지막 라운드).

### 4.3 대응
되돌아갈 라운드의 전역 모델에서 시작해, 숨기는 클라이언트와 심는 클라이언트들을 뺀 채 남은 라운드를 이어 학습한다. 저자의 학습 코드를 그대로 쓰고 시작 모델과 제외 목록만 바꾼다. 요청이 학습이 끝난 뒤에 오는 경우에는 저장된 갱신 위에 같은 계산을 사후에 하면 같은 판정이 나오고, 공모자를 뺀 재학습으로 요청을 이행한다.

### 4.4 문턱값
상쇄율 0.8, 내린 z −3, 올린 z 2, 올린 사람 2 명 이상, 최대 몫 0.6, 연속 3 라운드, 시작 5 라운드. 6 궤적에서 고정했고 민감도는 §6.6 에 있다.

### 4.5 비용
라운드당 (참여자 수 + 1) × 500 장 순전파. 모델을 새로 만들지 않고 라벨·트리거·역할 정보가 필요 없다. 대응은 남은 라운드(87–93) 학습이다.

## 5. 왜 피할 수 없는가 (분석)
**공격의 필요조건이 곧 판정의 양성 조건이다.** 학습 끝 모델이 트리거 입력에서 깨끗하려면 트리거 입력 위에서 심는 쪽의 영향과 숨기는 쪽의 영향이 지워져야 한다. 삭제 뒤에 켜지려면 숨기는 쪽의 영향이 커야 한다. 이 상쇄가 공개 입력에도 일정 비율로 새면(FUBA 는 전역 모델 전체를 되밀므로 샌다; 실측 R-012), 공개 입력 위의 누적 영향에서 §3.1 의 네 조건이 성립한다. 이것이 공모 판정이다.

**정상에서 거짓 경보가 나려면** 어떤 클라이언트가 나머지보다 MAD 3 배 넘게 내리면서, 동시에 둘 이상이 MAD 2 배 넘게 올리고, 그 합이 서로 지워야 한다. 정상 영향이 독립이면 이 셋의 동시 확률은 각각의 꼬리 확률의 곱보다 작다. 소유자는 자기 클래스를 올리므로 "가장 내린 사람"이 될 수 없다. [공격 없는 궤적의 실측 R-015 예정]

**공격자가 피하려면.** (a) 되밀기를 여러 명에 나누면 가장 내린 사람이 집합이 된다 — z ≤ −3 인 사람 전부를 내린 쪽으로 보면 같은 규칙이 적용된다 [위장자 2 명 궤적 R-016 예정]. (b) 되밀기를 약하게 하면 학습 중 공격 성공률이 올라 숨지 못한다. (c) 상쇄를 트리거 입력에만 가두고 공개 입력에 새지 않게 하면 이 방법은 보지 못한다 — 이것이 경계이며, 그때는 요청 시점에 지울 입력을 포함한 집합에서 조금 빼 보는 심사(R-009 의 flow z, 숨기는 클라이언트 3/3, 소유자 z 0)가 보완한다. BadFU 의 노트북 15 라운드 궤적이 이 경우다 (R-017: 경보 없음). (d) 심는 사람을 아주 많이 두어 각자의 몫을 작게 하면 올린 사람 집합이 비지만, 합은 여전히 숨기는 쪽을 지워야 하므로 상쇄율과 내린 z 는 남는다 (내리기만 있음으로 보고됨).

## 8. 결론
삭제로 깨어나는 백도어는 같은 입력에 반대되는 학습 신호를 보내 평균에서 사라지게 한 것이다. 그 신호는 학습 중 각 클라이언트가 각 클래스를 얼마나 올리고 내렸는지에 남는다. 여럿이 올리고 한 명이 그만큼 내리는 클래스를 찾으면 타깃·숨기는 쪽·심는 쪽이 한 번에 나오고, 그들을 빼고 이어 학습하면 삭제는 이행되고 백도어는 사라진다.

## 부록 A. 식
- 누적 영향: P_j(c) = Σ_{t: j∈P_t} mean_{x∈X_p} [ f_c(x; θ_{t−1} + U_j^t) − f_c(x; θ_{t−1}) ]. f_c 는 클래스 c 의 로그확률, U_j^t 는 집계 가중치를 곱한 갱신, X_p 는 공개 입력.
- 상쇄율: H(c) = 1 − |Σ_j P_j(c)| / Σ_j |P_j(c)|.
- z 점수: z_j(c) = (P_j(c) − median_i P_i(c)) / MAD_i P_i(c).
- 공모(c) ⇔ H(c) ≥ 0.8 ∧ min_j z_j(c) ≤ −3 ∧ |{j: z_j(c) > 2}| ≥ 2 ∧ max_{j∈올린 쪽} P_j(c) / Σ_{j∈올린 쪽} P_j(c) ≤ 0.6.
- 1 차 근사로 P_j(c) 의 라운드 항은 ⟨U_j^t, ∇_θ f_c⟩ 의 평균이다. 전역 갱신의 변화는 참여자 항의 합이므로, "모델이 깨끗하다" 는 "항들의 합이 0" 이고 "삭제로 켜진다" 는 "한 항이 크다" 다.
