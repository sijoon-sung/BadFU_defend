# 기존 방법은 왜 안 되는가 — 집중 분석 (2026-10-12)

용어: **운반자** = 백도어를 심는 클라이언트. **위장자** = 같은 입력에서 거꾸로 밀어 백도어를 숨기고, 나중에 자기 데이터 삭제를 요청하는 클라이언트. **X\*** = 트리거가 든 입력 (서버는 모른다).
근거의 출처: [R] = `REPORT_2026-10-12.md` 절 번호, [U] = `FUBA/logs/analysis/update_stats_loc_fuba.json` (`analysis_update_stats.py`, 로컬 FUBA 1 시드), [H] = `FUBA/logs/analysis/hedge_loc_fuba.json` (`analysis_hedge.py`), [P] = 공격 논문 (`docs/paper_reviews/`). 방법 전체 목록은 `RELATED_METHODS.md`.

## 0. 먼저, 공격이 무엇을 만들어 놓는가 (세 가지 사실)
1. **백도어는 두 몫의 합으로 숨어 있다.** 운반자 몫 Σ_A U_j 가 백도어를 밀고, 위장자 몫 U_k 가 X\* 위에서 반대로 민다. 학습 중 전역 모델은 깨끗하다 (ASR 5–9 %). [R1]
2. **운반자 몫은 혼자서는 무해하다.** 운반자 하나를 통째로 빼도 ASR 9 → 4–6, 정확도 94.8 → 94.4 (변화 없음). 운반자 넷을 다 빼도 ASR 0.7. [U]
3. **위장자 몫은 혼자서는 해롭다.** 위장자만 빼면 ASR 9 → 63, 정확도 95 → 75. 운반자 없이 위장자만 남으면 정확도 82 (위장자의 억제 자체가 큰 왜곡이고, 운반자와 짝이 되어야만 "정상처럼" 보인다). [U]

이 셋이 아래 모든 실패의 뿌리다: **해로운 물건은 "합"이고, 각 조각은 정상이다.**

## 1. 학습 중 집계 방어 (Krum, Multi-Krum, Median, Trimmed-mean, FLAME, FLDetector, BaFFLe, MASA 학습판, B3D, MNTD, BackdoorIndicator, AlignIns)

### 1.1 무엇을 가정하나
각 라운드의 **갱신 하나하나**를 보고 이상한 것을 거른다. 이상 = 크기가 크다, 남들과 방향이 다르다, 또는 전역 모델의 행동이 나빠진다.

### 1.2 왜 안 되나 (기전)
- **운반자는 가장 "평범한" 갱신이다.** 로컬 FUBA 에서 라운드별 갱신의 중앙값과의 코사인: 운반자 0.80–0.81, 정상 0.65. Krum 점수(작을수록 믿음): 정상 0.030, 운반자 0.034–0.040. 운반자끼리는 서로 닮았고(코사인 0.73; 정상끼리 0.65) 넷이 뭉쳐 있어 중앙값이 운반자 쪽으로 끌린다. [U]
- **유일한 이상치는 위장자다.** 갱신 크기 0.38 (정상 0.10, 3.6 배), Krum 점수 0.54 (정상의 18 배). 7 라운드 중 5 라운드에서 Krum·크기 기준 "가장 의심"이 위장자. [U] 즉 집계 방어가 걸러 내는 것은 백도어를 **막는 쪽**이다. 위장자를 걸러 내면 억제가 사라져 운반자의 백도어가 그대로 전역 모델에 들어간다 (운반자는 여전히 평범해 보이므로 안 걸린다).
- **행동 검사는 볼 것이 없다.** 학습 중 전역 모델의 ASR 은 5–9 % 다. 전역 모델을 검증 데이터로 시험하는 방어(BaFFLe, BackdoorIndicator)는 깨끗한 모델만 본다. [R1]
- **합의 관계는 한 명 점수로 안 보인다.** 위장자와 운반자의 관계("서로 지운다")는 두 갱신을 같이 봐야 나오는데, 위 방어 열 종은 전부 한 명 점수형이다. 공격 논문도 같은 설명을 한다. [P: 02_FUBA 32, 60]

### 1.3 근거와 상태
- 공격 논문 Table II: 열 가지 방어를 학습 단계에 걸어도 언러닝 뒤 ASR 0.93–0.97 (MNIST, n=20, m=5). [P: 02_FUBA 32]
- BadFU Table VI: Median/Trimmed-mean 을 써도 활성화 뒤 ASR 84–96. 오히려 잠복 ASR 을 1–7 % 로 낮춰 **위장을 돕는다**. [P: 01_BadFU 42, 49]
- 우리 측정 [U] 은 K=8 (악성 5/8, 과반) 의 축소 설정이다. **과반 설정에서는 어떤 다수결 방어도 당연히 실패하므로 이 수치는 논문에 못 쓴다.** 논문 설정(n=20, m=5 = 25 %)에서 다시 재야 한다 — 궤적 묶음 `tdef` (K=20) 가 그것이다. 그 설정에서는 운반자 넷이 소수 무리가 되므로 FLAME 류 군집 방어가 운반자를 걸러 낼 가능성이 있다. 공격 논문은 "운반자가 세기(γ)를 낮춰 10–20 % 만 걸린다"고 보고한다. 우리 재현에서 확인할 것: (a) 운반자가 걸리는 비율, (b) 걸려도 남은 운반자 몫으로 언러닝 뒤 ASR 이 오르는가.
- 상태: **기전은 확인(과반 설정), 논문 설정 재측정 필요.**

## 2. 언러닝 연산자 (빼기, 증류 FU, FedEraser, FedU, SIFU, 재학습)

### 2.1 무엇을 가정하나
요청자의 영향을 **정확히** 걷어내면 좋은 언러닝이다. 정답 모델 = 요청자 없이 처음부터 다시 학습한 모델.

### 2.2 왜 안 되나 (기전)
- **요청자의 영향이 곧 억제다.** 정확히 걷어낼수록 백도어가 완전히 깨어난다. 빼기: ASR 48 (IID) / 54 (non-IID). 증류 FU: 29 / 43 — 덜 깨어나는 것은 덜 정확히 지웠기 때문이지 방어가 아니다 (요청자 영향이 남는다 = 삭제 불이행). [R1]
- **"정확한 언러닝"의 정답 모델도 백도어 모델이다.** 요청자 없이 다시 학습하면 운반자들의 독 데이터는 그대로 있다. BadFU: Retrain 뒤 ASR 99 (CIFAR-10). FUBA 재현(공격자가 재학습에 참여): 44 / 30. [P: 01_BadFU 36; R1]
- **클라이언트가 다시 참여하는 연산자는 공격자에게 두 번째 기회를 준다.** 재학습·FedEraser 보정은 남은 클라이언트의 학습이 필요하다. 운반자는 그때 다시 심는다. 우리 FedEraser 결과(ASR 4 / 8)는 **운반자가 보정 중에 정직하게 학습한다고 가정한 구현**이라 비현실적이다. BadFU 논문의 FedEraser 는 79 %. [R1 비고; P: 01_BadFU 36]
- 정확도 대가: FedEraser 는 정상 요청에서도 정확도 89 (빼기 94). [R1]

### 2.3 결론
언러닝을 "더 정확히" 하는 것은 답이 아니다. 정확함과 안전이 이 공격에서는 **반대 방향**이다. 그래서 방어는 언러닝 연산자 밖에, 요청 시점에 있어야 하고, **운반자의 몫을 건드려야** 한다 (삭제와 별개의 조치).
- 상태: **3 시드로 확인.** 단, FedEraser 비교군은 "운반자가 보정 중에도 공격한다" 설정으로 다시 돌려야 공정하다 (공식 코드로).

## 3. 요청 심사 (수락/거부형): Zhang 2023, Qian KDD'23, Liu AAAI'24, UnlearnGuard, 그리고 "한 명 점수" 탐지 (MASA, SubID 식, 가중치 지도)

### 3.1 무엇을 가정하나
요청(또는 요청자의 저장 갱신)을 하나 보고 "이상하면 거부, 아니면 수락".

### 3.2 왜 안 되나 (기전)
- **위장자의 저장 갱신은 "큰 정상 갱신"처럼 보인다.** 공개 입력 위에서 위장자의 기능 효과 크기 11.2, non-IID 클래스 소유자 9.0, 정상 2.8. 크기로 가르면 소유자를 같이 잡고, 크기를 안 쓰면 위장자를 놓친다. SubID 식 잔차: IID 에서는 위장자 1 위, non-IID 에서는 소유자가 1 위. [R4, R13]
- **상쇄는 X\* 위에서만 보인다.** 깨끗한 입력 위에서는 정상 클라이언트도 운반자와 "상쇄"로 나온다 (정상 0.40, 위장자 0.37 — 구분 불가). 서버가 X\* 를 못 보는 한, 저장 갱신만으로 짝을 못 찾는다. [R14.1]
- **MASA 식(언러닝 손실 상승)은 위장자를 가장 정상으로 본다.** AUROC 0.0–0.1. 위장자의 데이터는 깨끗하기 때문이다 — 해로운 것은 데이터가 아니라 "다른 몫과의 관계"다. [R4]
- **SubID 는 전제부터 안 맞는다.** 학습 중 갱신은 정상이라 가정하고, 언러닝 라운드에 **새 방향**이 생기는 능동형 공격을 겨냥한다. 잠복형은 백도어 방향이 이미 학습 갱신 안에 있고 언러닝 중 새 방향이 없다. [P: 04 38]
- **수락/거부는 둘 다 진다.** 거부 = 잊힐 권리 위반 (공격자가 바라는 것 중 하나). 수락 = 활성화. 운반자를 모르니 셋째 길이 없다.
- **문턱 하나는 피해 간다.** 요청 쪼개기(장부 없이는 통과), 미끼(정상 셋의 기여를 2.5 배로 부풀리면 z 14 → 2, ASR 37). [R5]
- **non-IID 에서 오탐.** 클래스 소유자를 빼면 정확도 92 → 81, ASR 29 — "정확도가 떨어졌다"는 검사는 정당한 소유자를 공격자로 본다. 우리 흐름 통계로도 오탐이 3 번 중 1 번 남는다. [R1, R15]

### 3.4 "헤지" 가설 (저장 갱신의 반상관으로 짝을 찾기, 2026-10-12 제안) — 측정으로 답함
제안: 위장자와 운반자의 갱신은 라운드마다 반대 방향이므로(헤지), 저장 갱신의 쌍 코사인(총노출)만으로 짝이 드러난다. 기존 공모 탐지(FoolsGold, MST-AD)는 양의 상관만 보므로 빈자리다.
측정 (`FUBA/analysis_hedge.py`, 로컬 FUBA, 라운드 평균 쌍 코사인):
| | 위장자–운반자 | 위장자–정상 | 운반자–운반자 | 정상–정상 | 운반자–정상 |
|---|---|---|---|---|---|
| 전체 매개변수 | **+0.56** | +0.60 | +0.73 | +0.65 | +0.45 |
| 층별 (conv1 / conv2 / fc1 / fc2 / fc3) | +0.65 / +0.71 / +0.55 / +0.47 / +0.59 | +0.85 / +0.78 / +0.56 / +0.54 / +0.62 | … | … | … |
| 공통 성분(라운드 평균 갱신) 제거 뒤 | −0.44 | **−0.50** | +0.23 | +0.44 | +0.02 |
- **반대 방향이 아니다.** 어느 층에서도 위장자–운반자 코사인은 양수이고, 위장자–정상과 같다. 억제는 매개변수 공간에서 운반자 갱신의 음수가 아니라, 트리거 입력에서만 반대로 작용하는 별도의 학습 벡터다 (FUBA 의 defender 벡터 = 공격 모델에서 정상 데이터로 미세조정한 차이).
- 공통 성분을 빼면 위장자는 **모두와** 반대(−0.44 / −0.50)가 된다. 가장 큰 갱신이라 평균을 빼면 혼자 반대편에 서는 것이지, 운반자와의 짝이 아니다. "가장 반대인 상대"를 라운드마다 고르면 위장자의 상대는 운반자·정상이 섞여 나오고, 정상의 상대도 마찬가지다.
- 총노출/순노출은 1.04 → 1.45 로 커지고 위장자가 총노출의 32 % 를 차지한다. 이것은 크기 신호(1 절의 노름 3.6 배)와 같은 것이고, non-IID 소유자가 같은 신호를 낸다 (3.2 절).
- 결론: 저장 갱신만으로는 짝이 안 보인다. 짝은 **활성화된 입력 위에서** 재야 보인다 (REPORT 14.3: 운반자 −0.9, 정상 +0.7). 헤지는 서론의 비유로는 좋지만 방법으로는 이미 기각된 '회전 1' 이다. 제안의 1 단계(클라이언트 단위 언러닝 강제)는 한 클라이언트형 BadFU 만 막는 정책이고, 두 클라이언트형(코드 설정)·FUBA 에는 효과가 없다.
- 상태: **1 시드, IID 로 확인.** non-IID(Dirichlet) 정상 쌍과의 비교는 K=20 궤적에서 한 번 더 돌린다 (`analysis_hedge.py --name <궤적>`).

### 3.3 결론
한 명을 점수 매기는 어떤 방법도 "서로 지우는 관계"를 못 본다. 보려면 (a) 요청자를 실제로 빼 본 뒤의 **행동 변화**를 (b) **X\* 가 드러나는 입력**(요청자가 낸 지울 데이터, 또는 빼서 깨어난 입력) 위에서 재야 한다. 그리고 출력이 수락/거부가 아니라 **누구 것을 걷어낼지**여야 한다.
- 상태: MASA·SubID 는 우리 재구현(proxy) 결과다. **공식 코드로 다시 돌려야 한다.** 기전은 3 시드로 확인.

## 4. 사후 정화 (INFOCOM 2026 "Malicious Forgetting"/SubID 의 SVD, null-space 게이트, OrthoPurify, Fine-pruning, NAD, 백도어 벡터 제거)

### 4.1 무엇을 가정하나
백도어는 모델(또는 갱신) 안의 **어떤 방향**이다. 그 방향을 찾아 깎으면 된다.

### 4.2 왜 안 되나 (기전) — 어디에 적용하느냐로 둘로 나뉜다
**(a) 요청자의 갱신 Δ_k 에 적용 (게이트, Δ 의 SVD):**
- **백도어는 Δ_k 안에 없다.** Δ_k = −U_k 는 억제를 걷어내는 변화다. Δ_k 를 아무리 깎아도 할 수 있는 일은 둘뿐이다: 억제를 남긴다(= 삭제를 안 한다) 또는 뺀다(= 활성화). 운반자 몫 Σ_A U_j 는 손도 못 댄다.
- **"깨우는 변화는 깨끗한 입력이 안 쓰는 방향에 있다"는 전제가 틀렸다.** 위장자를 빼면 보통 이미지 1,000 장 중 ~250 장이 타깃으로 분류되고 정확도가 95 → 79 로 떨어진다. 변화의 75–92 % 가 깨끗한 특징 공간 **안**에 있다. 그래서 null-space 투영 게이트는 ASR 63 → 61 (못 막음). 부분공간을 90 % 로 줄여야 ASR 40 이 되는데, 그때는 정상 요청의 갱신도 60 % 가 깎인다. [R16]
- SubID 류 SVD 는 저장 갱신 행렬에서 "정상 부분공간"을 잡고 언러닝 갱신의 **잔차**를 본다. 잠복형은 잔차가 없다 (4.1 의 전제 위반). [P: 04 17–18, 38]

**(b) 활성화된 모델 θ' 에 적용 (Fine-pruning, NAD, I-BAU 류 — 깨끗한 라벨 데이터로 미세조정·가지치기):**
- 원리상 백도어를 지울 수는 있다. 그러나 (i) 라벨 있는 깨끗한 데이터와 **학습**이 필요하고, (ii) 요청마다 맹목적으로 돌려야 하며(탐지가 없다), (iii) 정확도를 깎고, (iv) **누가 심었는지 모른다** (책임 귀속 없음). (v) Fine-pruning 의 "깨끗한 입력에서 잠잠한 뉴런" 기준은 여기서 뒤집힌다: 깨어난 백도어는 보통 이미지의 25 % 를 뒤집으므로 가장 **활발한** 뉴런이다.
- 상태: **(a) 는 측정으로 확인 [R16], (b) 는 아직 안 돌렸다.** BackdoorBench 의 공식 구현을 가져와 비교군으로 돌려야 한다. (v) 는 가설이다.

### 4.3 결론
갱신 Δ_k 만 보는 정화는 구조적으로 불가능하다. 모델 전체를 정화하는 방법은 가능하지만 비싸고 맹목적이며 귀속이 없다. 어느 쪽이든 **운반자를 찾는 단계**가 없으면 "삭제는 이행하고 백도어만 걷어낸다"를 못 한다.

## 5. 재억제·복구 (지우기 전 모델 쪽으로 다시 누르기: KD, 깨끗한 데이터 재학습, "repair")

### 5.1 왜 안 되나
- 백도어는 눌리지만 요청자 몫이 다시 들어간다: 재주입 α 0.16. [R13]
- 더 나쁜 것: **매개변수 공간에서 요청자 방향으로 한 걸음도 안 움직여도(α ≈ 0) 기능은 돌아온다.** 남들 모델을 교사로 증류하면 지운 클라이언트의 자기 데이터 정확도 50 → 79. 교사에 요청자의 지식이 들어 있기 때문이다. 입력을 "요청자를 빼도 답이 안 바뀐 것"으로 제한해도 75. [R15.4]
- 결론: 요청자 지식이 든 어떤 모델을 교사로 삼는 복구도 삭제를 되돌린다. "복구"는 삭제 이행과 양립하지 않는다.
- 상태: **3 시드 + 소거 실험으로 확인.**

## 8. 이 분석이 설계에 준 것 (한 줄씩)
- 해로운 것은 합 → 관계를 본다 (짝, TRACE).
- 학습 중엔 안 보임 → 요청 시점에 본다 (DOSE).
- X\* 는 받거나 깨워야 함 → 탐침 = 지울 데이터 ∪ 빼서 깨어난 입력.
- 정확한 제거도 백도어 → 운반자 몫을 건드린다 (DEFUSE), 삭제와 별개로.
- 복구는 삭제를 되돌림 → 요청자 몫은 손대지 않고, 요청자 지식이 든 교사도 쓰지 않는다.
- 한 명 점수는 쪼개기·미끼에 약함 → 장부와 정상 n 명 띠.
- 과반 설정은 모든 비교를 무의미하게 함 → 주 설정은 논문대로 K=20, 25 %.
