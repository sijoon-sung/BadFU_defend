# 지금까지의 실험 보고 (2026-10-12)

설정 공통: FUBA(MNIST, LeNet, K=8, 운반자 0–3, 위장자 4, 8 라운드, 웜업 3), 조건 IID / owner(클라 7 이 클래스 3 의 90 %), 시드 3 (DISLAB). BadFU(CIFAR-10, ResNet-18, K=6, 15 라운드, 운반자 0, 위장자 5)는 로컬 1 시드. 요청자: 위장자 4, 정상 7·5.
"고친 코드"는 2026-10-11 밤의 캐시 버그 수정 이후를 뜻한다. 한 단계짜리 결과는 버그와 무관, 여러 단계짜리는 다시 돌린 것만 유효.

## 7. 비용
(갱신) 가상 제거 모델을 요청자 간 공유하고 LOO 기준을 저장 확률의 중앙값으로 바꿔, 모집단 비용이 K² → K 순전파, 요청 한 건의 새 모델 0 개(첫 요청만 K). 결과 수치는 변경 전과 동일(FUBA z 12.9/0.4/0.5, 쪼개기 13.2, 운반자 집합, 해독제 λ=1 모두 일치).
K=8: 전체 15 s / 표본 5 명 7 s. K=100: 18 min / 47 s (LeNet, 탐침 500). ResNet K=50 표본 5: 48–85 min(격자 포함). 궤적 지표: 10 s (LeNet) / 87 s (ResNet). 학습 없음.

## 8. 고친 버그·바뀐 것
- 모집단 캐시 키(단계 번호 → 모델 지문). 순차 요청의 전체 예산 띠를 인과적으로. 흩어짐 0 → 판단 불가. ddof=1. α(재주입) 기록. 멈춤은 경보로 안 셈.
- MAD 는 공격자 과반에서 깨짐 → std 기본. 수정의 조기 종료는 끔(ASR 19 잔존).
- 탐침 기본 = 공개 + 지울 입력.

## 10. 해독제 방향 정화 (antidote.py, 로컬 FUBA 1 시드, 오늘)
요청자 4 를 뺀 모델에서 운반자 {1,3,2} 를 찾고, 활성화 입력(답이 클래스 8 로 몰린 122 장)에서 "8 의 확신을 올리는 방향" h 를 구해, 운반자 몫 중 h 성분만 뺐다 (운반자 몫의 4–5 %).
| 방법 | ASR | ACC | 요청자 몫 되살림 α |
|---|---|---|---|
| 요청만 (빼기) | 62.9 | 75.0 | 0 |
| 운반자 통째 제거 | 8.8 | 77.1 | −0.52 |
| 재억제 수정 (KD) | 9.7 | 91.0 | 0.13 |
| **해독제 λ=1** | **4.5** | **90.2** | **0.0006** |
| 해독제 λ=2 (상한 초과) | 0.0 | 83.5 | 0.001 |
- 요청자 몫을 전혀 되살리지 않고(α≈0) 운반자 몫의 5 % 만 빼서 ASR 을 가장 낮췄다. 정확도는 KD 와 비슷. "재우기"가 아니라 "지우기".
- λ 는 서버가 건강 상한(θ' 대비 변화 ≤ 0.3) 안에서 가장 크게 고른다(ASR 을 못 보므로). λ=1 이 그 값.
- 정상 요청(7)은 표시되지 않아 정화를 건너뛰고 그대로 수락됐다.
- 1 시드, FUBA 만. BadFU 와 3 시드는 미확인.
