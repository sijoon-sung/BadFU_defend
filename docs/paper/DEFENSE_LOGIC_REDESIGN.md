# 알고리즘 중심 재설계와 실행 결과

**방향 정정 (2026-10-14):** 아래의 soft 삭제 반응 중심 재설계는 원래 목표인 FL→FU 공통 구조와 장력 기반 방어에서 벗어났다. 특히 “상쇄 가설의 보편적 보장을 철회”하는 것을 “장력을 중심에서 제외”하는 결정으로 연결한 부분을 정정한다. 현재 [v7](draft_v7.tex)은 FUBA·BadFU의 같은 주입–억제 구조, 삭제 경계 점수, 조건부 수학 및 학습 캐시 재생을 본문으로 삼는다. 아래84조건과 실패 기록은 부록·비교군 근거로 보존한다. 이 문서 §1의 방향·핵심 주장은 현재 주장이 아니다.

2026-10-14. 최신 원고 [v7](draft_v7.tex), 수학·코드 대응 [ALGORITHMIZATION](ALGORITHMIZATION.md), 선행 방어의 전개 분석 [HOW_OTHERS_EXPLAIN](HOW_OTHERS_EXPLAIN.md).

## 1. 연구 방향을 바꾸는 결정

논문의 중심 질문을 **“학습 중 상쇄 연합을 찾을 수 있는가”에서 “비교 가능한 삭제와 구별되는 활성화 반응을 관측하고 확인할 수 있는가”로 바꾼다.** 상쇄는 동기를 설명하는 한 사례이며 필수 판정 조건에서 제외한다. 이 변경은 원래 주장의 보존보다 검증 가능한 알고리즘을 우선한 것이다.

현 단계에서 사용할 핵심 주장 문장:

> 삭제 반응을 비교 요청에 대한 조건부 확률 흐름으로 정식화하고, 선택한 출력 방향을 별도 입력에서 확인하는 요청 감사 절차를 제시한다. 이 절차는 상대 공격자를 사전에 특정할 필요가 없으며, 한 FUBA 궤적에서 기존 클래스 전환 검사에 없는 신호를 확인했다. BadFU 변형에 대한 검출력과 서로 다른 삭제 연산자에서의 일반화는 아직 확보하지 못했다.

목표로 삼되 아직 결과로 쓰지 않을 주장:

> 정상 데이터 이질성과 삭제 연산자의 오차를 통제한 요청 조건부 검사는 서로 다른 잠복 구조에서 삭제 후 활성화를 배포 전에 구별한다.

목표 문장을 주장으로 승격하려면 §5의 관문 실험을 통과해야 한다. soft score 하나를 추가한 것만으로 강한 노벨티가 생겼다고 평가하지 않는다. 중요한 기여 후보는 **요청 조건·관측 범위·연산자 오차를 함께 다루는 검증 절차**다.

## 3. 이번에 실제 수행한 실험

R-028–R-031. 같은 저장 궤적 세 개에서 총 **84개 요청–삭제비율–프로브 조건**을 실행했다. 새 학습 84회가 아니다. FUBA 18, BadFU 변형 18, 공격 없는 정상 모델 48조건이다. GPU에서 후보 및 비교 모델 예측을 실제 계산했다.

- FUBA: MNIST/LeNet, K20, 100라운드, IID seed522 한 모델. 억제자4, 정상5/19.
- BadFU 변형: CIFAR-10/ResNet18, K6, 15라운드 한 모델. camouflage 요청자5, 정상1/2. 같은 클라이언트 내부 묶음을 제거하는 원래 BadFU 실험이 아니다.
- 정상 대조: MNIST/LeNet, K8, 8라운드 한 모델의 8명. FUBA K20 전체 정상 분포를 대체하지 않는다.
- 비율 .05/.10/.20. `matched`는 이전 감사의 입력, `fresh`는 공개 입력의 다음 256개와 이전 요청 프로브를 제외한 새 256개다. 각 뷰는 128/128로 분할한다.
- `fresh` 공개 구간은 이전 ACC 평가 구간 일부와 겹친다. 새로운 학습 시드나 완전히 봉인된 시험 데이터라고 부르지 않는다. 공격 정답으로 문턱을 맞추지는 않았다.
- z3, 최소 효과 .02, MAD floor .005와 분할 규칙을 실행 전에 정했다. 실패 후 문턱을 바꾸지 않았다.

아래는 **검출기 경보 수**다. 분모는 서로 상관된 요청–비율 조합이다. `기존/새 입력`을 나눠 표시했다. 모든 방법에 공개·요청 뷰를 제공했다.

|---|---:|---:|---:|---:|
| FUBA 억제자 | 3 | 1 / 1 | 1 / 1 | **2 / 2** |
| FUBA 정상 | 6 | 0 / 0 | 0 / 0 | 0 / 0 |
| BadFU 변형 요청자 | 3 | **1 / 0** | 0 / 0 | 0 / 0 |

검출기와 별개인 보존 예산 TV>.15는 FUBA 억제자 .20에서만 두 프로브 모두 위반했다. 이 붕괴를 새로운 백도어 탐지 성과로 합산하지 않는다. 모든 조건에서 충분한 비교군이 있어 새 비교기가 판정 불가를 반환한 경우는 없었다.

### 긍정 결과의 정확한 의미

FUBA .10의 공개 뷰에서 soft 점수는 선택한 클래스8의 확인 z가 기존 입력 6.154, 새 입력 6.050이었다. 같은 분할의 hard와 기존 DOSE는 모두 경보가 없었다. 공개 TV는 각각 .0397, .0437로 보존 예산보다 작았다. 따라서 이 점에서 검출 신호는 전체 출력 붕괴로 설명되지 않는다. 별도 기존 ASR 평가 R-024에서 동일 삭제 모델의 ASR은 기준9.8%에서49.8%로 증가했다. 새 논문의 모든 조건을 다시 ASR 평가한 것은 아니다.

이 결과는 soft 관측이 정보를 보존할 가능성을 지지한다. 실제 입력의 모든 argmax가 불변이었다는 주장이나 동일 오탐률에서의 통계적 우월성을 뜻하지 않는다. 현재 최소 효과 문턱은 hard/soft 모두 같은 수치지만 두 점수의 검출력이 같은 비용이나 오탐률로 보정된 것은 아니다.

### 실패가 바꾸는 설계 판단

FUBA .05는 soft도 놓쳤다. 이전 공동삭제 검증은 .05/.10에서 경보를 냈다(R-020). 따라서 새 후보가 공동삭제보다 일괄 우수하다는 주장을 버린다.

BadFU .20의 기존 요청 입력에서 soft의 선택 z=4.162이지만 확인 z=.676이었다. hard도 선택 z=5.301에서 확인1.358로 줄었다. 분할 확인이 항상 도움이 되는 것이 아니라, 관측된 작은 신호를 잃는 비용이 있음을 보여준다. 희소성·표집 변동·모델 상태 중 무엇이 원인인지는 추가 실험이 필요하며 이 숫자만으로 원인을 확정하지 않는다.

기존 DOSE는 같은 요청에 기존 입력에서 경보가 있었으나 새 입력에서는 없었고, 새 입력의 정상 요청자1(.20)에는 경보를 냈다. 즉 입력 대표성은 새 점수만의 문제가 아니다. 새 방법의 정상 경보0을 성공으로 강조하면서 BadFU 미검출을 숨기면 안 된다.

현재 결론은 **FUBA의 soft 관측 가설은 제한적으로 지지, BadFU까지의 공통 검출 가설은 미확인**이다. 새로운 통계량을 더 붙이거나 문턱을 낮추기 전에 관측 범위와 비교군을 검증한다.

## 4. 원고의 논리 전개

1. **문제:** 배포 전 정적 행동만으로 삭제가 드러낼 위험을 평가하기 어렵다.
2. **가설:** 삭제를 통제된 개입으로 실행하고 비교 요청과 대조하면 요청 특이적 반응을 관측할 수 있다.
3. **두 설계 문제:** 보통의 삭제 변화와 어떻게 구별할 것인가; 예측 클래스 전환 전 변화를 어떻게 보존할 것인가.
4. **알고리즘 도출:** 동료 삭제 기준 → 여러 원래 클래스에서 들어오는 soft 확률 질량 → 고정된 표적 확인 → 위험/보존 판정.
5. **분석:** 점수 범위, argmax 사각지대의 구성적 예, 공통 반응 제거 및 관측 비식별성. 공격 성공률 정리와 혼동하지 않는다.
6. **평가:** 각 설계 선택에 하나의 반박 가능한 질문을 붙인다. BadFU 실패와 probe 교체 민감도를 본문에 둔다.
7. **기여 범위:** 공통 감사 인터페이스와 검증 가능한 후보 알고리즘. 보편적 방어·정확한 가해자 식별·안전한 망각 완료는 현재 결과로 주장하지 않는다.

## 5. 노벨티를 실제로 확보하기 위한 다음 관문

다음 표는 **미실행 계획**이다. 기존 전역 점수에 항을 더 붙이는 것보다 원래 위협과 관측·연산자의 관계를 해결하는 데 우선순위를 둔다.

| 우선순위/질문 | 필요한 실험과 비교 | 통과 기준과 실패 시 결정 |
|---|---|---|
| P0. 원래 위협을 측정하는가 | 원래 BadFU의 같은 클라이언트 backdoor/camouflage 묶음과 실제 묶음 삭제. 충분히 잠복한 모델부터 최소3 학습 시드 | 삭제 전/후 ACC·ASR로 활성화 성립 확인. 이 전제 실패 시 방어표에서 제외하고 재현 실패로 보고 |
| P0. 입력이 위험을 관측하는가 | 공개/요청/정당하게 접근 가능한 보존 입력; 표본수128/256/512/1024; 독립 probe draw 반복. 무작위와 **선택 집합에서만 학습한 관측 위치 선택** 비교 | 탐지 이득이 확인 입력·시드에 유지되어야 함. oracle trigger 입력은 상한선 표에만 사용. 관측 선택이 희소 신호를 못 찾으면 범위를 제한 |
| P0. 정상 차이를 잘못 공격으로 보는가 | K20·동일 학습 길이의 clean IID/Dirichlet/owner 궤적. 표본 수·참여량을 맞춘 대조와 현재 동일 비율 대조의 소거. 정상 보정/시험 시드 분리 | 전체 뷰·단계 파이프라인을 고정한 동일 FPR에서 hard/soft/DOSE 비교. 예컨대 split-conformal 5%를 주장하려면 최소19개 교환 가능한 정상 보정 에피소드가 해상도상 필요하며 정확도에는 더 많은 에피소드가 필요 |
| P1. 감산의 인공물을 탐지하는가 | 같은 요청에서 근사 감산/FedEraser/retain-only 재학습 비교, 연산자별 대조 모델 생성 | 연산자 교체 후에도 효과가 남아야 공통 감사 주장 가능. 그렇지 않으면 해당 근사 연산자 진단으로 범위 제한 |
| P1. 기존 방법보다 나은가 | 기존 DOSE, MASA, UnlearnGuard. 적용 단계·접근 정보·비용을 맞춘 뒤 각 원래 실행 지점을 보존. FLAME/DeepSight는 학습 단계 방어와 요청 감사 결합 조건에서 비교 | 같은 정보와 FPR에서 ASR–ACC–비용의 개선. 관련 논문을 읽었다는 사실을 비교 실험 실행으로 표현하지 않음 |
| P1. 실제 복구되는가 | 추정 후보로 전체 삭제를 이행한 복구, 정답 집합 제외 재학습은 oracle 상한. 후속 학습10/30/50라운드 재활성화 | 망각·보존·잔여ASR 함께 보고. 잠복 상태 복원을 치료 성공으로 집계하지 않음 |
| P2. 적응형·분할·다중표적에 견디는가 | 고정 검출기와 probe 접근 가정 아래 공격을 다시 학습. 누적 요청, 단일 출처 및 다중 표적, 비교군 오염 | 비용을 맞춘 공격/방어 곡선. 저장 업데이트 배율 변경만으로 적응형 평가라고 부르지 않음 |

가장 유망한 추가 알고리즘 방향은 **요청 조건에 따라 관측 위치를 선택하고, 별도 입력에서 그 선택을 확인하는 절차**다. 현재 score는 전역 평균이라 희소 활성화가 희석될 수 있다. 다만 이 방향도 일반적인 선택/검정의 재사용이며, BadFU의 실제 묶음 제거·정상 non-IID 대조·연산자 오차 분석을 함께 해결해야 논문의 기여가 된다. 아직 구현·검증했다고 주장하지 않는다.

## 6. 파일과 재실행

코드: `FUBA/response_audit.py`, `experiment_response.py`, `summarize_response.py`, `tests/test_response_audit.py`. 통합 옵션: `run_structural_guard.py audit --components response`. 기존 기본값은 `existing`이다.

결과: `FUBA/logs/response_audit/{fuba,badfu,clean}.json`, `summary.json`, 입력 인덱스를 뺀 상세 점수 `diagnostics.json`. 입력 인덱스·출처 설정은 원본 결과에 있다. 실행 당시 비교기 두 버전의 소스 스냅샷을 SHA-256으로 검증하여 보관했다. 두 버전의 차이는 이진 분류를 판정 불가로 처리하는 분기뿐이며 이 실험은 모두10클래스다. 동작 검사47개가 통과했다.

저장소 루트에서 다음을 실행한다. `source` 파일에 등록된 로컬 원본 체크포인트와 데이터가 필요하다. 이 파일들은 결과 JSON에 포함되어 있지 않다. 새 실행은 기존 결과를 보존하도록 다른 출력 디렉터리를 쓴다.

```powershell
$py = 'C:\Users\sijoo\Documents\ChatGPT\badFU\envs\badfu-original\python.exe'
& $py FUBA/experiment_response.py --source FUBA/logs/paired_audit/fuba_local.json --out FUBA/logs/response_replay/fuba.json
& $py FUBA/experiment_response.py --source FUBA/logs/paired_audit/badfu_local.json --out FUBA/logs/response_replay/badfu.json
& $py FUBA/experiment_response.py --source FUBA/logs/paired_audit/clean_local.json --out FUBA/logs/response_replay/clean.json
& $py FUBA/summarize_response.py --folder FUBA/logs/response_replay
& $py -m unittest discover -s FUBA/tests -v
```

GPU 비용은 세 결과의 `elapsed_seconds`에 각 기록되어 있다. 실제 학습 시드 증가, 원래 BadFU 재현, 새 복구 실험, 선행 방어의 학습 실행은 이번 실행에 포함되지 않는다.
