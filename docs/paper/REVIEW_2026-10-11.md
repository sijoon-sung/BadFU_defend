# 리뷰어 관점 코드 점검 (2026-10-11 밤)

독립 검토(별도 에이전트, 결론을 주지 않고 코드만 줌) + 자체 점검. 심각도 순. "고침" 은 커밋에 반영, "남음" 은 설계/실험 과제.

## 고침 (코드)
| # | 문제 | 왜 중요한가 | 조치 |
|---|---|---|---|
| 1 | **모집단 캐시 키가 단계 번호**(base_id)라서, 팔(arm)·요청자가 바뀌어 모델이 달라져도 같은 번호면 이전 모집단을 재사용 | 여러 단계가 있는 모든 결과(owner 의 dose/always, 쪼개기, 순차 요청, BadFU)가 잘못된 기준으로 계산됨. 한 단계짜리(IID 본 결과, pair)는 무관 | 키를 **모델 지문**(합·절대합·샘플합·크기) + 표본 집합 + 비율 + 탐침 모드로 바꿈. base_pred 도 지문 키 |
| 2 | 순차 요청의 전체 예산 띠가 **미래 요청자**를 후보에서 뺌 (서버가 모를 정보) | 공격 열에서 위장자 조각 전부가 띠에서 빠져 z_glb 가 실제보다 깨끗함 | 띠를 요청 시점마다 인과적으로(이미 뺀 사람 + 지금 요청자만 제외) 다시 만듦 |
| 3 | z 의 흩어짐이 0 이거나 모집단이 비면 **z=0 → 조용히 통과** | 건강한 멤버가 없는 상황(BadFU 전량 제거)에서 모두 통과 | 차이가 탐침 1 % 넘으면 '판단 불가'(z=99 → 표시). std 는 ddof=1 |
| 4 | 수정이 요청자 기여를 되돌리는 정도를 재는 지표가 없음 | "ASR 이 준 건 억제자를 되살려서"라는 반박에 답 못 함 | **α = ⟨θ_out − θ_plain, U_k⟩ / ‖U_k‖²** 를 기록. 로컬: 위장자 요청 수정 뒤 α=0.13, 정상 요청 '항상 수정' α=0.06, 수정 없으면 0 |

고친 뒤 로컬 검사: 한 단계 결과 동일(z 11.2 → 10.4 는 ddof). 순차 요청의 정상 열에서 요청 한 건 비교의 오탐(z 37)이 **사라짐** — 그것은 캐시 버그였다. 전체 예산 띠의 정상 오탐(2/3)은 남음.

## 다시 돌려야 할 표 (캐시 버그 영향)
- owner 조건의 dose/always 팔 (단계 1.7), 쪼개기 10 조각(T4-a), 순차 요청(T4-b), BadFU 전부. IID 한 단계 결과(T1 oneshot/dose, T2, T3, T4-c/g/i)는 영향 없음.
- 명령: `cd FUBA && FORCE=1 STAGES="dose adaptive aggregate" CONDS="owner iid" bash run_all.sh` (adaptive 는 쪼개기·순차만 바뀜)

## 리뷰어가 물을 질문에 대한 지금 답
- "dose 의 단계적 제거가 실제로 쓰인 결과가 있나?" — IID 에서는 항상 한 단계. owner 에서 1.7 단계, BadFU 에서 4 단계였으나 BadFU 는 신호가 없음. **단계 기능은 '무너진 모델을 내보내지 않음'(보호 장치)으로만 주장**하고 탐지 이득은 주장하지 않는다.
- "탐지 결정에 공격 정보가 쓰였나?" — 결정 경로에는 없음(검토 확인). 트리거·타깃은 ASR 채점에만.

## 추가 (같은 날 밤): BadFU 를 범위 안으로
- 탐침의 범위를 '깨끗한 공개 입력'에서 **'요청이 지우려는 데이터'** 로 넓힘 (`--probe_mode forget`). BadFU 의 위장 집합 D_c = {(x+τ, y)} 는 트리거 입력이므로 활성화가 바로 거기서 드러난다.
- 로컬 1 시드 (ResNet-18, 증류 연산자): 위장자 5 첫 단계 δ=0.6 에서 z=+8.4 (표시·수정), 정상 1: 1.9, 정상 2: −0.7. 최종 ASR 27 → 6.2 (ACC 82.5 → 76.5).
- 전량 빼기(oneshot)는 누구든 무너져 '판단 불가'(z=99) 로 표시됨 — 올바른 동작(무너진 모델을 내보내지 않음). dose 는 0.6~0.9 까지 빼고 멈춤: 정상 요청도 전량 제거가 안 된다. 이는 깊은 망에서 **빼기 연산자의 한계**이고 탐지의 한계가 아니다. BadFU 의 실제 FU(FedEraser 보정)를 연산자로 쓰는 판이 다음.
- 전제: 서버가 잊을 집합의 **입력**(라벨 불필요)을 본다. 샘플 단위 FU 요청의 일반적 형태이며 BadFU 저자도 '요청 데이터 심사'를 제안.
- 멈춤(abort) 단계는 경보로 세지 않도록 고침.
