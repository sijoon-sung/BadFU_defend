# 언러닝 활성화 백도어: 탐지 → 정화 실측 (FUBA / BadFU 실제 코드 기준)

실측일 2026-10-05~06. RTX 4060 8GB, Windows. 모든 숫자는 **공격 저자 공개 코드를 실제로 실행**한 궤적에서 나왔다.
아래는 **예비 실험**이다(1회 실행, 소규모). 수치는 경향으로만 읽을 것.

## 1. 공격 재현 (어떤 코드를 어떻게 돌렸나)

| | FUBA (stcebra/FUBA) | BadFU (BingguangLu/BadFU) |
|---|---|---|
| 실행 | `mpiexec -n 5 python main.py` (진짜 MPI) | `badfu.py` 구성요소 재사용 (`fl_detect_badfu.py`) |
| 데이터/모델 | MNIST, Net(LeNet류) | CIFAR-10, ResNet-18 |
| 트리거 | IBA(오토인코더 미세노이즈 ±0.04) | BadNet 패치 + UBA-Inf 영향함수 위장 |
| 구조 | 공격자 0~3, 방어자(요청자) 4, 정상 5~7 | 백도어 클라 0, 위장 클라 5, 정상 1~4 |
| 라운드 | 8 (warmup 3) | 12 |
| 잠복 ASR | 5.05% | 22.4% |
| 요청자 언러닝 후 ASR | **34.48%** (+29pp) | **34.6%** (+12pp) |

Windows에서 FUBA를 돌리기 위해 바꾼 것(공격 로직은 그대로): `pip install impi-rt`(Intel MPI 런타임), psycopg2-binary, `dataset.py`의 DALI import 가드, DataLoader `num_workers=0`. 상세: `FUBA/run_real_fuba.sh`.

BadFU 전처리는 공식 `prepare_data.sh`의 `rm/mv` 단계가 `pert_result.pt`가 가리키는 이미지 경로를 깨뜨리므로 그 두 줄을 생략했다(`BadFU_src/BadFU-main/regen_and_detect.sh`).

## 2. 탐지: 무엇이 보였고 무엇이 안 보였나

### 실패한 통계량 (기록으로 남김)
- **전체 업데이트 코사인(반평행)**: 모든 쌍이 +1.0 근처로 포화. 주 작업 방향에 묻힘. 실패.
- **쌍-차이 헤드 집중도 κ**: BadFU에서는 작동(κ=2.5~2.8×, 타깃 class0)했으나 FUBA에서는 실패(κ=1.37, 정상쌍보다 낮음). BadFU 성공은 두 악성 클라가 clean 데이터를 **공유**하는 BadFU 코드 구조 때문이었고, 데이터를 공유하지 않는 FUBA에서는 비-IID 지배클래스 차이에 묻혔다. **일반 탐지기가 아니었다.**

### 작동한 통계량: 같은 클래스 행에서 "둘 다 크게, 반대로"
쌍 $(u,k)$, 클래스 $c$의 헤드(fc3) 행 업데이트에 대해
$$O_{uk}(c)=\big[-\cos(\Delta W_u[c,:],\Delta W_k[c,:])\big]_+\cdot\min(\lVert\Delta W_u[c,:]\rVert,\lVert\Delta W_k[c,:]\rVert)$$

실제 FUBA 궤적 결과 (`FUBA/fuba_O_on_real.py`):

| 쌍 유형 | 타깃행 cos | 쏠린 클래스 = 타깃(8) 비율 |
|---|---|---|
| 공격자-방어자 | −0.20 | **1.00** |
| 공격자-정상 | −0.54 | **1.00** |
| 공격자-공격자 | **+0.81** | 0.00 |
| 정상-정상 | +0.77 | 0.00 |

- **타깃 클래스 식별**: 공격자가 낀 모든 쌍이 class 8을 가리킴.
- **공격자 군집**: 타깃 행에서 서로 +0.9 정렬.
- **요청자 식별**: 타깃 행을 **가장 크게**(0.101; 공격자 0.05~0.07, 정상 0.03~0.04) 움직이면서 공격자 군집과 **반대**(−0.22). 반대 집단 중 유일한 큰 값.

한계: 공격자-방어자 쌍 자체가 O 최상위는 아니다(방어자가 전 클래스를 세게 억제해 타깃행 반대가 약함). 요청자는 쌍 랭킹이 아니라 **타깃 행의 클라별 크기·방향**으로 집힌다. 1회 실행이라 임계값은 정상 모델 기준분포로 다시 정해야 한다.

비용: 쌍 전체 $O(n^2)$ 대신, 공격자가 한 클래스에 뭉친다는 성질을 써서 **클래스별 군집 통계 $O(nC)$**로 대체 가능. 요청 시에는 요청자 1명만 대보면 $O(n)$.

## 3. 정화: 삭제 요청은 들어주고 백도어만 끈다 (`FUBA/purify_compare.py`)

1차 근사 $\theta_T=\theta_0+\sum_{r,k}U_k^r$, $U_k^r=\tfrac1K(\text{local}_r[k]-\text{global}_{r-1})$. 요청자 기여 $U_{req}$는 **항상 전부 제거**(권리 보장). 공격자 쪽은 네 방식 비교.

| 변형 | ACC | ASR | 정상 클라 기여 손실 |
|---|---|---|---|
| A 잠복(그대로) | 95.75 | 5.05 | — |
| B 요청자만 제거 (= 공격 활성화) | 84.83 | **34.48** | — |
| C 요청자 + 공격자 **통째** 제거 | **68.41** | 0.00 | — |
| D 요청자 + 공격자의 **V 성분만** (fc3, k=8) | 89.55 | 17.05 | — |
| **E 요청자 + 전원의 V 성분** (판정 없음, fc3, k=8) | **90.09** | **12.23** | **8.8%** |
| F 요청자 + 임의 방향 (대조, k=8) | 84.83 | 34.42 | — |
| D/E with V from **전체 파라미터 PCA** | 73~77 | 36~40 | 30% |

$V$ = 활성 라운드 공격자 업데이트들의 상위-$k$ 주성분. **fc3(헤드) 공간으로 제한**했을 때만 작동한다.

읽는 법:
- **B→E**: 요청을 그대로 들어주되 모든 클라의 $V$ 성분을 빼면 ASR 34→12, ACC 85→90 — **둘 다 좋아진다.** 임의 방향(F)은 아무 효과 없음 → $V$가 의미 있는 방향이다.
- **E ≥ D**: 공격자를 판정해서 빼는 것(D)보다 **판정 없이 전원에 적용**(E)이 더 낫거나 같다. 정상 클라의 $V$ 성분은 전체 기여의 8.8%뿐이라 오탐 비용이 작다.
- **C**: 공격자를 통째로 빼면 ASR은 0이지만 ACC가 68로 무너진다. 공격자의 정상 기여까지 지우기 때문. "강도를 낮춰 지우기"는 이 둘 사이 어딘가일 뿐이고, 방향으로 쪼개는 E가 트레이드오프 바깥에 있다.
- **전체 파라미터 PCA는 실패**: 공격자 업데이트의 주성분은 주 작업 방향이라 그걸 빼면 정상 성능만 깎인다. 백도어 방향은 헤드에서 분리해야 한다.

한계(정직하게): 잔여 ASR 12%는 깨끗 모델 5%보다 높다 — 억제이지 완전 제거가 아니다. 1차 근사라 비선형 보정(FedEraser식)이 더 필요하다. 이후 라운드에서 다시 열리는지(reversion), 트리거 섭동 재활성화, 백도어 뉴런 존재 지표(BEC류)는 아직 측정하지 않았다.
