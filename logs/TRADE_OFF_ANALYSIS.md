# ⚖️ Trade-off Analysis: Security vs. Unlearning Efficacy

> **핵심 질문:** *"서버가 이상 가중치 델타를 감지하고 Client 0의 언러닝 업데이트를 드랍(기각)하면, 당연하겠지만 클라이언트의 데이터가 모델에서 제대로 지워지지 않는(언러닝 실패) 트레이드오프가 발생하지 않는가?"*

---

## 1. 트레이드오프의 본질 (The Core Dilemma)

연합 머신 언러닝(Federated Unlearning) 시스템에서 방어 메커니즘을 적용할 때 필연적으로 마주치는 **3대 핵심 지표 간의 삼각 딜레마(Trilemma)**입니다:

```
                       [1. Model Utility (Clean ACC)]
                                     ▲
                                    / \
                                   /   \
                                  /     \
  [2. Security (Backdoor ASR)] ◄─'───────'─► [3. Unlearning Efficacy (MIA / Forget Rate)]
  (백도어 격발 원천 억제)                      (요청 데이터의 완전한 소거)
```

### 1) 무방비 언러닝 (Naive Unlearning)
* **언러닝 유효성:** 100% (위장 데이터 $D_c$가 완전히 지워짐)
* **보안성:** 0% (**Backdoor ASR이 91.24%로 폭증**하여 모델 파괴)

### 2) 서버 레벨 드랍 방어 (Request Dropping / Rejection)
* **보안성:** 100% (Client 0의 이상 델타를 버리므로 **Backdoor ASR이 6.22%로 억제**)
* **언러닝 유효성 트레이드오프:**  
  Client 0이 요청한 $D_c$가 모델 가중치에 여전히 잔존(Residual Memorization)하므로, **순수한 의미에서의 언러닝(잊힐 권리)은 100% 달성되지 못함.**

---

## 2. 규제적·법적 관점의 정당성 (GDPR Article 12(5))

실제 현실(GDPR / CCPA)에서 이 트레이드오프는 법적으로 어떻게 해석되는가?

* **GDPR 제17조(잊힐 권리)의 예외 조항 (Article 12(5) & Article 17(3)):**
  * 유럽연합 GDPR 규정은 *"명백히 근거가 없거나 과도한 요청, 특히 악의적이거나 시스템 공격을 목적으로 하는 데이터 삭제 요청에 대해 데이터 관리자(서버)는 수수료를 부과하거나 **요청 수행을 거부(Refuse to act on the request)**할 수 있다"*고 명시하고 있습니다.
* 따라서 서버 레벨 감사에서 **시간적 가속도 1.54배, 클래스 요동 4.46배**라는 명백한 백도어 무기화(Weaponization) 증거가 포착된 경우, 서버의 언러닝 요청 기각은 **합법적 정당 방위(Legitimate Defense)**로 인정받습니다.

---

## 3. 트레이드오프를 해소하는 2대 기술적 해결 경로

### 경로 1: 악성 노드 전면 퇴출 (Full Client Revocation & Purge) - [가장 우아한 해결책]
* **원리:**
  * 공격자가 $D_c$만 골라서 지워달라고 편협하게 요청했을 때, 서버는 *"너의 요청에서 공격 패턴이 적발되었으므로, 너의 요청($D_c$만 삭제)을 들어주는 대신 **너의 모든 기여분(D_clean, D_bd, D_c 전체)을 모델에서 영구 퇴출**한다"*고 처리.
* **실험 결과 (Experiment 03 - Scenario 3):**
  * **Clean ACC:** 94.41% (정상 유지)
  * **Backdoor ASR:** **0.45%** (백도어 $D_{bd}$까지 모델에서 완전히 소멸)
  * **언러닝 유효성:** 100% (Client 0의 모든 데이터가 모델에서 깨끗이 삭제됨)
  👉 **보안과 언러닝 유효성 두 마리 토끼를 모두 잡는 궁극의 해법!**

### 경로 2: 경계 정제 언러닝 (Purified Boundary Unlearning)
* **원리:**
  * $D_c$를 완전히 버리는 대신, 프록시/서버가 검증용 클린 앵커 데이터셋(Canary Set)으로 미세 정렬(Calibration)을 걸어 타깃 클래스 0으로의 쏠림만 깎아내고 나머지 특징은 잊게 만드는 소프트 마스킹 기법.
* **효과:**
  * 백도어 뉴런의 발화만 억제하면서 일반적인 데이터 포인트의 결정 경계 이탈을 유도.

---

## 4. 결론

사용자님의 지적대로 **"단순 기각"은 언러닝 불이행이라는 부작용**을 남깁니다.  
따라서 실무적인 최적의 정책은:
1. **1차:** 서버 그래디언트 감사로 이상 요동(Surge 4.46x / Accel 1.54x) 적발.
2. **2차:** 악의적 언러닝 시도로 확정 시, 해당 클라이언트의 요청만 골라 삭제해주지 않고 **해당 클라이언트 전체를 연합에서 영구 퇴출(Full Revocation)**시킴으로써 **언러닝(데이터 완전 소거)과 보안(백도어 완전 박멸)을 동시에 완결**짓는 파이프라인이 가장 이상적입니다.
