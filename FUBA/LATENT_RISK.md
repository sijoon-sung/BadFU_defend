# 잠재 위험 지도 (latent risk map) — 가중치만으로, 요청 이전에

## 묻는 것

언러닝 요청이 들어오기 **전에**, 서버가 저장해 둔 궤적(라운드별 전역·로컬 가중치)만으로 "누가 공격자이고 누가 상쇄 역할(요청자)인가"를
트리거를 모르는 채 가려낼 수 있는가. 데이터도, 트리거 생성기도, 평가용 ASR 도 쓰지 않는다. 쓰는 것은 가중치뿐이다.

두 신호를 클라이언트마다 계산한다 (`latent_risk.py`).

### (A) 형태 서명 (shape signature)

라운드별 업데이트 `d_{k,r} = local_r[k] − global_{r−1}` 을 층별 행렬로 본다 (conv 가중치는 `out × (in·kh·kw)` 로 펴고, fc 가중치는 그대로, bias 는 뺀다).

| 값 | 뜻 |
|---|---|
| `frob` | 업데이트 크기 |
| `sigma1_share` = σ1/Σσ | 한 방향이 업데이트를 얼마나 독점하는가 (저랭크 정도) |
| `eff_rank` = exp(H(σ/Σσ)) | 유효 랭크. 낮을수록 저랭크 |
| `concentration` | \|원소\| 상위 1% 좌표가 갖는 제곱 질량 비율. 소수 좌표에 몰린 업데이트일수록 큼 |
| `consistency` = cos(d_{k,r}, d_{k,r−1}) | 라운드가 바뀌어도 같은 방향을 미는가 |

전체 모델 값은 층별 행렬을 블록대각으로 본 특이값 합집합(σ1 비율·유효 랭크)과 전체 벡터의 노름·집중도·일관성이다.
라운드별·층별 값을 모두 저장하고, 활성 라운드(웜업 이후) 평균을 요약으로 둔다.

출처 아이디어: *Weight-space Detection of Backdoors in LoRA Adapters* (arXiv 2602.15195) — 백도어 어댑터의 업데이트는 깨끗한 어댑터와 스펙트럼 서명이 다르다.

### (B) 참조 백도어 벡터 (reference backdoor vector, BV) 정렬

서버는 공격자의 트리거를 모른다. 대신 **자기 트리거**로 일반 백도어 벡터를 만든다.

1. 최종 전역 모델 θ_T 의 복사본을 서버 보유 소량 데이터로 몇 에폭 학습하되, 절반에 3×3 흰 패치(모서리 선택)를 붙이고 라벨을 서버가 고른 타깃으로 바꾼다.
2. (모서리 × 타깃) 조합마다 `BV = θ_trained − θ_T`. 기본 2 모서리(`br`, `tl`) × 3 타깃(`0 5 8`) = 6 개.
3. 평균 → `BV_generic`. 개별 BV 도 모두 보관한다.
4. 기본 타깃 중 **8 은 실제 공격 타깃**이다. 정답이 새는 것을 막기 위해 8 을 뺀 평균 `BV_non_target` 을 함께 보고하고, 판정은 `BV_non_target` 과 개별 BV 로도 성립해야 한다.

클라이언트마다 누적 기여 `U_k = Σ_{r∈active} d_{k,r}` 에 대해 `cos(U_k, BV)` (전체·층별) 와 라운드별 `cos(d_{k,r}, BV)` 를 잰다.
부호를 그대로 둔다: 백도어를 **심는** 쪽은 양, **상쇄하는** 쪽은 음이어야 한다.

출처 아이디어: *Backdoor Vectors* (arXiv 2510.08016) — 백도어 미세조정의 가중치 차이는 트리거·타깃이 달라도 공통 성분을 가진 벡터로 다룰 수 있다.
관련: *Watch the Weights* (arXiv 2508.00161) — 가중치만으로 백도어를 읽는 방향.

## 왜 두 공격이 이 흔적을 남길 것으로 보는가

- **FUBA** (gradient reweighting + consistency loss). 공격자는 백도어 기울기를 특정 파라미터로 몰아 넣고(reweighting), 라운드마다 같은 방향을 유지하도록 강제한다(consistency loss). Adv-defender(요청자)는 그 방향을 **정확히 상쇄**하는 업데이트를 낸다. 따라서 공격자·요청자 모두 정상보다 저랭크·고집중·고일관성 업데이트를 내고(A), 공격자는 BV 와 양의 정렬, 요청자는 음의 정렬을 보일 것이다(B).
- **BadFU** (고정 위장 데이터). 공격자는 매 라운드 같은 위장 데이터로 학습하므로 같은 방향을 반복한다(일관성↑). 상쇄 역할은 백도어 방향을 거꾸로 미는 업데이트를 내므로 BV 와 음의 정렬을 보일 것이다.

정상 클라이언트는 매 라운드 다른 미니배치를 보므로 업데이트 방향이 흔들리고(일관성↓), 특정 방향을 독점하지 않으며(σ1 비율↓, 유효 랭크↑), BV 와의 정렬은 0 근처여야 한다.

## 서버 데이터 가정

참조 BV 를 만들려면 서버가 소량의 정상 데이터를 가져야 한다. 여기서는 **MNIST 테스트셋 앞 N 장(`--server_data`, 기본 500)** 을 쓴다.
이 N 장은 클라이언트 학습 데이터(train)와 겹치지 않고, 테스트셋의 나머지(`[N:N+server_eval]`)로 BV 모델의 깨끗한 ACC 와 서버 트리거 ASR 을 자체 점검한다.
실제 FL 에서는 서버가 보유한 검증 셋(FLAME·FLTrust 류 방어가 두는 것과 같은 가정)에 해당한다. 궤적 평가(ACC/ASR)에 쓰는 테스트셋과 앞부분이 겹치므로,
엄밀히는 평가 셋을 `[N:]` 으로 제한하거나 train 의 별도 조각을 떼어야 한다. 이 실험은 경향만 본다.

## 실행

```bash
cd FUBA
python latent_risk.py --name det1 --rounds 8 --K 8 --warmup 3 --attackers 0 1 2 3 --defender 4 --target 8
python latent_risk.py --name det2 ...
python aggregate_latent_risk.py --names det1 det2 det3
```

- 출력: `logs/latent_risk/{name}.json` (라운드별·층별 형태 서명, 모든 BV 에 대한 정렬, 채점 요약), `{name}_bv.pt` (BV 벡터), 집계 `logs/latent_risk/summary.md` (+ `.json`).
- 옵션: `--server_data`, `--bv_epochs 3`, `--bv_targets 0 5 8`, `--bv_corners br tl` (`bl`, `tr` 가능), `--bv_patch 3`, `--n_gpu 0` (CPU).
- `--attackers/--defender/--target` 은 **채점에만** 쓰인다 (순위·AUROC). 신호 계산 자체는 정답을 보지 않는다. `--target` 은 `BV_non_target` 에서 뺄 타깃을 정한다.

채점: 스칼라 특징마다 요청자의 내림차순 순위, 공격자 순위, AUROC(공격자+요청자 vs 정상), AUROC(요청자 vs 나머지). AUROC 는 자체 구현(sklearn 없음).

## 판정 (결과를 보기 전에 고정)

| | go | no-go |
|---|---|---|
| (B) 부호 | 요청자가 `cos(U_k, BV_generic)` **가장 음수**(순위 K/K), 공격자가 **가장 양수**(순위 1..4). `BV_non_target` 과 개별 BV(타깃 8 제외)에서도 같은 순서 | 순서가 시드마다 뒤집히거나 정상 클라이언트가 섞임. `BV_non_target` 에서 무너지면 타깃 8 BV 가 정답을 누설한 것 |
| (A) 형태 | σ1 비율·집중도·일관성에서 AUROC(공격자+요청자 vs 정상) ≥ 0.9, 유효 랭크는 반대 방향 | AUROC ≈ 0.5. 정상 클라이언트의 비-IID 편중(class_owner)이 같은 서명을 내면 분리 불가 |
| 라운드 궤적 | 활성 라운드 진입(4 라운드)부터 공격자·요청자의 `cos(d_{k,r}, BV)` 가 양·음으로 갈라져 유지 | 웜업과 구분 없음 |

go 이면 다음 단계는 (1) 비-IID(`owner`, `dir01`) 궤적에서 오탐 확인, (2) BadFU 궤적에 같은 절차, (3) 두 신호를 합친 하나의 위험 점수와 요청 심사 규칙.

## 주의

- K=8·8라운드 소규모 설정이다. 경향만 본다.
- BV 는 θ_T 에서 출발한 미세조정 차이이므로 θ_T 가 이미 백도어를 품고 있으면 BV 가 작아질 수 있다(이미 열린 문을 다시 여는 셈). `bv.models[*].asr` 로 BV 가 실제로 트리거를 학습했는지 확인한다.
- 모든 cos 는 1차 근사 기여(`U_k = Σ d_{k,r}`)에 대한 값이다. FedAvg 의 1/K 는 cos 에 영향 없다.
