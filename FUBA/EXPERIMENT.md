# 실험 코드: 연합 언러닝 활성화 백도어의 탐지와 삭제 권리를 보존하는 정화

FUBA 공개 코드로 공격 궤적을 실제로 만들고, 서버가 저장한 업데이트만으로 탐지와 정화를 수행한 뒤 통계를 낸다. 수치는 소규모 예비 실험 결과이다.

## 한 번에 실행

```bash
cd FUBA
bash run_experiment.sh det1 det2 det3
```

저장된 궤적이 이미 있으면 공격 단계를 건너뛴다.

```bash
SKIP_ATTACK=1 bash run_experiment.sh det1 det2
```

## 실험 설정

- 공격: FUBA, MNIST, IBA 트리거, 클라이언트 8명(공격자 0~3, 요청자 4, 정상 5~7), 타깃 클래스 8, 8라운드(웜업 3), 전원 참여.
- 실행 환경: Windows, RTX 4060 8GB. MPI 런타임은 `pip install impi-rt`, 그 밖에 `psycopg2-binary`. `dataset.py`의 DALI import 가드와 DataLoader `num_workers=0`만 바꾸었고 공격 로직은 그대로이다.
- 메모리가 부족하면 `run_real_fuba.sh`의 BLAS 스레드를 1로 둔 설정을 유지한다.

## 방법 요약

**탐지.** 각 쌍 (u,k), 클래스 c의 분류 헤드 행 업데이트에 대해
`O_uk(c) = max(0, -cos(ΔW_u[c], ΔW_k[c])) · min(||ΔW_u[c]||, ||ΔW_k[c]||)`.
합이 가장 큰 클래스를 타깃으로 두고, 그 행에서 서로 정렬된(cos > 0.5) 가장 큰 집단을 공격자 군집, 군집과 반대이면서 가장 크게 움직인 클라이언트를 요청자로 둔다.

**정화.** `θ_pur = θ_T − U_req − Σ_{k≠req} P_V U_k`. 요청자 기여는 전부 지우고(삭제 권리), 나머지는 백도어 방향 V 성분만 지운다. V는 탐지된 공격자들의 라운드별 헤드 업데이트 주성분 상위 k개(기본 8).

## 결과 (2회, det1·det2)

탐지: 타깃 2/2, 공격자 정밀도·재현율 1.00, 요청자 2/2.

| 방법 | ACC | ASR |
|---|---|---|
| A 잠복 상태 | 95.95±0.20 | 5.69±0.64 |
| B 요청자만 제거 (공격이 노리는 결과) | 84.42±0.41 | 39.06±4.58 |
| C 요청자+공격자 통째 제거 | 67.67±0.74 | 0.01±0.01 |
| D 제안 (전원의 V 성분 제거) | 88.09±2.01 | 21.79±9.56 |
| E 임의 방향 제거 (대조군) | 84.44±0.46 | 39.05±4.61 |

정상 클라이언트 기여 손실 약 8%. 원 수치는 `logs/pipeline_det1.json`, `logs/pipeline_det2.json`, `logs/pipeline_aggregate.json`.

## 한계

- 정화 후 ASR이 잠복 상태보다 높으므로 억제이지 제거가 아니다. 재활성화 시험, 백도어 뉴런 존재 지표, 이후 라운드 학습 뒤 재발 여부는 측정하지 않았다.
- 실행 간 편차가 크다(det1 ASR 34.5→12.2, det2 43.6→31.4). 반복 횟수를 늘려야 한다.
- 모델은 기여의 단순 합으로 근사했다. 처음부터 재학습한 기준 모델과의 비교는 하지 않았다.
- 적응형 공격자, BadFU 궤적에 대한 동일 절차 적용, 기존 방어(FUBA 저자의 Top-k·Enforce, 요청 심사, 강건 집계)와의 직접 비교는 아직 하지 않았다.
